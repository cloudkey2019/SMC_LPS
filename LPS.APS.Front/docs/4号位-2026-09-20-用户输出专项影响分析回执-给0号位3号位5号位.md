## 一、3 处口径冲突（C1/C2/C3）——均为 5 号位 整改下游，前端附 file:line 证据

### C1：订单摘要状态 `AT_RISK` / `ESTIMATED_ONLY` 与新 §3.1.2 / §3.3 冲突

| 项 | 内容 |
|---|---|
| 前端现状 | `src/api/aps-v1/types/common.ts:124-140` `ORDER_SUMMARY_STATUSES = ['ON_TIME','DELAYED','AT_RISK','UNSCHEDULED','ESTIMATED_ONLY']`；label `AT_RISK='风险'`、`ESTIMATED_ONLY='仅估算'` |
| 数据来源 | `src/api/aps-v1/order.ts:89-94` 把后端 `GET /api/order-query/summary` 的 5 字段映射回，其中 **`{status:'AT_RISK', count: dto.riskCount}`（L92）** 直接吃后端 `riskCount` |
| 新文档要求 | §3.1.2 交付状态收敛为 `ON_TIME / DELAYED / UNSCHEDULED / UNFULFILLED`；§3.3 **风险与交付分离**（RiskLevel 不再作为正式风险口径，风险归「执行偏差风险」）；§1.2-C 明示 **Order.DelayStatus 不得作为 APS 延期真值**（应以 FinalTask max PlannedEndTime vs CustomerDueDate 判延期） |
| 冲突点 | 前端 `AT_RISK` / `ESTIMATED_ONLY` 两态、以及「延期取自 DelayStatus」的口径，均与新文档相左 |
| **下游依赖** | **P0-OUT-02 / P0-OUT-03**（5 号位 修 `GetSummaryAsync`：去 riskCount、补 UNFULFILLED、延期真值改 FinalTask 口径）。**前端 `order.ts:92` 的 riskCount 映射、`common.ts` 两枚举，须待 5 号位 DTO 改后才能跟改——否则前端单方面删态会与后端实际返回字段脱节** |
| 前端动作 | **暂不改**。待 5 号位 出修订版 Summary DTO 契约 → 前端同步收敛枚举 + 改映射 + 改 label |

### C2：资源「瓶颈」展示与新「负荷率」口径冲突

| 项 | 内容 |
|---|---|
