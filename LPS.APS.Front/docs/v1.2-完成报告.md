## 四、v1.0 教训为什么不复存在

**v1.0 教训**（[[feedback_rbac_aps_routes]]）：mock/role/index.mock.ts 把 admin 角色注册到老版本路由树，老权限码与新路由对不上 → 老权限码失效 + 新路由被错杀。

**v1.2 不再怕的 3 个理由**：

| 项 | v1.0 | v1.2 |
|---|---|---|
| 路由来源 | mock/role/index.mock.ts 动态注册（含老路由）| `apsV1Routes` 静态挂载（合并进 constantRouterMap/asyncRouterMap），**不走** mock 角色路由树 |
| 角色数据 | 与 mock 路由树**耦合** | `MOCK_ROLE_PRESETS` 在 store 独立维护，**解耦** |
| 权限码定义 | 字符串（拼写错误不报错）| TS 联合类型 `aps.*`，**编译期检查** |

所以 v1.2 路由级 RBAC 是**安全的**，可在任意时刻挂 meta，并由 `pnpm verify:rbac` 一键验证。
