## 二、13 端点字段级契约（前缀 `/api/governance`）

**通用约定**：
- 线格式 JSON **camelCase**（ASP.NET Core 默认序列化，与已落地 14 个 DTO 一致）；C# 实体侧 PascalCase
- 响应外层为既有 `ApiResponse` 壳（`apsHttp` 自动剥壳，端点返回即下表「响应」列类型）
- 权限码：`aps.setup.view`（读）/ `aps.setup.edit`（写）/ `aps.setup.publish`（发布），缺码 → **403**
- 错误码契约（4 号位 前端现为原文透传 ElMessage.error，请 3 号位 按此落地）：
  - **400** = 状态红线（目标 RuleSetVersion 非 DRAFT 却写/发；changeReason 空）
  - **422** = 数据红线（唯一性重复 / From==To / SetupMinutes≤0 / DEFAULT 带产品 / EXACT 缺产品），**业务消息需可读原文**
  - **404** = id/runId 不存在
- 枚举字面量（与 DDL CK 严格一致）：RuleType = `EXACT | DEFAULT`；Status = `DRAFT | ACTIVE | DEPRECATED`

## 三、DTO 字段表（线格式 camelCase）

### SetupRuleDto（#1/#5 响应元素；#2/#3/#6/#7 响应同构）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 主键 |
| ruleSetVersionId | int | 归属版本 |
| ruleType | `EXACT \| DEFAULT` | CK 字面量 |
| departmentCode / stageCode / operationCode / resourceCode | string | 4 基础维度（operationCode 为唯一工序维度，**不得有 From/ToOperationCode**） |
| fromMaterialCode / toMaterialCode | string? | EXACT 必填非空 / DEFAULT 必为 null；**不得相等** |
| setupMinutes | number | **> 0** |
| status | `DRAFT \| ACTIVE \| DEPRECATED` | 规则状态 |
| remark | string? | 可选备注 |
| createdAt / createdBy / updatedAt / updatedBy | IsoDateTime / string? | 后端权威字段，前端只读 |

**唯一性（§8.3）**：EXACT = (Version, Dept, Stage, Op, Resource, From, To) 7 元组；DEFAULT = (Version, Dept, Stage, Op, Resource) 5 元组；**EXACT+DEFAULT 跨类型同 5 元组也判重**（DEFAULT 是该产品对的兜底，二者互斥）。

### SetupRuleExactInput（#2/#3 body）
`ruleSetVersionId, departmentCode, stageCode, operationCode, resourceCode, fromMaterialCode, toMaterialCode, setupMinutes, remark?` —— 同上前 9 字段（无 id/status/审计字段）。

### SetupRuleDefaultInput（#6/#7 body）
`ruleSetVersionId, departmentCode, stageCode, operationCode, resourceCode, setupMinutes, remark?` —— **无产品字段**；若请求体携带非空 from/toMaterialCode → 422。

### SetupUncoveredStatDto（#10 响应元素）
`departmentCode, stageCode, operationCode, resourceCode, fromMaterialCode, toMaterialCode, count: int, lastOccurrence?: IsoDateTime`
（聚合在**后端**做，前端不做 0 分钟兜底计算——§7.3 硬约束）

### OperationResourceEligibilityDto（#9 响应）
`operationCode: string, resourceCodes: string[], resources?: [{ resourceCode, resourceName?, departmentCode?, stageCode? }]`
算法（§3.3/§7.2）：当前 Operation 合法资源 ∩ 同部门同 Stage 任一 Operation 合法资源（前后产品都合法的设备交集）。

### SetupDiffDto（#12 响应）
`ruleSetVersionId, otherVersionId, addedCount, modifiedCount, removedCount, publishStatus, comparedAt?`
+ **`setupRuleChanges: { added: SetupRuleChangeDto[], modified: SetupRuleChangeDto[], removed: SetupRuleChangeDto[] }`**（确认函 Q7，3 号位 需补此维度）

SetupRuleChangeDto：`ruleType, operationCode, departmentCode?, stageCode?, resourceCode?, fromMaterialCode?, toMaterialCode?, setupMinutes?`；modified 行另含 `id, before: Partial<SetupRuleDto>, after: Partial<SetupRuleDto>`。

### SetupRuleSetVersionDto（#11 响应元素）
`id, ruleSetId, versionCode, status, effectiveFrom?, effectiveTo?, publishedAt?, publishedBy?, createdAt`
