## 二、Reschedule 字段对齐告知（**新**）

**3号位 回执 §四**：POST `/api/governance/run/candidate` 入参为 `CreateCandidateRunRequest`，与前端 `TriggerRescheduleInput` 字段不对齐：

| 前端字段（旧） | 后端字段（新） | 4号位 处理 |
|---|---|---|
| `objectRefType` | 无此字段 | 删除（前端不再传）|
| `objectRefId` | 无此字段 | 删除 |
| `objectRefIds` | 无此字段 | 删除 |
| `reason` | `Remark` | reason → Remark |
| `actor` | 无此字段（后端从 JWT 取）| 保留用于审计 fallback |
| `domainKey` | `DomainKey` | ✓ |
| `runType` | `RunType` | ✓ |
| 无 | `Purpose` | 新增（与 RunType 配对）|
| 无 | `BasePlanVersionId?` | 新增（可选）|
| 无 | `DataCutoffTime?` | 新增（可选，缺省 now）|

**RunType×Purpose 冻结合法组合**（@see RunLifecycleService.cs:65-71）：

| RunType | 合法的 Purpose |
|---|---|
| `MANUAL_RESCHEDULE` | `MANUAL_ADJUSTMENT` |
| `LOCAL_RESCHEDULE` | `INSERT_RESCHEDULE` / `MANUAL_ADJUSTMENT` |
| `INSERT_ORDER_WHATIF` | `CTP` / `INSERT_IMPACT_ANALYSIS`（永不可激活）|

**4号位 已落地**：
- `types/run.ts` L169-184 重构 `TriggerRescheduleInput`（删除 objectRef*、新增 purpose/basePlanVersionId/dataCutoffTime）
- `run.ts` L223-260 triggerReschedule 改为 camelCase payload `{ runType, purpose, domainKey, basePlanVersionId?, dataCutoffTime?, remark }`
- `Gantt.vue` 三处调用点全部更新：

  - L1313 单 Task 重排 → LOCAL_RESCHEDULE × INSERT_RESCHEDULE
  - L1423 资源不可用 → LOCAL_RESCHEDULE × INSERT_RESCHEDULE
