## 二、为什么必须等真实 JSON（不可用 DTO 反推兜底）

### 2.1 DTO 反推样本的边界

4 号位 已按 `OrderListItemDto.cs` + `Program.cs:90-93` `JsonNamingPolicy = CamelCase` 反推一条 JSON 样本（含 OrderCanonicalId=552898），**可在 dev 联调前启动 frontend 静态部分**，但有 3 项字段名**不敢 100% 对齐**：

| 字段 | PascalCase（DTO）| camelCase（推测）| 风险 |
|---|---|---|---|
| `uom` | `UOM` | `uom` | ⚠️ 全大写缩写 — `JsonNamingPolicy.CamelCase` 默认处理可能产出 `uom` 或 `UOM` |
| `mtsInstructionNo` | `MTS_InstructionNo` | `mtsInstructionNo` | ⚠️ 下划线 + 缩写 — `CamelCase` 不处理下划线，可能产出 `mTS_InstructionNo` |
| `bomno` | `BOMNO` | `bomno` | ⚠️ 全大写缩写连写 — 可能产出 `bomno` / `bomNO` / `BOMNO` |

→ **dev 真实响应可能在以上 3 字段产生与反推样本不一致的命名**，导致前端 TS 接口字段拼写错位、verify [M] 段 M02 接受类断言失败。
