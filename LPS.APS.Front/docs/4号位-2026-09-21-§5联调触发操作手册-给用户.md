## 一、用户操作（Step A-D，浏览器）

### Step A — 切真实模式

1. 打开终端：`cd frontNew`
2. 确认 `.env.dev` 或 `.env.pro` 已配：
   ```
   VITE_USE_MOCK=false
   VITE_APS_API_BASE_URL=https://localhost:7044  # 或部署的 pro URL
   ```
3. 跑：`pnpm dev`
4. 浏览器开 `http://localhost:5173`（或 vite 提示的端口）→ 登录 admin

### Step B — 进规则与参数维护 → 选已有 DRAFT

1. 左侧菜单 → APS → 规则与参数维护
2. 左侧列表选一条 `status === 'DRAFT'` 的 RuleSet（如 `RS-DEFAULT`）
3. 右侧详情应自动加载 parameters / segments / strategy / diff / history 五个 Tab

### Step C — F12 抓真实 JSON（关键）

1. F12 → Network 面板 → 清空 → 勾选 "Preserve log"
2. 触发"重新加载详情"（如切换 RuleSet 或刷新页面）
3. 在 Network 找两次响应：
   - **`GET /api/governance/rule-set/version/{versionId}`**（或 `/published-version`）→ 右键 **Copy response**
   - **`GET /api/governance/parameter-set/version/{versionId}`** → 右键 **Copy response**
4. 把两份 JSON 分别存为：
   ```
   frontNew/docs/real-rule-set-version.sample.json
   frontNew/docs/real-parameter-set-version.sample.json
   ```
5. （可选）再触发 [+ 新建草稿] → fork 一份 DRAFT → 重复抓这两份 DRAFT 响应 → `real-rule-set-version.draft.sample.json` / `real-parameter-set-version.draft.sample.json`

### Step D — 把 5 主题 JSON 的 keys 抄到 bindings.json

1. 打开 `real-parameter-set-version.sample.json` → 找 5 JSON 字段：
   - `lockJson` / `supplyJson` / `procurementJson` / `solverStrategyJson` / `candidateGuardrailJson`
2. 复制每份 JSON 字符串 → 在编辑器格式化（VS Code: Alt+Shift+F）→ 列出所有 key 路径
3. 打开 `src/api/aps-v1/parameter-set.bindings.json`（**新建**，模板见 §二），按下列填：

```json
{
  "parameterSet": {
    "procurement": [
      { "keyPath": "planningYield", "parameterName": "计划良率", "type": "PERCENT", "editable": true, "sensitive": false, "description": "排产时考虑的良率补偿" },
      { "keyPath": "demandProtectionThreshold", "parameterName": "需求保护阈值", "type": "PERCENT", "editable": true, "sensitive": false },
      { "keyPath": "defaultPurchaseLT", "parameterName": "默认采购前置期", "type": "DURATION", "editable": false, "sensitive": false },
      { "keyPath": "crossDomainBlockBuffer", "parameterName": "跨域共享设备缓冲", "type": "DURATION", "editable": true, "sensitive": true },
      { "keyPath": "planningPurchasePlaceholderEnabled", "parameterName": "启用采购占位", "type": "BOOLEAN", "editable": true, "sensitive": false }
    ]
  },
  "ruleSet": { "...": "（同 shape，按 RS sample 填）" }

```

4. 在 `src/api/aps-v1/index.ts` 注册：
   ```ts

   import { registerParameterSetBindings } from './parameterSetBindings'
   registerParameterSetBindings(parameterSetBindings)
   ```

## 二、bindings.json 模板

`src/api/aps-v1/parameter-set.bindings.json`：
```json
{
  "_comment": "B 设计稿 §5 Step D — 真实后端 key 绑定表（覆盖 draftBuffer.ts heuristic）。联调抓 JSON 后填。",
  "parameterSet": {
    "lock": [],
    "supply": [],
    "procurement": [],
    "solverStrategy": [],
    "candidateGuardrail": []
  },
  "ruleSet": {
    "lock": [],
    "supply": [],
    "procurement": [],
    "solverStrategy": [],
    "candidateGuardrail": []
  }
}
```

`ParameterBinding` 字段含义：
- `keyPath`（必填）：点分路径，如 `planningYield` 或 `policies.priority.segments`
- `parameterName`（可选）：UI 展示别名，缺则用 keyPath
- `sensitive`（可选，默认 false）：是否敏感字段
- `editable`（可选，默认 true）：是否可编辑
- `type`（可选）：显式类型；缺则 fallback 到 heuristic
- `description`（可选）：参数说明（前端未来可加 detail 列）

## 三、注意事项

1. **双轨 fork 后**两份 DRAFT 都是 5 JSON 全空（前端 populateBufferFromDetail mock 派生），**真实模式 loadDualTrackBuffers 应从 GET response 反序列化**。Step C 后 4号位 会联调确认；如后端直接返 `lockJson` 等字符串字段，**前端已写好 parseParameterSetBlocks**。
2. **Dirty 拦截**（Issue 14）：已加 `onBeforeRouteLeave` + `beforeunload`。用户复测时如有 UX 问题（如弹窗太烦），可调 ElMessageBox 文案或加白名单（如"刷新页面"不算离开）。
3. **OCC 409**（Issue 11）：store 已 catch 409 → 友好提示。后端真实施 OCC 后行为可见，Step E 实测。
4. **publishDualTrack 串行**：先 RS 后 PS，任一失败即停。RS 已发 PS 失败时，**前端不自动回滚 RS**（业务上不可回滚已发布），仅提示用户"请刷新页面后单独处理 PS"。
