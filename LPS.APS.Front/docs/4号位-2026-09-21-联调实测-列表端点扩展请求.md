# 4号位 → 3号位：联调实测发现 /api/governance/rule-sets 列表端点需扩展字段

> **触发**：B 设计稿 Step 3.1（store loadList 接续真实后端）→ 浏览器实测 → 页面全空，定位为列表 DTO 缺关键字段。
> **优先级**：P1（不阻塞 4号位 本周验证，前端已落 mapping + 详情回填兜底；扩展后前端可去掉兜底）
> **期望回复时间**：本周末前（B 设计稿 Step E 联调验证在即，4号位 需确认契约稳定）
> **依据**：[frontNew/docs/real-rule-set-list.sample.json](real-rule-set-list.sample.json)（已抓包落档，484 条均同一形状）

## 一、问题描述（实测）

`GET /api/governance/rule-sets`（[GovernanceController.cs:675-686](../../lps/LPS.APS.Web/Controllers/GovernanceController.cs#L675-L686)）当前返回精简主表：

```json
{
  "id": 1287,
  "ruleSetCode": "TEST-RS-...",
  "ruleSetName": "集成测试规则集",
  "description": "Integration Test",
  "isActive": true,
  "createdAt": "2026-09-21T11:48:05.2433333",
  "createdBy": "IntegrationTest"
}
```

4号位 `RuleSetSummaryDto`（[types/rule.ts:19-37](../src/api/aps-v1/types/rule.ts#L19-L37)）需要 13 字段，列表端点缺 5 个关键：

| 字段 | 影响 |
|---|---|
| `domainKey` | 卡片 Domain tag 显示空；数据权限（`assertScope({domainKey})`）无法判断 |
| `currentVersion` / `draftVersion` | 卡片版本号 `v{{undefined}}` 显示成 `v`；发布按钮 disabled 判断拿不到 |
| `status` | 状态标签显示空白（默认 primary 蓝块）；KPI 6 态统计全 0；fork 守门矩阵判断不到 |
| `lastChangeReason` | 卡片变更原因不显示（次要，但 B 设计稿 §3.4 fork 守门校验源） |
| `publishedAt` / `retiredAt` | 发布/退役时间不显示 |

→ 列表页全空，点不进去（点击需要 `ruleSetId`，主表叫 `id`），4号位 无法端到端验收 U21/U22。

---

## 二、临时方案（4号位 已落地）

在 [ruleApi.listRuleSets](../src/api/aps-v1/rule.ts#L301-L347)（真实模式分支）加了 mapping：

- 主表直连字段：`ruleSetId←id, ruleSetCode, ruleSetName, createdAt`
- 占位字段：`domainKey='ALL', currentVersion=0, status=isActive?'PUBLISHED':'DISABLED', validationStatus='PENDING'`
- store [loadDetail](../src/store/modules/aps/rules.ts#L265-L297) 加载完后**回填列表行**（用详情真实值校正占位字段），实现"先骨架后详情"的两段渲染。

→ **页面可用了**（点卡片即可加载详情 + 回填列表行），但**首屏所有卡片都显示"Domain / v— / 待回填"**，状态分布 KPI 不准（首屏 status 全是 PUBLISHED 兜底）。

## 三、建议扩展契约（请 3号位 评估）

**选项 A — 后端 JOIN 一次性扩展**（推荐，与现有 list endpoint 兼容）

`GET /api/governance/rule-sets` 返回 DTO 新增以下 5 字段：

```json
{
  "id": 1287,
  "ruleSetCode": "TEST-RS-...",
  "ruleSetName": "集成测试规则集",
  "description": "Integration Test",
  "isActive": true,
  "domainKey": "FAMILY_INJECTION",       // ← 新增（来自 RuleSet.DemandDomainKey 或 Domain 关联表）
  "currentVersion": 3,                    // ← 新增（Latest PUBLISHED Version 编号；无发布版则为 0）
  "draftVersion": 4,                      // ← 新增（Latest DRAFT Version 编号；无则为 null）
  "status": "PUBLISHED",                  // ← 新增（Latest PUBLISHED/DRAFT/PUBLISHED/DISABLED；与最新 Version 同步）
  "lastChangeReason": "调整 Demand Protection 阈值", // ← 新增（Latest Version.ChangeReason）
  "lastChangeAt": "2026-09-21T...",       // ← 新增（Latest Version.UpdatedAt 或 PublishedAt）
  "createdAt": "...",
  "createdBy": "..."
}
```

**实现路径建议**（[GovernanceController.cs:675](../lps/LPS.APS.Web/Controllers/GovernanceController.cs#L675) → `_ruleSetRepo.GetListAsync`）：
- 仓储层 SQL：左 JOIN `RuleSetVersion` 取每个 RuleSet 的 `MAX(Version) WHERE Status='PUBLISHED'` + `MAX(Version) WHERE Status='DRAFT'`
- 或：Dapper 多次查询 + 应用层 GroupBy（避免破坏仓储抽象）
- 权限：保持 `aps.rule.view`（与现状一致）
- 缓存：可加 60s 内存缓存（列表场景对实时性不敏感，1 分钟滞后可接受）

**选项 B — 新增独立端点（次推荐，4号位 改动最小）**

`GET /api/governance/rule-set-list-with-status` 返回完整 DTO（与 RuleSetSummaryDto 1:1 对齐）

**选项 C — 4号位 兜底继续**

前端保持现有 mapping + 详情回填，**接受首屏 5 字段占位 + 卡片点击后回填**。优点：3号位 零改动；缺点：UX 差（首屏看不到状态）、KPI 不准、fork 守门矩阵首屏会误判（虽然 store loadDetail 后会校正）。

| 选项 | 4号位 工作量 | 验收体验 |

## 五、附加请求（与本次扩展同源）

1. **同步扩展 `/api/governance/parameter-sets`**（同 controller L691）→ ParameterSet 列表页同样缺字段，未来 4号位 ParameterSet 维护页也会遇到同样问题。请同步扩展（若实现 A，仓储层 `_parameterSetRepo.GetListAsync` 同样 JOIN）。
2. **Web DTO 命名约定**：返回字段建议用 camelCase（已对齐 MVC 默认）；不要 PascalCase。
3. **空值约定**：
   - `domainKey` 无值 → `'ALL'`（前端 fallback 已有）
   - `currentVersion` 无发布版 → `0`（前端 placeholder 已识别）
   - `draftVersion` 无草稿 → `null`（前端 `r.draftVersion` optional 字段）
   - `status` 永远不为空（即使是 'DISABLED' 也得返）
