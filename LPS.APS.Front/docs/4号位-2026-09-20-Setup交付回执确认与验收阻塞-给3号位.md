## 二、lps 代码同步核实：**Id-口径终定（v1.1）适配报告**（回执偏差清单未覆盖的契约事实）

4 号位 按源码逐端点核实，发现三项契约事实**在 SetupRuleDtos.cs 头注/实现中已终定、但回执偏差清单（#1-#7）未列出**。前端已全部适配，此处通报备案（**不请求变更，均已按后端现状对齐**）：

### 2.1 写输入全面 Id-口径（超出偏差 #5 的 eligibility 范围）

SetupRuleDtos.cs 头注权威口径：**部门/设备/物料一律传内部主键 Id，大工艺/工序传 Code**——

| 输入 | Id 字段 | Code 字段 |
|---|---|---|
| `SetupRuleExactInput` | `productionDepartmentId` / `resourceId` / `fromMaterialId` / `toMaterialId` | `stageCode` / `operationCode` |
| `SetupRuleDefaultInput` | `productionDepartmentId` / `resourceId` | `stageCode` / `operationCode` |

传 Code 字段名会被模型绑定静默丢弃 → Id=0 → 422 数据红线。**前端适配架构**：UI 层保持 Code-口径（展示/红线/预填不变），提交时 Code→Id 解析——编辑态优先取 SetupRuleDto 双返回的权威 Id，新建态查下拉选项映射；解析失败**硬阻断提交**（不发 Code 伪载荷），错误文案明示主数据缺口。

### 2.2 双返回机制核实 ✅（原 §二.1 问题已由代码自答，无需回复）

- `SetupRuleDto` 同时回带 Id + Code（`departmentCode/resourceCode/fromMaterialCode/toMaterialCode` 可空，经 MasterDataCodeCache 反查）；
- **Id 字段名核实**：`FromMaterialId` / `ToMaterialId`（camelCase `fromMaterialId/toMaterialId`）与前端 v1.0 函 §二.1 的猜测**完全一致** ✅，该问题闭环；
- `status` 派生三态映射核实（DeriveStatus）：DRAFT/SUBMITTED/APPROVED → `DRAFT`；PUBLISHED → `ACTIVE`；DISABLED/ARCHIVED → `DEPRECATED`——与前端 SETUP_RULE_STATUS_META 三态零冲突。

### 2.3 版本列表治理六态（#11/#12）区别于规则派生三态

`SetupRuleSetVersionDto.Status` 与 `SetupDiffDto.PublishStatus` 回**治理六态原文**（DRAFT/SUBMITTED/APPROVED/PUBLISHED/DISABLED/ARCHIVED）。前端已补 `SETUP_VERSION_STATUSES` + 六态中文标签映射；版本选择器展示六态、`canEdit` 判 `status === 'DRAFT'` 与后端 GetVersionForWriteAsync（非 DRAFT → 400）语义一致。

### 2.4 DEFAULT `[JsonExtensionData]` material 键拦截

SetupRuleDefaultInput 带 ExtensionData 拦截：请求体出现含 "material" 的键（大小写不敏感）→ 422。前端 `SetupRuleDefaultInput` 类型为封闭 6 字段接口，**结构上不可能发出 material 键**，合规零改动。

### 2.5 ⚠️ P0 升级：主数据缺口覆盖**部门/设备/物料三类**（原 §二.2 仅问物料）

原函只问了物料 Code→Id 端点；代码同步后全量 grep 核实：**后端无任何主数据读端点（部门/设备/物料均无）**，且 #9 eligibility 响应仅回 `resourceCodes`（无 resourceId）。影响链：

- **编辑流程可用**（双返回 Id 权威回填）✅；
- **真实模式 create 流程 Id 无来源** ❌：新建 EXACT/DEFAULT 时部门/设备/物料下拉只能靠前端 mock 映射（DEPT_A=1 / MC001=1 / MAT_A=1 …），dev 库真实主键与 mock 不一致则写入错 Id（DDL 无 FK 约束，**后端不拦**，错 Id 静默入库且 Code 反查为 null）。

**请 3 号位 二选一给书面结论（09-25 前）**：

- **方案 a（推荐，改动最小）**：#9 eligibility 响应 `resources[]` 明细补 `resourceId`；另补 3 个轻量主数据 GET 端点（departments / resources / materials，回 `{id, code, name}`），前端下拉即切真实源；
