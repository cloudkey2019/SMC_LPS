## 二、P0 必答疑问（2 项，09-26 前）

### P0-1【P0】Candidate 页是否需「EXPEDITE 影响范围」展示位

**文档依据**：§四 + §七
- §四：「影响范围包括：EXPEDITE 需求订单；当前计划中允许调整的其他需求订单。保护订单仍参与计算，但 EXPEDITE 不能突破保护边界」
- §七：「V1 不自动计算牺牲成本，仅输出影响范围供业务确认」

**4 号位 疑问**：
- 文档明文「输出影响范围供业务确认」——前端 **Candidate.vue 对比激活前**是否需要新增「将受影响的其他订单」列表？
- 还是仅在 ACTIVE 激活前由**业务人员手动**比对？（无 UI 模块，仅流程规范）

**影响**：
- 如需新增 UI 模块：1~2 人天（前端 + 后端影响范围端点）
- 如无需：仅在文档 / 流程层约束，4 号位 不动

**请 3 号位 拍板**：
- (a) **新增 UI 模块** → 后端新增 `GET /api/candidate/{id}/expedite-impact` 端点 + 前端 Candidate.vue 加「影响范围」卡片
- (b) **维持现状**（无 UI 模块）→ 仅文档 / 流程约束，4 号位 不改

**4 号位 倾向 (a)**：业务方反馈"插单后不知道哪些订单会被推迟"是常见痛点，UI 透明化能减少 ACTIVE 激活后才发现"挤占他人"的纠纷。

### P0-2【P0】§10A.1 EXISTING_ORDER_ADVANCE 是 EXPEDITE 的唯一入口吗

**文档依据**：§二 + §三
- §二：「EXPEDITE 作用对象为需求订单（Demand），不是 Task」
- §三：「EXPEDITE：用户指定某需求订单需要优先满足」

**4 号位 疑问**：EXPEDITE 作用于需求订单，但 v1.4 §10A 五入口中**只有 10A.1 EXISTING_ORDER_ADVANCE 允许 EXPEDITE**。**是否还有 CTP / 销售订单 / 紧急插单 / 插单分析 等入口需新增**？

**请 3 号位 拍板**：
- (a) **§10A.1 是唯一入口** → 4 号位 不新增 UI（维持现状）
- (b) **需新增其他入口** → 4 号位 待 3 号位 明确新入口后评估 UI 范围

**4 号位 倾向 (a)**：v1.4 §10A 五入口已涵盖「白天 Candidate 重排」全部场景；CTP 属于销售报价环节（不在 V1 范围，见 P1-1）；插单分析如需可走 10A.1 EXISTING_ORDER_ADVANCE。
