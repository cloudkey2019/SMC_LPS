# APS V1 Resource Calendar资源日历能力补充冻结方案 v1.3

## （人工能力槽模型与职责边界修订版）

------------------------------------------------------------------------

# 一、本轮修订说明

本文用于补充APS V1有限产能排程中的Resource
Calendar（资源日历）能力模型。

本轮修订重点调整：

1.  明确Resource Calendar业务维护Owner与数据建模Owner的区别；
2.  明确5号位负责资源能力业务维护，2号位负责数据库建模和运行数据承载；
3.  保留人工能力槽不污染正式Resource主数据的原则；
4.  保持设备资源与人工能力槽统一消费、分别建模；
5.  不扩展Candidate触发规则，避免与运行治理裁决混淆。

本方案不改变：

-   有限产能Solver职责；
-   OperationPlanningMode；
-   Setup换型模型；
-   Pegging模型；
-   PI Position模型；
-   Domain模型。

核心原则：

> 排程消费模型统一，但资源事实模型不强制统一。

> 正式同步资源主数据与APS内部能力抽象不得混合。

------------------------------------------------------------------------

# 二、资源能力总体模型

APS V1中：

-   设备资源；
-   人工能力槽；

均参与有限产能排程。

统一：

-   Solver消费逻辑；
-   Task资源占用逻辑；
-   可用时间判断逻辑。

不统一：

-   数据来源；
-   维护方式；
-   生命周期。

------------------------------------------------------------------------

# 三、设备Resource模型

设备继续采用正式Resource主数据。

来源：

-   MES；
-   EAM；
-   其他制造资源同步接口。

Resource代表：

> 制造现场正式认可的设备资源。

模型：

Resource

↓

ResourceCalendarSlot

ResourceCalendarSlot表示：

> 某设备在什么时间可以被APS排程占用。

规则：

-   有有效日历：允许进入排程；
-   无有效日历：不可用。

禁止：

> 无日历自动解释为7×24小时可用。

------------------------------------------------------------------------

# 四、人工有限能力模型

APS V1不维护真实人员信息。

人工采用：

> 生产部门 + 小工序 + 人工能力槽

模型。

人工能力槽不是员工。

不建设：

-   人员档案；
-   HR接口；
-   技能矩阵；
-   人员排班体系。

人工能力槽是：

> APS有限产能计算中的抽象能力单元。

例如：

  生产部门   小工序   人工能力槽
  ---------- -------- ------------
  A部门      精修     精修01
  A部门      精修     精修02

人工槽必须包含：

-   生产部门；
-   小工序；
-   能力槽编码。

不同生产部门、不同小工序的能力不可直接混用。

------------------------------------------------------------------------

# 五、人工能力槽建议模型

经过讨论，建议新增人工能力槽模型。

该模型作为当前V1推荐实现方案，用于避免人工能力污染正式Resource主数据。

## ManualCapacitySlot（人工能力槽）

建议字段：

-   ManualSlotId
-   ProductionDepartmentId
-   OperationCode
-   OperationName
-   SlotCode
-   IsActive

说明：

ManualCapacitySlot不是员工，而是某生产部门某小工序下可用于APS有限产能计算的能力位置。

## ManualCapacitySlotCalendar（人工能力槽日历）

建议字段：

-   ManualSlotId
-   StartTime
-   EndTime
-   AvailableFlag
-   Remark

表达：

某人工能力槽何时可被APS排程占用。

------------------------------------------------------------------------

# 六、资源日历统一要求

无论设备还是人工能力槽：

资源日历均必须关联生产部门。

## 设备

Routing

↓

Operation

↓

ProductionDepartment

↓

Resource

↓

ResourceCalendarSlot

↓

有限产能排程

## 人工

Routing

↓

Operation

↓

ProductionDepartment + Operation

↓

ManualCapacitySlot

↓

ManualCapacitySlotCalendar

↓

有限产能排程

V1不建设人工技能匹配体系。

人工能力槽按照：

> 生产部门 + 小工序

确定。

不建设：

-   人工技能矩阵；
-   人员资格管理；
-   复杂人工技能排程体系。

------------------------------------------------------------------------

# 七、资源日历与Solver关系

1号位Solver消费：

-   设备Resource可用时间；
-   人工能力槽可用时间。

Solver统一处理资源占用。

但是数据库层：

不要求设备Resource和人工能力槽强制统一。

排程对象：

设备：

具体设备Resource。

人工：

具体人工能力槽。

不是：

"某工序总能力"。

------------------------------------------------------------------------

# 八、职责边界（重点修订）

## 5号位：Resource Calendar业务Owner

负责：

-   Resource Calendar业务维护；
-   人工能力槽业务维护；
-   资源能力事实运营管理；
-   面向4号位提供维护业务接口；
-   支撑车间人员维护资源能力。

5号位负责回答：

> 现场当前有哪些可用于APS排程的资源能力。

5号位不负责：

-   数据库模型设计；
-   Solver；
-   Task资源分配算法；
-   排程优化。

------------------------------------------------------------------------

## 2号位：Resource Calendar数据建模与持久化Owner

负责：

-   Resource Calendar数据库建模；
-   DDL设计；
-   主外键关系；
-   数据持久化；
-   数据加载；
-   向1号位Solver提供运行输入。

2号位负责：

> 如何在APS系统中表达和保存资源能力事实。

2号位不负责：

-   资源能力业务定义；
-   车间资源维护规则制定。

------------------------------------------------------------------------

## 4号位：资源能力维护页面Owner

负责：

-   页面；
-   操作入口；
-   查询与编辑交互。

支持：

1.  设备资源日历维护；
2.  人工能力槽维护；
3.  人工能力槽日历维护。

维护对象：

不是人员，而是APS能力槽。

------------------------------------------------------------------------

## 1号位：资源能力消费Owner

负责：

-   消费资源可用时间；
-   Task分配到具体设备或人工能力槽；
-   有限产能排程。

不负责：

-   Resource Calendar维护；
-   人工能力槽维护；
-   资源能力事实管理。

------------------------------------------------------------------------

## 3号位

不负责：

-   Resource Calendar；
-   人工能力槽维护；
-   资源可用时间维护。

Resource Calendar不是规则引擎内容。

------------------------------------------------------------------------

# 九、资源日历缺省语义

统一：

设备：

无有效日历 = 不可用。

人工能力槽：

无有效日历 = 不可用。

原因：

有限产能排程必须基于真实可用能力。

------------------------------------------------------------------------

# 十、资源日历变化

资源日历属于资源能力事实。

变化包括：

-   设备停机；
-   临时维修；
-   加班增加；
-   人工能力槽调整。

资源日历变化后：

进入APS运行流程，由运行治理决定后续动作。

具体Candidate触发规则属于独立裁决，不在本文展开。

------------------------------------------------------------------------

# 十二、最终冻结结论

APS V1采用：

> 排程消费统一，资源事实分别建模。

设备：

Resource + ResourceCalendarSlot

人工：

ManualCapacitySlot + ManualCapacitySlotCalendar

人工能力槽不是员工，不进入正式Resource主数据。

Resource Calendar属于APS资源能力事实，不属于规则引擎。

职责最终确定：

-   5号位：Resource Calendar业务Owner，负责资源能力业务维护；
-   2号位：Resource Calendar数据建模与持久化Owner，负责系统承载；
-   4号位：维护页面Owner；
-   1号位：Solver消费Owner；
-   3号位：不负责Resource Calendar。

该模型保持有限产能排程精度，同时避免人工能力抽象污染正式Resource主数据。
