# CLAUDE.md — 5号位业务规则规则

## 职责

本目录属于 5号位，负责业务规则、策略、凭证生成。

允许实现：

- Pegging 规则
- 库存扣减策略
- 订单优先级规则
- 拆批规则
- 冻结区规则
- 缺料识别规则
- 原因码判断规则
- 业务凭证生成

## 禁止事项

- 禁止直接写数据库。
- 禁止访问数据库连接。
- 禁止写框架代码。
- 禁止直接修改 ScheduleContext 基础设施。
- 禁止直接创建 Task，除非通过约定凭证交给 2号位执行。
- 禁止修改 1号位排程算法。
- 禁止修改 2号位持久化逻辑。

## 凭证规则

5号位只做决策，输出 Voucher 或规则结果。
2号位负责执行状态变更。

## 原因事实规则

5号位可以辅助判断 ReasonCode。

最终 ExplanationFactDraft 可由 1号位或调度链路生成，但不得由 5号位直接落库。

## Stage / BOM / Routing 规则

涉及 BOM 阶段推导、StageCode、ChildRequiredStageCode、StageDetail 的规则，必须遵守当前字段说明与防腐层文档。

禁止自行发明 StageCode。
禁止把 ProcessType 当 StageCode。
禁止把 OperationName 当 ProcessType。

## 库存与物料规则

- 遵守库存五层架构，禁止跨层取数。
- MaterialCode 不承载仓库、客户、订单、责任部门信息。
- 一物多仓、一物多映射时，禁止 `.First()` 随意取第一条，必须按规则、优先级或上下文判断。
- 业务规则不得直接修改库存事实表，必须输出凭证或规则结果。

## 输出要求

每次修改本目录代码时，必须说明：

1. 修改了哪条业务规则
2. 输入是什么
3. 输出是什么
4. 是否产生 Voucher
5. 是否影响 1号位排程输入
6. 是否影响 2号位落库
