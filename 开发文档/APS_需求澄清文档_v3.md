## 1. 需求摘要

建设有限产能APS系统，支撑日7000订单规模的滚动排程与多视图计划输出（Asprova式：一套计划结果 + 多视图）：
- **近期执行（可下发/冻结窗口=未来3天）**：时分精度，输出机台/产线级作业顺序与派工清单，人工确认后下发MES；冻结窗口内默认不被系统自动打乱。
- **远期协同（计算窗口=未来90天）**：以日/周/月时间桶聚合输出PSI（需求-供给-库存）、资源负荷/瓶颈与交付风险，用于提前识别缺料与产能缺口并驱动协同决策（不直接下发）。

基于256G内存单服务器，借鉴Asprova算法实现15分钟全量排产。系统具备JSON可配置约束规则引擎（产品族×订单类型），BOM按需展开（库存满足剪枝），自制+采购件统一齐套管理。输出**区间型计划**（最早-最晚时间窗），支持甘特图拖拽调整、人工确认后下发MES。

**核心目标**：多目标优化（交期满足率/装配配套率/生产效率）、ATP/CTP可承诺计算、what-if仿真（版本保留1周）、计划vs实际复盘分析。

**关键痛点解决**：
- 无限产能 → 有限产能
- 无滚动排产 → 滚动排程（近期执行3天冻结 + 远期90天协同视图）
- MTS缺主计划 → 同步生产降低在库
- 过度合批 → 多目标权衡最优

## 2. 范围（In/Out）+ 假设 + 约束

### 2.1 In Scope（范围内）

| 模块 | 需求描述 |
|------|----------|
| 有限产能排产引擎 | 7000订单/天处理能力，15分钟内完成全量计算 |
| 计划视图体系（Asprova式） | 近期执行（未来3天时分精度，可下发/冻结）+ 远期协同（未来90天按日/周/月桶聚合） |
| 区间型计划输出 | 最早-最晚时间窗，非唯一确定解 |
| 可配置约束引擎 | JSON格式，按产品族×订单类型矩阵配置 |
| BOM按需展开 | 上层库存满足则剪枝，不展开下层 |
| 采购件管理 | API对接采购系统（小时级），含供应商库存+在途量 |
| ATP/CTP计算 | 可承诺交期/产能计算，插单5分钟评估 |
| what-if仿真 | 版本保留最近1周，指标对比（交付率/配套率/效率） |
| 甘特图交互 | 机台/产线级展示，支持拖拽调整 |
| 复盘分析 | 计划vs实际偏差分析报表 |
| 异常预警 | 界面实时预警 + EAS对接（邮件/短信） |
| N天冻结期 | 已发布计划占用资源保护机制 |

### 2.2 Out of Scope（范围外）

| 项 | 说明 |
|----|------|
| MRP运算 | ERP已生成工单，APS专注排产优化 |
| 移动端应用 | 本期不涉及 |
| WMS对接 | 齐套检查使用ERP库存，WMS由MES对接 |
| 采购件ATP | 无需供应商产能承诺，仅管理库存+在途 |
| 电子签章 | 本期不涉及 |
| 自动化设备控制 | 仅下发计划至MES，不直接控制设备 |

#### 采购承诺能力边界（统一口径）
- 本项目不做“供应商产能承诺级 CTP”（即不计算供应商侧有限产能排程）。
- 但必须支持“采购供给可用时间计算”：
  - 参与因素：现有库存 + 在途预计到货 + 供应商库存（若可获取） + 采购提前期
  - 输出能力：缺料预警、可用时间推算、采购建议（加急/分批/替代料/调整到货期的提示）
- 该能力用于齐套判断与排产可行性评估，不替代采购系统的下单与供应商协同流程。

### 2.3 关键假设

| 假设项 | 假设内容 |
|--------|----------|
| 硬件性能 | 单服务器256G内存，通过算法优化满足15分钟性能要求 |
| 日计划量级 | 当日需起工订单约400-500单（MTS当日起工 + MTO应起工） |
| 约束冲突处理 | 产能不足可通过加班解决，无明确硬约束优先级 |
| 计划下发 | 排产结果需人工确认后方可下发MES |
| 算法借鉴 | 参考Asprova算法思路，输出区间型计划 |
| 采购同步 | API小时级同步供应商库存与在途量 |

### 2.4 约束条件

| 约束项 | 约束值 |
|--------|--------|
| 排产计算时限 | ≤15分钟（7000订单全量） |
| 硬件配置 | 256G内存单服务器 |
| 并发用户 | ≤100人 |
| 宕机容忍 | 4小时，冷备恢复 |
| 计划数据保留 | 1年 |
| 变更日志保留 | 1个月 |
| 仿真版本保留 | 最近1周，自动清理 |
| 插单评估时限 | ≤5分钟 |
| 采购数据同步 | API，小时级 |

## 3. 系统边界与职责划分

### 3.1 系统集成边界表

| 系统 | 职责定位 | 向APS输入 | APS向该系统输出 | 交互频率 |
|------|----------|-----------|-----------------|----------|
| **ERP** | 主数据与订单源头 | 销售订单(SO)、预测单(SS)、补库订单(SS-U)、库存数据、工单、BOM、物料主数据 | 计划确认状态、回写计划时间、需求预测反馈 | 实时API + 定时批量 |
| **MES** | 工艺与执行反馈 | 多版本工艺路线、设备产能参数、模具状态、执行实绩（开工/完工/报工） | 机台级排产计划、工序开始/完成时间区间 | 计划下发：每日/滚动更新；实绩：实时 |
| **采购系统** | 采购件供给管理 | 供应商库存、在途采购订单、采购提前期、MOQ | 采购需求建议、缺料预警 | API，小时级同步 |
| **EAS** | 异常告警通道 | - | 计划异常事件（延期风险/缺料/瓶颈） | 实时推送 |
| **WMS** | 仓库执行 | - | - | 由MES对接，APS不直连 |

### 3.2 APS输出物分类与确认机制

| 输出物类型 | 具体内容 | 确认机制 | 自动/人工 | 责任归属 |
|------------|----------|----------|-----------|----------|
| **建议型输出** | 计划版本对比报告、what-if仿真结果、资源负荷预测、瓶颈预警 | 供决策参考 | 查看即可 | 计划员 |
| **确认型输出** | 近3天执行计划（时分级，含机台级甘特图与派工清单） | 必须人工确认后方可下发 | 人工确认 → 自动下发 | 计划员确认 → 系统自动下发MES |
| **自动型输出** | 缺料预警、供给建议、ATP/CTP计算结果、风险告警 | 实时生成并推送 | 自动生成 | APS系统 |

### 3.3 计划版本/发布/回滚/反馈责任矩阵

| 环节 | 动作 | 执行角色 | 责任说明 |
|------|------|----------|----------|
| **版本创建** | what-if仿真生成新版本 | 计划员 | 复制基线，调整参数，生成对比版本 |
| **版本对比** | 多版本指标对比（交付/配套/效率） | 计划员 | 选择最优版本或继续调整 |
| **版本采纳** | 将仿真版本设为生效版本 | 计划员 | 确认后锁定，准备发布 |
| **计划发布** | 下发至MES执行 | 系统（人工确认后自动） | 确认后自动下发，占用N天冻结期资源 |
| **计划回滚** | 撤回已发布计划，恢复到上一版本 | 计划员（当日未开工）/生产主管（本车间未开工） | 仅允许回滚未进入执行的计划 |
| **执行反馈** | MES回写实际开工/完工时间 | MES → APS | 自动采集实绩数据 |
| **偏差分析** | 计划vs实际对比 | 系统自动生成报表 | 支持复盘分析 |

### 3.4 关键边界规则

1. **计划确认边界**：APS输出计划必须经过人工确认后方可下发MES，系统不允许自动直接下发
2. **冻结期边界**：已发布计划进入N天冻结期，期间资源被保护，插单需评估是否影响已承诺交期
3. **数据一致性边界**：ERP为订单/库存主数据权威源，MES为工艺/实绩权威源，APS为排产结果权威源
4. **异常处理边界**：计划异常（延期风险/缺料）由APS预警，人工决策，不自动调整计划

## 4. 术语与口径字典

### 4.1 订单类型术语

| 术语 | 全称 | 定义 | 来源系统 | 转化规则 | 优先级口径 |
|------|------|------|----------|----------|------------|
| **SO** | Sales Order（销售订单） | 客户下达的确定性订单，有明确交期承诺 | ERP销售模块 | 不可转化为SS/SS-U | 最高优先级，承诺交期不可随意调整 |
| **SS** | Schedule Stock（计划库存/预测补库） | 基于销售预测生成的补库订单，维持目标库存水平 | ERP计划模块/APS生成 | 可转化为SO（客户下单后），可转化为SS-U（紧急需求） | 中优先级，允许在交期范围内浮动 |
| **SS-U** | Schedule Stock-Urgent（紧急补库） | 因库存低于安全库存、断料风险或客户投诉触发的紧急补库订单 | APS自动生成（预警触发）或ERP手工创建 | 可转化为SO（客户正式下单） | 高优先级，仅次于SO，允许抢占SS资源 |

**优先级排序**：SO > SS-U > SS

### 4.2 产品层级术语

| 术语 | 定义 | 维护责任 | 数量级 |
|------|------|----------|--------|
| **产品族** | 具有相似工艺特征、共享资源的产品集合，排产策略配置的基本单位 | 研发/工艺部门维护，APS引用 | 100+ |
| **品番** | 具体的产品型号，对应唯一BOM和工艺路线 | ERP物料主数据维护 | 10万+ |
| **产品系列** | 营销维度的产品分组，可能与产品族交叉 | 销售部门维护，APS不直接使用 | - |
| **零部件** | 原材料、半成品、外购件，BOM的节点 | ERP物料主数据维护 | 几十万+ |

### 4.3 库存状态术语

| 状态 | 定义 | 是否参与"可用量"计算 | 说明 |
|------|------|------------------------|------|
| **可用** | 在库且未被预留的库存 | 是 | 可用量 = 在库量 - 已预留量 |
| **冻结** | 被特定计划版本预留的库存 | 否（该版本内已占用） | N天冻结期内被锁定 |
| **待检** | 已入库但未完成质检 | 否 | 质检合格后转入可用 |
| **在制** | 正在生产过程中的在制品 | 部分参与（预计完工时间后可用） | 按工序进度计算预计可用时间 |
| **在途** | 采购在途或调拨在途 | 是（按预计到货时间） | 采购件在途参与齐套时间计算 |
| **预留** | 被特定订单/工单预留 | 否 | 预留解除后恢复可用 |
| **安全库存** | 触发补库的最低库存水位 | 否（低于此水位时生成SS-U） | 不参与常规可用量计算 |

**可用量计算口径**：
- 齐套检查时点的可用量 = 当前可用库存 + 在制预计可用 + 在途预计到货 - 已冻结预留

### 4.4 Pegging（供需 pegging）术语
> 补充澄清：详见第X章（合批/拆批回溯与断链解释口径）。

| 术语 | 定义 | 口径说明 |
|------|------|----------|
| **Pegging** | 需求与供给的匹配关联关系 | 记录哪个需求被哪批库存/在制/在途满足 |
| **库存优先** | 优先使用现有库存满足需求 | 按优先级（SO>SS-U>SS）+ 时间先后分配库存 |
| **缺口补齐** | 库存不足部分通过生产/采购补齐 | 生成工单或采购建议 |
| **绑定粒度** | Pegging的精细程度 | 按批次级别绑定，支持追溯 |
| **断链** | Pegging关系中断 | 当库存被挪用、计划变更导致原匹配关系失效时标记断链，需重新匹配 |

**Pegging规则口径**：
- 库存分配优先级：SO > SS-U > SS
- 同优先级内：需求日期早的优先
- 追溯要求：支持从成品订单追溯到原材料批次
#### 4.4.1 断链触发分类与系统处置（需求）
断链不仅是标记，更必须驱动系统动作与解释输出，触发与处置如下：

1) **断链触发原因分类（至少覆盖）**
   - 库存被挪用：同物料库存被更高优先级需求占用（例如插单SO占用）
   - 状态变化：库存/在制被质检冻结、报废、转库，导致不可用
   - 供给延迟：在途到货延迟、上游工序完工延迟
   - 人工调整：人工改动计划、拆分/合并批次导致原绑定失效

2) **系统处置动作**
   - 自动重配：对断链需求重新执行 pegging（遵循“库存优先+缺口补齐”）
   - 保留解释：保留“断链前后两条链路”，用于追溯与复盘
   - 输出预警：若断链导致交期风险，必须输出“风险预警+影响订单清单”

3) **解释性输出要求**
   - 必须能回答：某订单缺货“是什么原因导致”（挪用/冻结/延迟/人工调整），并给出时间点与责任归因线索（不等同追责，只是可追溯）。

### 4.5 时间围栏（Time Fence）术语
> 补充澄清：详见第X章（Time Fence/Firm/Frozen碰壁规则）。

| 术语 | 定义 | 时间范围 | 行为规则 |
|------|------|----------|----------|
| **Time Fence** | 计划变更的敏感时期划分 | 可配置（如3天/7天/14天） | 区分计划的稳定性要求 |
| **冻结期（Frozen Zone）** | 已进入执行或即将执行的时间段 | 通常为1-3天 | 计划已发布，资源已占用，插单需评估影响 |
| **锁定区（Firm Zone）** | 计划已确定但尚未进入执行的时间段 | 通常为3-14天 | 允许有限调整，需审批或影响评估 |
| **允许变更区（Open Zone）** | 远期计划，可灵活调整 | Fence之外 | 允许自由调整，自动重排 |
| **粗排（Rough-Cut）** | 基于关键资源的能力粗算 | 月/季计划阶段 | 精度到周/天，用于中长期规划 |
| **精排（Detailed Scheduling）** | 基于全部约束的详细排产 | 日/周计划阶段 | 精度到时分，用于执行指导 |

**Fence规则口径**：
- Fence期内：计划变更需人工确认，评估对下游影响
- Fence期外：系统自动允许调整，参与下次滚动排程
- 不同产品族可配置不同Fence长度
#### 4.5.1 Fence三段与“N天冻结”的统一定义
为统一“冻结期/锁定/围栏”口径，本系统采用三段式 Fence，并用参数映射：

- **Frozen Zone（冻结期）= N天**：默认 N=3（可按产品族配置）
  - 行为：计划已发布，资源/物料默认不可被自动抢占；插单必须走影响评估+审批。
- **Firm Zone（锁定区）= N+M天**：默认 M=7（可按产品族配置）
  - 行为：允许有限调整（需影响评估），调整需留痕并输出“影响清单”。
- **Open Zone（允许变更区）= Firm之外**
  - 行为：允许系统自动重排，作为滚动优化主要空间。

备注：N、M 两个参数属于“策略可配置范围”，可按【产品族×订单类型】配置不同值。

#### UC-003 默认仲裁规则（Fence内插单）

3) **输出要求**

## 7. 主流程 + 异常流程

### 7.1 主流程：计划视图体系（Asprova式：一套计划结果 + 多视图）

> 说明：本系统不采用“日/周/月/季四级互斥归属”的排程方式。系统始终以**一套排程结果**（任务网络 + 资源作业顺序 + 供需占用）作为单一事实来源；“近期/远期”通过不同视图呈现同一结果，避免口径冲突。

#### 7.1.1 时间窗口与滚动机制（统一口径）
1) **计算窗口（Rolling Horizon）**：每次排程计算覆盖“当前时点起未来 **90天**”。
2) **滚动触发**：
   - 每日定时滚动（建议每日1次，例如08:00）
   - 事件触发滚动：插单、关键资源停机/恢复、关键物料到货变化、关键工单完工/延误等
3) **冻结/下发窗口（执行保护）**：未来 **3天** 为冻结窗口（Frozen Zone）。
   - 冻结窗口内默认不允许系统自动打乱已冻结任务；
   - 若必须调整，必须输出影响清单与原因，并形成新计划版本。
4) **时间桶（Time Bucket，用于远期视图聚合，不代表另起一套计划）**：
   - 日桶：按自然日
   - 周桶：按自然周（周一00:00~周日24:00；可按公司历法配置）
   - 月桶：按自然月
   - 补充：用于监控的“未来7天”称为**7天风险窗**（滚动窗），不称作周计划，避免混用。

#### 7.1.2 主流程（从数据到一套排程结果）
```
1. 数据同步
   ├─ ERP：SO/SS/SS-U订单、库存、工单、BOM
   ├─ MES：工艺路线、设备产能、模具状态、实绩（开工/完工/报工）
   └─ 采购系统API：供应商库存、在途量（小时级）

2. BOM按需展开（剪枝策略）
   逐层检查库存 → 满足则停止展开 → 不满足继续下层

3. 齐套检查（自制+采购）
   ├─ 自制件：库存+在制预计可用
   └─ 采购件：库存+在途+供应商库存

4. 有限产能排产（借鉴Asprova）
   ├─ 加载JSON约束规则（产品族×订单类型）
   ├─ 多目标优化（交期/配套率/效率）
   └─ 输出区间型计划（最早-最晚时间窗）+ 建议单点计划

5. 近期执行视图（未来3天，时分精度）
   ├─ 资源甘特图（机台/产线级作业顺序）
   ├─ 近3天派工清单（可下发）
   └─ 交付预测/交期风险清单（解释原因）

6. 远期协同视图（未来90天，按日/周/月桶聚合）
   ├─ PSI（需求-供给-库存）趋势表/图
   ├─ 资源负荷/瓶颈视图（资源组负荷）
   └─ 缺料与交付风险视图（预警+影响清单）

7. 人工确认与计划发布
   ├─ 冻结未来3天资源与物料占用（冻结期保护）
   └─ 下发MES执行（下发口径见7.3）
```

#### 7.1.3 近期（执行）视图：输出物与字段最小集合（可验收）
> 目的：回答“未来3天，哪台设备先做什么、做多少、何时开始结束、是否冻结不可动”，并可下发MES。

A) **资源甘特/作业顺序视图（机台/产线级）**
- 计划版本号（plan_version_id）：本次排程结果版本
- 工厂（factory_id）、车间/产线（workshop_id/line_id）
- 资源/设备（resource_id）：甘特图行
- 作业任务编号（task_id）：甘特条唯一ID
- 工单号（work_order_no）
- 订单号（order_no）、订单类型（order_type：SO/SS/SS-U）
- 物料/零件编码（item_code）、名称（item_name）
- 工序名称（operation_name）
- 计划数量（plan_qty）
- 计划开始时间（start_time）、计划结束时间（end_time）
- 冻结标记（freeze_flag：是否在未来3天冻结窗口内）
- 优先级原因（priority_reason）、换型类别（setup_class）

B) **近3天派工清单（下发包）**
- 下发批次号（dispatch_batch_id）
- 计划版本号（plan_version_id）
- 执行日期（work_date）、班次（shift，可选）
- 工厂/车间（factory_id/workshop_id）、资源/设备（resource_id）
- 作业任务编号（task_id）、工单号（work_order_no）
- 物料/零件（item_name）、计划数量（plan_qty）
- 建议开始/结束（start_time/end_time）
- 冻结标记（freeze_flag）、允许调整标记（editable_flag）

C) **交付预测/交期风险清单**
- 订单号（order_no）
- 需求交期（due_date）
- 预计交付日期（promise_date）
- 延误天数（delay_days）
- 延误原因分类（delay_reason_type：缺料/产能不足/冻结限制/插单挤占/设备故障/人工调整等）
- 关键缺件（critical_item，可选）

D) **占用/锁定与解释记录（用于“挪用/断链解释”）**
- 需求来源订单（demand_order_no）
- 物料/零件（item_name）、占用数量（allocated_qty）
- 供给来源类型（supply_type：库存/在制/在途/计划产出/采购到货）
- 供给来源编号（supply_ref_no：批次/工单/采购单等）
- 锁定级别（lock_level：不锁/锁定/冻结锁定）
- 是否被挪用（reallocated_flag）、挪用原因（reallocated_reason）
- 追溯链编号（pegging_chain_id）

#### 7.1.4 远期（协同）视图：输出物与字段最小集合（90天窗口，可验收）
> 目的：回答“未来90天哪些物料会短缺、哪些资源会超负荷、交付风险集中在哪些周”，驱动补库/加班/外协/调拨等决策。

E) **PSI视图（需求-供给-库存表：日/周/月桶）**
- 时间桶类型（bucket_type：日/周/月）、时间桶起始（bucket_start）
- 工厂（factory_id）
- 物料/零件编码（item_code）、名称（item_name）
- 期初库存（begin_stock）
- 需求量-客户订单（demand_so_qty）
- 需求量-补库（demand_ss_qty）
- 供给量-计划生产入库（supply_prod_qty）
- 供给量-采购到货（supply_po_qty）
- 供给量-跨厂到货（supply_transfer_qty，可选）
- 期末库存（end_stock）
- 安全库存（safety_stock）
- 短缺标记（shortage_flag）、最早短缺桶（first_short_bucket）

F) **负荷/瓶颈视图（资源组负荷：周/月桶为主）**
- 时间桶类型（bucket_type：周/月）、时间桶起始（bucket_start）
- 工厂（factory_id）
- 资源组（resource_group_id）
- 需求工时（required_hours）、可用工时（available_hours）
- 负荷率（load_rate）、超负荷工时（overload_hours）
- 瓶颈标记（bottleneck_flag）
- 建议动作（action_suggestion：加班/外协/提前生产/调拨/换线）

#### 7.1.5 验收口径（与第11/12章保持一致）
1) 同一计划版本下：资源甘特/派工清单/PSI/负荷视图口径一致（同源数据）。
2) 冻结窗口（未来3天）内：系统不自动打乱已冻结任务；若因插单调整，必须输出影响清单与原因，并形成新版本。
3) PSI/负荷视图覆盖未来90天：至少支持日/周/月桶切换；周桶按自然周（周一~周日）。
4) 对任何缺货/延期：必须能输出原因分类，并能追溯到占用/锁定/断链证据链（pegging_chain_id 等）。

### 7.2 异常流程：插单处理

```
1. 标记紧急订单（SO或SS-U）
2. 快速BOM展开（仅关键路径）
3. 齐套快速检查
4. Fence判断：
   ├─ Fence外 → 正常重排
   └─ Fence内 → ATP评估（5分钟内）
5. 影响分析：
   ├─ 可承诺 → 占用冻结资源，重排
   └─ 不可承诺 → 输出延迟影响清单
6. 人工决策确认
7. 重排并发布新版本
```
### 7.3 区间型计划输出与MES下发口径（V1落地规则）
- APS输出的“区间型计划”包含：最早开始/最晚开始/最早完成/最晚完成 + 建议开始/建议完成（单点建议）。
- **V1下发MES口径**：下发“建议开始/建议完成（单点计划）+ 冻结标记（Frozen/Firm）”，用于执行指导；
  - 时间窗用于：风险评估、插单影响分析、计划稳定性分析与复盘，不直接作为MES执行指令。
- 当人工拖拽调整或插单触发重排时，必须产生新版本，并输出“计划变更原因摘要”。

## 8. 策略可配置范围与生效维度

### 8.1 策略配置清单

| 策略项 | 可配置值 | 生效维度 | 行为差异说明 |
|--------|----------|----------|--------------|
| **排程方向** | 正排/倒排/混排 | 全局/产品族 | 正排：从当前向后排；倒排：从交期倒推；混排：关键工序倒排，其他正排 |
| **Pegging深度** | 单层/多层/全链路 | 产品族/订单类型 | 单层：仅成品-工单；多层：穿透至零部件；全链路：至原材料 |
| **库存优先策略** | 先进先出/优先级优先/最近到期优先 | 产品族 | 影响库存分配顺序 |
| **合批策略** | 严格按单/允许合批/强制合批 | 产品族/订单类型 | 影响生产效率和换线次数 |
| **最小批量** | 数值 | 产品族/品番 | 低于此数量不合批或建议外协 |
| **优先级评分因子** | 订单类型权重+交期紧急度+客户等级+利润贡献 | 全局 | 影响资源竞争时的分配优先级 |
| **Time Fence长度** | 1天/3天/7天/14天 | 产品族/订单类型 | Fence内计划保护强度不同 |
| **滚动频率** | 日（定时）+事件触发 | 全局 | 定时滚动 + 插单/资源/物料事件触发重排 |
| **计算窗口** | 固定未来90天 | 全局 | 每次排程覆盖当前时点起未来90天 |
| **时间桶视图** | 日/周/月（聚合展示） | 全局 | 远期协同视图按时间桶聚合；近期执行视图保持时分精度 |
| **插单处理策略** | 严格拒绝/评估后允许/强制插队 | 订单类型 | Fence内插单的处理方式 |
| **加班策略** | 不允许/允许（需确认）/自动扩展产能 | 产品族/设备组 | 产能不足时的处理方式 |
| **替代设备策略** | 不使用/优先使用/成本权衡 | 产品族/工序 | 是否允许使用替代设备 |
| **多目标优化权重** | 交期:配套率:效率 可调节 | 产品族 | 不同产品族优化目标不同 |

### 8.2 策略版本管理（需求）

| 需求项 | 说明 |
|--------|------|
| **策略版本保存** | 支持保存多组策略配置为版本 |
| **策略版本对比** | what-if仿真时可选择不同策略版本进行对比 |
| **策略生效记录** | 记录每个计划版本使用的策略配置，支持追溯 |
| **策略回滚** | 支持回退到历史策略版本 |
### 8.3 有限产能约束范围（V1 Must/Should/Could）
为避免方案设计阶段对“算到什么程度”产生分歧，本项目按阶段固化约束范围：

- **Must（V1必须纳入有限产能计算）**
  1) 资源日历（班次/停机/维护窗口）
  2) 工序顺序与前后依赖（路线约束）
  3) 工时/节拍（CT）与产能上限（按设备/设备组）
  4) Time Fence（冻结/锁定）内资源不可被自动抢占（除插单审批）
  5) 关键模具可用性（模具在用/维修/待检）

- **Should（V1建议纳入；若数据准备不足可先降级）**
  1) 并行资源（同工序多机并行）
  2) 替代设备策略（按产品族/工序配置）

## 第X章 关键疑问澄清与落地口径（Clarification Layer）

> 目的：把“容易误解但决定成败”的关键问题一次性讲清楚，形成团队统一口径。  
> 原则：主文档的范围、流程、接口、验收不推倒重来；本章作为“澄清层”，逐条回答疑问，并把结论落到可配置项、输出字段与验收口径上。  

### X.0 统一口径总览（先把规矩立住）
- **单一事实源**：系统始终以“一套计划结果（任务网络 + 资源顺序 + 供需占用）”作为事实源。  
- **近期执行窗口**：未来 **3天** 为冻结/可下发窗口（时分精度）。冻结区默认不被系统自动打乱；若调整必须输出影响清单并生成新版本。  
- **远期协同窗口**：未来 **90天** 用于协同视图（PSI/负荷/风险），以**日/周/月时间桶**聚合展示，不直接下发。  
- **自然周定义**：周桶默认周一00:00~周日24:00（可按公司历法配置）；“未来7天”称为7天风险窗，不称周计划。  
- **降级原则**：当性能/数据质量不足时，允许按“关键路径/瓶颈资源/关键物料Top-N/分域并行”降级计算，但必须标识计算模式并保证解释可追溯。

### X.1 **文档缺失：** 文档在第4.1节将订单优先级硬性规定为 `SO > SS-U > SS`。

**1）疑问/风险点（原始关注）**  
**文档缺失：** 文档在第4.1节将订单优先级硬性规定为 `SO > SS-U > SS`。

**2）业务解释（用现场语言讲清楚）**  
- 该问题本质上影响：交期承诺可信度、计划稳定性、以及跨工序/跨工厂协同的可执行性。  
- 若口径不清，系统会被迫“人肉兜底”，难以形成标准化运行机制。

**3）系统行为口径（写成可验收的规则）**  
- **Must（必须实现）**：系统自动怎么做/不做什么/何时需要人工确认。  
- **Should（建议实现）**：提升可用性与精益一致性的增强能力（可做V1.5/V2）。  
- **Not required（本期不要求）**：明确不做项，防止范围失控。
