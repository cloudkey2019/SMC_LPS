# APS V1代码审核基线与最终验收审核规范 v1.0

## 冻结基线一致性审核版

版本：v1.0

------------------------------------------------------------------------

# 一、文档定位

本文档用于指导APS V1后续代码审核、整改复核和最终验收。

目标：

-   保证代码实现符合冻结业务；
-   防止审核过程中重新设计业务；
-   明确必须整改项与优化建议边界；
-   保证0～5号位职责不漂移。

------------------------------------------------------------------------

# 二、审核基准优先级

代码审核必须按照以下优先级：

1.  APS V1最终全部流程与业务基线
2.  APS核心排产全流程走查
3.  数据架构与防腐层设计
4.  集成接口设计
5.  数据库字段说明及DDL
6.  对应号位开发实施包

如代码与上述文档冲突：

以冻结基线为准。

------------------------------------------------------------------------

# 三、审核原则

## 3.1 不因技术方案重新设计业务

禁止：

-   因代码结构调整改变业务Owner；
-   因实现方便复制业务真相；
-   因算法优化改变冻结规则。

------------------------------------------------------------------------

## 3.2 区分问题等级

## P0：必须整改

包括：

-   违反冻结业务；
-   数据真相重复；
-   Owner错误；
-   核心流程缺失。

------------------------------------------------------------------------

## P1：影响V1完整性

包括：

-   已冻结功能未实现；
-   接口缺失；
-   异常闭环不足。

------------------------------------------------------------------------

## P2：优化建议

包括：

-   性能优化；
-   代码重构；
-   可维护性提升。

不作为V1阻断条件。

------------------------------------------------------------------------

# 四、1号位审核重点

检查：

-   Solver输入正确；
-   Resource约束正确；
-   OperationPlanningMode支持；
-   Setup进入资源时间；
-   人工Resource支持。

禁止：

-   计算Pegging；
-   维护Supply；
-   生成权限逻辑。

------------------------------------------------------------------------

# 五、2号位审核重点

检查：

-   SchedulingOrchestrator；
-   Demand/Supply闭环；
-   Pegging；
-   Allocation；
-   FinalTask；
-   ScheduleRun；
-   PlanVersion。

禁止：

-   第二套Pegging；
-   第二套Supply；
-   权限治理。

------------------------------------------------------------------------

# 六、3号位审核重点

检查：

-   Auth/RBAC；
-   Rule/Parameter；
-   Candidate治理；
-   Scope；
-   生命周期。

禁止：

-   Solver逻辑；
-   排程计算；
-   Task生成。

------------------------------------------------------------------------

# 七、4号位审核重点

检查：

-   页面链路；
-   用户操作；
-   展示接口。

禁止：

-   页面计算业务结果；
-   绕过Service修改核心数据。

------------------------------------------------------------------------

# 八、5号位审核重点

检查：

-   ODS事实；
-   PI Position；
-   NextOperationContext；
-   Query接口。

禁止：

-   重算Pegging；
-   修改计划结果；
-   成为运行Owner。

------------------------------------------------------------------------

# 九、冻结红线检查

重点检查：

禁止新增：

-   OperationSupply；
-   OperationPegging；
-   CandidateInput平台；
-   SetupRuntime平台；
-   第二套计划结果。

------------------------------------------------------------------------

# 十、最终验收要求

代码通过必须满足：

-   业务闭环；
-   数量闭环；
-   时间闭环；
-   版本闭环；
-   职责闭环；
-   接口闭环。

------------------------------------------------------------------------

# 十一、最终原则

代码审核的目标：

不是追求重新设计最优架构。

而是确认：

> 当前实现是否准确落地已经冻结的APS V1业务和技术基线。

本规范作为后续所有号位代码审核统一依据。
