# APS V1 各号位9.15冻结后增量开发实施修订包 v1.0

**版本：v1.0**\
**定位：9.15冻结实施包增量修订说明**\
**适用对象：1～5号位开发团队及开发AI**

------------------------------------------------------------------------

# 一、文档目的

本修订包不是重新设计APS
V1，而是在9.15冻结实施包基础上，同步本轮最终冻结调整。

本版本只处理：

-   职责边界调整；
-   接口链路调整；
-   Setup换型规则；
-   无设备小工序；
-   人工有限产能；
-   用户输出责任；
-   Auth/RBAC归属；
-   Candidate治理。

已有冻结业务不重新打开。

------------------------------------------------------------------------

# 二、统一修订原则

## 保留

继续保留：

-   既有代码结构；
-   已审核通过逻辑；
-   SchedulingOrchestrator；
-   Pegging；
-   Allocation；
-   ScheduleRun；
-   PlanVersion；
-   Solver接口。

------------------------------------------------------------------------

## 禁止

禁止：

-   根据接口调整重新设计业务模型；
-   建立第二套Supply；
-   建立第二套Pegging；
-   建立第二套权限体系；
-   将治理职责迁移到运行模块。

------------------------------------------------------------------------

# 三、1号位实施修订

## 3.1 新增支持

### Operation Planning Mode

1号位Solver需要消费：

-   FINITE_RESOURCE；
-   UNCONSTRAINED；
-   WAIT_ONLY。

处理：

  模式              处理
  ----------------- ------------------
  FINITE_RESOURCE   进入有限能力求解
  UNCONSTRAINED     保留工艺时间
  WAIT_ONLY         形成等待约束

------------------------------------------------------------------------

## 3.2 人工有限产能

人工统一作为Resource。

复用：

    Resource
    +
    ResourceCalendar
    +
    OperationResourceEligibility

禁止：

-   HumanSolver；
-   WorkerSolver；
-   独立人工排产模型。

------------------------------------------------------------------------

## 3.3 Setup换型

Setup作为Resource Timeline约束。

Solver需要考虑：

-   FromMaterial；
-   ToMaterial；
-   SetupTime；
-   Resource。

禁止：

将Setup形成独立Task类型。

------------------------------------------------------------------------

## 3.4 用户输出

1号位负责产生：

-   延期原因；
-   Resource阻塞原因；
-   Setup影响原因；
-   Unscheduled原因。

2号位负责保存。

------------------------------------------------------------------------

------------------------------------------------------------------------

# 九、最终冻结要求

后续代码开发必须遵循：

1.  业务真相只有一份；
2.  接口调整不改变业务Owner；
3.  查询服务不能复制计算逻辑；
4.  治理服务不能承担运行计算；
5.  页面不能绕过正式业务链路。

本修订包作为9.15冻结实施包后续开发同步依据。
