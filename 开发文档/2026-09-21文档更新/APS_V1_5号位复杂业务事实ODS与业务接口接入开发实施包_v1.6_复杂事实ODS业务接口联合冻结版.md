# APS V1_5号位复杂业务事实ODS与业务接口接入开发实施包 v1.6

## 复杂业务事实、ODS与业务接口联合冻结版

版本：v1.6\
适用对象：5号位及开发AI

------------------------------------------------------------------------

# 一、文档定位

本版本基于9.15冻结实施包及最终职责边界调整，用于指导5号位复杂业务事实、ODS、防腐层和业务接口开发。

本版本不重新设计APS业务模型，只同步：

-   复杂事实接入；
-   PI Position；
-   NextOperationContext；
-   Manual ETA；
-   Query接口；
-   前端业务中转。

------------------------------------------------------------------------

# 二、5号位最终职责

5号位负责：

-   复杂业务事实ODS；
-   外部系统事实接入；
-   PI Position计算；
-   NextOperationContext计算；
-   MES复杂事实标准化；
-   Manual ETA事实维护；
-   业务查询接口。

5号位不负责：

-   Pegging计算；
-   Allocation计算；
-   Solver计算；
-   FinalTask生成；
-   计划结果修改。

------------------------------------------------------------------------

# 三、PI Position职责边界

## 3.1 5号位负责

计算：

-   PI当前执行位置；
-   已完成Stage解释；
-   下一执行上下文。

输出：

-   Position信息；
-   StartStageCode；
-   StartOperationCode；
-   NextOperationContext。

------------------------------------------------------------------------

## 3.2 2号位负责

消费：

-   PI Position；
-   NextOperationContext。

用于：

-   LogicalProductionDemand；
-   Solver输入准备。

------------------------------------------------------------------------

## 3.3 禁止

禁止：

-   5号位生成Supply；
-   5号位计算Pegging；
-   5号位生成Task。

------------------------------------------------------------------------

# 四、MES复杂事实接入

5号位负责：

-   MES工序事实；
-   Stage事实；
-   报工事实标准化；
-   工序级LastReportResourceCode。

------------------------------------------------------------------------

边界：

5号位提供事实解释。

2号位负责运行消费。

------------------------------------------------------------------------

# 五、Manual ETA

## 5.1 Owner

Manual ETA维护归5号位。

包括：

-   人工调整；
-   ETA事实保存；
-   历史追溯。

------------------------------------------------------------------------

## 5.2 责任链

    5号位
    Manual ETA事实

    ↓

    2号位
    Effective ETA计算

    ↓

    Pegging/Scheduling
    消费

------------------------------------------------------------------------

# 六、Query接口建设

5号位向4号位提供业务查询接口。

包括：

-   Plan Overview；
-   Order Plan；
-   Gantt；
-   Explanation；
-   Supply Trace；
-   Pegging Trace；
-   Demand Protection查询；
-   MES查询。

------------------------------------------------------------------------

# 七、查询接口边界

5号位负责：

-   DTO转换；
-   查询聚合；
-   前端友好输出。

禁止：

-   重算Pegging；
-   重算Allocation；
-   修改计划结果。

------------------------------------------------------------------------

# 八、与2号位接口

5号位提供：

-   PI Position；
-   NextOperationContext；
-   MES复杂事实；
-   ODS事实；
-   ETA事实。

2号位提供：

-   运行结果；
-   计划事实；
-   Pegging结果。

------------------------------------------------------------------------

# 九、与3号位接口

5号位消费：

-   用户权限上下文；
-   Business Scope上下文。

不负责：

-   用户权限；
-   Role管理；
-   Candidate治理。

------------------------------------------------------------------------

# 十、跨厂事实边界

保持：

跨厂物流事实用于：

-   SH存在性判断；
-   物流追溯。

不形成：

-   INTERPLANT_IN_TRANSIT Supply；
-   独立Supply模型。

------------------------------------------------------------------------

# 十一、禁止事项

禁止：

-   复制2号位Pegging；
-   复制2号位Allocation；
-   直接修改核心排程表；
-   成为计划结果Owner；
-   建设第二套运行真相。

------------------------------------------------------------------------

# 十二、验收重点

必须验证：

1.  PI Position计算准确；
2.  NextOperationContext可被2号位消费；
3.  Manual ETA责任清晰；
4.  Query接口满足前端需求；
5.  不产生第二套业务真相；
6.  ODS事实与APS运行边界清晰。

------------------------------------------------------------------------

# 十三、最终冻结原则

5号位定位：

> APS V1复杂业务事实与业务查询能力中心。

5号位负责解释事实、提供接口，不改变APS运行真相。
