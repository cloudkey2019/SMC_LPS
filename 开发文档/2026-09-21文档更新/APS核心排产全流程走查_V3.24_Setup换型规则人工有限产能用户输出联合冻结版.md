# APS核心排产全流程走查 V3.24

## Setup换型规则、人工有限产能、用户输出联合冻结版

版本：V3.24

------------------------------------------------------------------------

# 一、文档定位

本版本基于APS
V1最终冻结业务基线、数据架构、接口设计及各号位实施包，用于最终排产流程走查。

本次更新仅同步：

-   Setup换型约束；
-   无设备小工序处理；
-   人工有限产能；
-   Candidate治理边界；
-   用户输出解释链路。

不改变原有APS V1核心流程。

------------------------------------------------------------------------

# 二、APS V1核心排产主流程

    需求输入
     ↓
    需求解析
     ↓
    Supply构建
     ↓
    Pegging供需承接
     ↓
    Logical Production Demand
     ↓
    有限产能排程
     ↓
    Task生成
     ↓
    计划发布
     ↓
    执行反馈

------------------------------------------------------------------------

# 三、排程前准备

## 3.1 运行输入

排程运行前准备：

-   Demand；
-   Supply；
-   Pegging结果；
-   PI Position；
-   NextOperationContext；
-   Rule Snapshot；
-   Parameter Snapshot；
-   Strategy Snapshot。

------------------------------------------------------------------------

## 3.2 职责边界

2号位：

负责运行数据准备。

3号位：

负责规则和参数冻结。

5号位：

负责复杂事实提供。

1号位：

负责Solver计算。

------------------------------------------------------------------------

# 四、有限产能排程流程

## 4.1 Operation Planning Mode

工序是否参与有限资源求解，由：

Operation Planning Mode

决定。

------------------------------------------------------------------------

## 模式

  模式              处理
  ----------------- ------------------
  FINITE_RESOURCE   进入有限能力求解
  UNCONSTRAINED     保留工艺时间
  WAIT_ONLY         形成等待约束

------------------------------------------------------------------------

# 五、Resource能力模型

统一：

    Resource
    +
    ResourceCalendar
    +
    OperationResourceEligibility

支持：

-   设备资源；
-   人工资源。

------------------------------------------------------------------------

# 六、Setup换型流程

Setup作为资源时间约束。

计算：

-   当前任务；
-   下一任务；
-   Resource；
-   Setup规则。

影响：

-   Start Time；
-   End Time；
-   Resource占用；
-   交期风险。

------------------------------------------------------------------------

禁止：

-   Setup作为独立生产Task；
-   Setup生成Supply；
-   Setup改变Pegging。

------------------------------------------------------------------------

# 七、无设备小工序处理

不再采用：

"无设备直接跳过"。

根据：

OperationPlanningMode

决定：

-   是否占用有限资源；
-   是否进入Solver；
-   是否形成等待关系。

------------------------------------------------------------------------

# 八、Candidate流程

Candidate流程：

    用户创建Candidate
     ↓
    3号位治理校验
     ↓
    2号位执行
     ↓
    1号位Solver计算
     ↓
    结果保存
     ↓
    用户比较确认

------------------------------------------------------------------------

# 九、解释输出流程

延期及影响原因：

    1号位排程过程产生
     ↓
    2号位保存
     ↓
    5号位查询接口
     ↓
    4号位展示

包括：

-   Material原因；
-   Resource原因；
-   Setup原因；
-   Dependency原因；
-   Firm/Frozen原因。

------------------------------------------------------------------------

# 十、Pegging与PI Position边界

## Pegging

Owner：

2号位。

保持：

-   Demand/Supply承接；
-   Allocation；
-   数量闭环。

------------------------------------------------------------------------

## PI Position

Owner：

5号位计算。

2号位消费。

不作为Supply。

------------------------------------------------------------------------

# 十一、跨厂业务

保持：

跨厂事实用于：

-   Supply承接解释；
-   物流追踪。

不形成：

-   第二Supply模型；
-   INTERPLANT_IN_TRANSIT Supply。

------------------------------------------------------------------------

# 十二、最终流程红线

禁止：

-   页面直接修改排程结果；
-   查询服务复制计算逻辑；
-   5号位重算Pegging；
-   3号位参与Solver；
-   1号位维护权限；
-   新建第二套计划真相。

------------------------------------------------------------------------

# 十三、流程验收重点

必须验证：

1.  排程主链闭环；
2.  Setup正确影响资源时间；
3.  人工资源可参与有限产能；
4.  Candidate可追溯；
5.  解释信息可查询；
6.  Pegging、PI Position职责不漂移。

------------------------------------------------------------------------

# 十四、最终结论

APS V1排产流程形成：

-   业务闭环；
-   数量闭环；
-   时间闭环；
-   版本闭环；
-   职责闭环。

本版本作为核心排产流程走查冻结依据。
