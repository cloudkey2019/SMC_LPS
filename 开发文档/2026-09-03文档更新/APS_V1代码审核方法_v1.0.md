# APS V1代码审核方法 v1.0

## 20260902 双专项冻结对齐版

------------------------------------------------------------------------

# 一、文档定位

本文档用于指导 APS V1 后续代码审核。

目的：

1.  保证代码审核基于当前冻结业务；
2.  防止历史讨论重新打开已冻结设计；
3.  防止以未来版本能力要求V1代码；
4.  明确各号位审核边界。

本文件不是业务设计文档。

它定义：

> 如何审核代码，而不是重新设计业务。

------------------------------------------------------------------------

# 二、审核依据优先级

代码审核必须按照以下顺序：

    APS V1当前有效冻结基线索引
            ↓
    APS V1最终业务基线
            ↓
    专项业务裁决
            ↓
    技术设计文档
            ↓
    号位实施包
            ↓
    代码实现

如代码与历史文档冲突：

以当前冻结基线为准。

------------------------------------------------------------------------

# 三、审核原则

## 1. 只审核冻结范围

必须判断：

-   当前V1是否要求；
-   当前号位是否负责；
-   当前接口是否冻结。

不得因为：

-   架构更优雅；
-   未来扩展更方便；
-   通用设计更漂亮；

要求V1重新设计。

------------------------------------------------------------------------

## 2. 区分问题等级

## P0

阻断V1：

例如：

-   核心流程错误；
-   数量闭环破坏；
-   权限边界失效；
-   接口契约错误。

------------------------------------------------------------------------

## P1

需要整改：

例如：

-   已冻结能力缺失；
-   边界实现错误；
-   测试不足。

------------------------------------------------------------------------

## P2

优化建议：

例如：

-   代码质量；
-   可维护性；
-   非V1扩展。

P2不得包装成V1缺陷。

------------------------------------------------------------------------

# 四、号位审核边界

## 1号位

负责：

-   有限产能Solver；
-   Resource Constraint；
-   Task生成。

审核：

-   输入是否正确；
-   约束是否生效；
-   求解结果是否符合冻结规则。

不审核：

-   Supply来源；
-   Domain Resolve；
-   Position计算。

------------------------------------------------------------------------

## 2号位

负责：

-   ScheduleRun；
-   Domain Resolve执行；
-   Pegging；
-   Allocation；
-   Position Snapshot保存与消费；
-   PlanVersion运行管理。

审核：

-   流程编排；
-   接口消费；
-   数量闭环；
-   主链正确性。

不审核：

-   ERP/MES事实解释；
-   Position计算规则。

------------------------------------------------------------------------

## 3号位

负责：

-   Rule；
-   Parameter；
-   Strategy；
-   Authentication；
-   RBAC；
-   Business Scope；
-   Audit；
-   DomainDefinition治理。

审核：

-   配置版本；
-   权限边界；
-   发布流程。

不审核：

-   Pegging；
-   Solver。

------------------------------------------------------------------------

## 4号位

负责：

-   页面；
-   展示；
-   操作入口。

审核：

-   展示正确；
-   权限体验。

不作为：

业务安全边界。

------------------------------------------------------------------------

## 5号位

负责：

-   ERP/MES/ODS事实；
-   PI Position计算；
-   Supply事实接口；
-   业务接口接入。

审核：

-   事实正确；
-   Position闭环；
-   接口契约。

不审核：

-   Pegging；
-   Allocation；
-   Solver。

------------------------------------------------------------------------

# 五、重点冻结检查项

## Domain

必须检查：

-   DomainDefinition由治理配置产生；
-   ScheduleRun冻结配置语义；
-   2号位执行Domain Resolve；
-   DomainKey属于运行结果。

禁止：

-   ERP直接提供DomainKey；
-   Material永久绑定Domain。

------------------------------------------------------------------------

## Supply / Position

必须检查：

ProductionInstruction：

是Supply。

ProductionInstructionPositionSnapshot：

是位置事实。

禁止：

-   Position作为Supply；
-   PI Transit生成Transit Supply；
-   Received重复扣减。

------------------------------------------------------------------------

## 数量闭环

必须检查：

    Σ Position.Quantity
    =
    ERP ProductionInstruction RemainingQty

异常：

记录。

不得自动修改事实。

------------------------------------------------------------------------

# 六、代码审核输出要求

正式审核报告必须包含：

1.  审核对象；
2.  Commit/版本；
3.  对应冻结基线；
4.  已通过项；
5.  P0/P1问题；
6.  不属于当前范围的问题；
7.  后续整改建议。

------------------------------------------------------------------------

# 七、禁止事项

审核过程中禁止：

1.  用旧文档推翻当前冻结；
2.  将未来V2/V3能力作为V1缺陷；
3.  因单个代码实现偏好重新设计业务；
4.  扩大号位职责；
5.  要求跨号位重复建设。

------------------------------------------------------------------------
