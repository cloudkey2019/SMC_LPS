# 二、治理范围

本次治理围绕两个专项：

## 专项一：Domain Resolve边界治理

核心结论：

-   DomainDefinition属于APS治理配置；
-   ScheduleRun启动时冻结本次运行配置语义；
-   2号位执行Domain Resolve；
-   Order / Demand DomainKey属于APS运行结果。

职责：

  角色       职责
  ---------- ----------------------
  3号位      DomainDefinition治理
  2号位      Domain Resolve执行
  其他号位   消费结果

------------------------------------------------------------------------

## 专项二：Supply / ProductionInstruction Position边界治理

核心结论：

ProductionInstruction：

属于Supply。

ProductionInstructionPositionSnapshot：

表示ProductionInstruction剩余数量的位置事实。

不是：

-   独立Supply；
-   新Supply来源；
-   历史事件流水。

关系：

ProductionInstruction \| +-- ProductionInstructionPositionSnapshot

# 四、已关闭的主要歧义

## 1. Position是否属于Supply

结论：

否。

------------------------------------------------------------------------

## 2. PI Transit是否生成Transit Supply

结论：

否。

PI Transit属于Position状态。

------------------------------------------------------------------------

## 3. SH Transit是否生成Transit Supply

结论：

否。

属于履约状态。

------------------------------------------------------------------------

## 4. 2号位是否负责Position计算

结论：

否。

5号位负责事实解释与Position计算。

------------------------------------------------------------------------

## 5. 5号位是否负责Pegging

结论：

否。

Pegging属于2号位。

# 六、号位审核边界

## 1号位

审核：

-   Solver；
-   资源约束；
-   Task生成。

不审核：

-   Supply；
-   Domain；
-   Position计算。

------------------------------------------------------------------------

## 2号位

审核：

-   ScheduleRun；
-   Domain Resolve执行；
-   Pegging；
-   Snapshot保存与消费。

不审核：

-   MES事实解释；
-   Position计算规则。

------------------------------------------------------------------------

## 3号位

审核：

-   规则治理；
-   配置版本；
-   权限。

不审核：

-   运行计算。

------------------------------------------------------------------------

## 4号位

审核：

-   展示；
-   操作。

------------------------------------------------------------------------

## 5号位

审核：

-   ODS事实；
-   ERP/MES解释；
-   Position计算。

不审核：

-   Pegging。

------------------------------------------------------------------------
