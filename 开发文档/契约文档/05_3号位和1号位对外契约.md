## 6.10 治理版本发布接口契约（阶段 A-4/A-5/A-6 扩展，P0-05/P0-06）

> 本契约由 3 号位治理域（Application 编排层）提供，红线 #5（接口即契约）要求接口签名变更前先更新本契约。
> 六态状态机：DRAFT / SUBMITTED / APPROVED / PUBLISHED / DISABLED / ARCHIVED（值即冻结 DDL CK 字面量）。
> 跨号位冻结语义（与 2 号位边界）：新 Run 无显式 `StrategyProfileVersionId` 时，必须得到**当前有效、无歧义的 PUBLISHED 策略包**；若配置存在歧义，报配置错误，而非随机取一个。Exact SQL/Cache 前缀为实现细节，不反向修改 2 号位主流程。


## 6.11 运行生命周期与 Candidate 最小确认契约（P0-08）

> 依据：0 号位《代码综合符合性审核报告》P0-08 + 冻结 DDL v5.1.2（§3.1 ScheduleRun / §3.2 PlanVersion）。
> 边界：以下为 3号位生命周期治理边界；**不重写 2号位已冻结的运行状态执行逻辑**
> （SchedulingOrchestrator / ScheduleRunService / DomainSchedulingJob / DomainLayerCoordinatorJob 的执行流转不动）。

### 边界总览（跨号位）

| 场景 | 3号位职责 | 2号位职责（不动） |
|---|---|---|
| FULL | ExpectedDomainKeysJson ≥1 Domain 校验；冻结规则治理 | 多 Domain 实际计算、结果持久化、Domain 计算主流程 |
| Candidate | ExpectedDomainKeysJson 严格 1 Domain 校验；最小人工确认（Actor/ConfirmedAt/CandidatePlanVersionId/Remark）；不强制 OA；不建 MultiDomain Candidate | 无（Candidate 由 2号位生成，3号位负责确认/激活边界） |
| FAILED 恢复 | **新建** ScheduleRun（生命周期动作） | RUNNING→COMPLETED/FAILED 状态流转执行 |

### 6.11.1 IRunLifecycleService（运行生命周期服务）

```csharp
/// <summary>ScheduleRun 运行生命周期治理（3号位，P0-08）</summary>
public interface IRunLifecycleService
{
    /// <summary>
    /// 校验 ScheduleRun.ExpectedDomainKeysJson 冻结规则（P0-08）。
    /// 规则：JSON 数组格式（DDL CHECK ISJSON 兜底）；
    ///       RunType=FULL_SCHEDULE 类 → Domain 数 ≥ 1；
    ///       RunType=RESCHEDULE 类（Candidate） → Domain 数恰为 1。
    /// 失败：抛 InvalidOperationException（配置错误，不静默降级）。
    /// </summary>
    Task ValidateExpectedDomainKeysAsync(int scheduleRunId, CancellationToken ct = default);

    /// <summary>
    /// Candidate 最小人工确认（P0-08 / 二轮复审 P0-05 / P0-06）。
    /// 语义：确认**仅记录事实，不写 ActivatedAt/ActivatedBy、不转 ACTIVE、不预检同域 ACTIVE**；
    ///       Base ACTIVE 存在时仍可正常完成确认（确认与唯一性无关）。
    /// 落点：仅经 IGovernanceAuditLogRepository 记录 OperationType=ConfirmCandidate 审计
    ///       （Actor / ConfirmedAt / CandidatePlanVersionId(=planVersionId) / 必要 Remark）。
    /// 激活（ActivateCandidateAsync）以该审计作为"已完成最小人工确认"的硬前置。
    /// 不强制 OA；不建 MultiDomain Candidate。
    /// </summary>
    Task ConfirmCandidateAsync(int planVersionId, string actor, string? remark, CancellationToken ct = default);

    /// <summary>
    /// 激活 Candidate（确认后正式采用：CANDIDATE → ACTIVE，原子替换同域旧 ACTIVE）。
    /// 前置（均为硬校验，缺失/不满足一律抛 InvalidOperationException）：
    ///   a) DomainKey 非空（V1 必填语义）；
    ///   b) 已完成最小人工确认：存在针对该 PlanVersion 的 ConfirmCandidate 审计记录；
    ///   c) 来源 Run 可激活：SourceScheduleRunId 非空，且其 RunType != "INSERT_ORDER_WHATIF"
    ///      （实施包十九：INSERT_ORDER_WHATIF 仅组合 CTP / INSERT_IMPACT_ANALYSIS，二者永远不得激活）。
    /// 采用边界：原子替换——单事务内将同域既有 ACTIVE 归档（Status→ARCHIVED + ArchivedAt），
    ///       再将本 Candidate 置 ACTIVE（UQ_PlanVersion_OneActivePerDomain 红线保留，不删除）。
    /// </summary>
    Task ActivateCandidateAsync(int planVersionId, string actor, CancellationToken ct = default);

    /// <summary>
    /// FAILED 恢复（P0-08）：为 FAILED ScheduleRun **新建** 一条 RUNNING ScheduleRun 重跑。
    /// 继承旧 Run 的 StrategyProfileVersionId 与 ExpectedDomainKeysJson 基线；
    /// 绝不动旧 FAILED 记录（不回改 RUNNING）。
    /// 返回新 ScheduleRunId。
    /// </summary>
    Task<int> RecoverFailedRunAsync(int failedScheduleRunId, CancellationToken ct = default);

    /// <summary>
    /// Run 引用追溯（P0-08 第 12 项）：ScheduleRun → StrategyProfileVersion → RuleSet/ParameterSet
    /// + 关联 PlanVersion 状态与结果。P0-06 已提供版本维（RunStrategyProfileTrace），本方法补齐 Run 维。
    /// </summary>
    Task<RunReferenceTrace> GetRunReferenceTraceAsync(int scheduleRunId, CancellationToken ct = default);
}
```

### 6.11.3 ExpectedDomainKeysJson 语义（冻结规则）

- 存储：`ScheduleRun.ExpectedDomainKeysJson`（NVARCHAR(MAX)，JSON 数组，DDL CHECK `ISJSON=1` 约束）
- 冻结时机：Run 启动时一次写入，创建后**不可修改**；不得根据已创建 PlanVersion 反推（DDL 表头注释）
- 终态判定权威：ScheduleRun 终态（COMPLETED / PARTIAL_SUCCESS / FAILED）判定唯一依据该字段
- 数量规则：FULL ≥1 Domain；Candidate（RESCHEDULE）恰 1 Domain
- 去重规则（P1-01）：FULL 场景预期 Domain 集合**不可重复**（重复 DomainKey 一律拒绝）
- 校验失败 → 抛 `InvalidOperationException`（配置错误），**不静默降级**

### 6.11.4 Candidate 最小确认语义

- 确认落点：**仅审计**（`OperationType=ConfirmCandidate`，`EntityType=PlanVersion`，`EntityId`=被确认的 PlanVersion.Id）；`CandidatePlanVersionId` = 被确认的 PlanVersion.Id，记入 `Remarks`
- 仅记录：Actor / ConfirmedAt / CandidatePlanVersionId / 必要 Remark（经 `IGovernanceAuditLogRepository`；审计实体无独立列，`CandidatePlanVersionId` 记入 `Remarks`）
- **确认不写 `ActivatedAt` / `ActivatedBy`、不转 ACTIVE、不预检同域 ACTIVE**（二轮复审 P0-05 / P0-06：确认仅是记录动作，Base ACTIVE 存在不影响确认）
- 不强制 OA；不建 MultiDomain Candidate（每 Domain 仅确认其自身）
- 激活前置（二轮复审 P0-03 / P0-04 / P0-06 收紧）：
  - `DomainKey` 非空（V1 必填）
  - **已完成最小人工确认**：存在针对该 PlanVersion 的 `ConfirmCandidate` 审计记录
  - **来源 Run 可激活**：`SourceScheduleRunId` 非空，且其 `RunType != "INSERT_ORDER_WHATIF"`
  - **原子替换**：单事务内归档同域既有 ACTIVE（→ARCHIVED + ArchivedAt）再置本 Candidate 为 ACTIVE；`UQ_PlanVersion_OneActivePerDomain` 红线保留

```csharp
    /// </summary>
    Task ReplaceActiveAsync(
```
