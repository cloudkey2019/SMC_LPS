# 第二章：核心数据结构契约

## 2.1 ScheduleContext（排产沙盘）

**业务用途**：排产沙盘是整个APS系统的核心数据容器，包含了一次完整排产所需的所有数据。

```csharp
/// <summary>
/// 排产沙盘上下文
/// 包含一次完整排产所需的所有数据
/// </summary>
public class ScheduleContext
{
    // ============ 基础标识 ============
    
    /// <summary>
    /// 域标识（如"ProductFamily_A"、"Factory_TJ"）
    /// 用于分域计算的核心标识
    /// </summary>
    public string DomainKey { get; set; }
    
    /// <summary>
    /// 计划版本ID
    /// 对应数据库PlanVersion表的主键
    /// </summary>
    public int PlanVersionId { get; set; }
    
    /// <summary>
    /// 计划期间开始日期
    /// </summary>
    public DateTime PlanHorizonStart { get; set; }
    
    /// <summary>
    /// 计划期间结束日期
    /// </summary>
    public DateTime PlanHorizonEnd { get; set; }
    
    /// <summary>
    /// 当前时间（用于冻结区判定）
    /// </summary>
    public DateTime CurrentTime { get; set; }
    
    // ============ 订单数据 ============
    
    /// <summary>
    /// 独立需求订单列表（PRODUCTION_INSTRUCTION生产指示，原MTS）
    /// 这些订单是排产的起点，需要进行Pegging和拆批
    /// </summary>
    public List<Order> IndependentDemands { get; set; }
    
    /// <summary>
    /// 所有订单列表（包括MTS和MTO）
    /// 包含独立需求和相关需求
    /// </summary>
    public List<Order> Orders { get; set; }
    
    // ============ 任务数据 ============
    
    /// <summary>
    /// 任务列表（排程的基本单位）
    /// 由拆批凭证生成，是1号位排程引擎的输入
    /// </summary>
    public List<Task> Tasks { get; set; }
    
    /// <summary>
    /// 历史锚点任务（已下发MES的冻结Task）
    /// 用于约束排程，确保已下发任务不被修改
    /// </summary>
    public List<Task> HistoricalAnchors { get; set; }
    
    // ============ 资源数据 ============
    
    /// <summary>
    /// 资源日历（设备可用时间）
    /// 包含设备的工作时间、维护时间、停机时间等
    /// </summary>
    public ResourceCalendar ResourceCalendar { get; set; }
    
    /// <summary>
    /// 资源列表（设备、产线、工作中心）
    /// </summary>
    public List<Resource> Resources { get; set; }
    
    // ============ 物料数据 ============
    
    /// <summary>
    /// 物料主数据列表
    /// </summary>
    public List<Material> Materials { get; set; }
    
    /// <summary>
    /// BOM展开结果（物料清单）
    /// 从ODS库拉取的BOM数据
    /// </summary>
    public BOMWorkset BOMData { get; set; }
    
    // ============ 库存数据 ============
    
    /// <summary>
    /// 库存记录列表
    /// 包含ERP库存和MES库存的统一视图
    /// </summary>
    public List<InventoryRecord> Inventories { get; set; }
    
    /// <summary>
    /// 在途库存列表（采购在途、生产在途）
    /// </summary>
    public List<InTransitInventory> InTransitInventories { get; set; }
    
    // ============ Pegging数据 ============
    
    /// <summary>
    /// Pegging连线关系
    /// 记录需求与供给的匹配关系
    /// </summary>
    public List<PeggingLink> PeggingLinks { get; set; }
    
    /// <summary>
    /// Pegging账本（订单级别的物料需求账本）
    /// 用于拆批裁决时查询物料需求
    /// </summary>
    public Dictionary<long, PeggingLedger> PeggingLedgers { get; set; }
    
    // ============ 配置数据 ============
    
    /// <summary>
    /// 业务规则配置
    /// 包含优先级规则、拆批规则、冻结区规则等
    /// </summary>
    public BusinessRuleConfig RuleConfig { get; set; }
    
    /// <summary>
    /// 排程参数配置
    /// 包含排程算法参数、性能参数等
    /// </summary>
    public SchedulingParameters SchedulingParams { get; set; }
    
    // ============ 运行时数据 ============
    
    /// <summary>
    /// 执行日志（用于调试和审计）
    /// </summary>
    public List<ExecutionLog> Logs { get; set; }
    
    /// <summary>
    /// 性能指标（用于监控和优化）
    /// </summary>
    public PerformanceMetrics Metrics { get; set; }
}
```

## 2.2 Task（任务实体）

**业务用途**：Task是排程的基本单位，代表一个具体的生产任务。

```csharp
/// <summary>
/// 任务实体（排程的基本单位）
/// </summary>
public class Task
{
    // ============ 基础标识 ============
    
    /// <summary>
    /// 任务ID（数据库主键）
    /// </summary>
    public long Id { get; set; }
    
    /// <summary>
    /// 任务编号（业务主键）
    /// 格式：T{OrderNo}_{OperationSeq}_{SplitIndex}
    /// 示例：TMO202603001_010_001
    /// </summary>
    public string TaskNo { get; set; }
    
    /// <summary>
    /// 计划版本ID
    /// </summary>
    public int PlanVersionId { get; set; }
    
    /// <summary>
    /// 关联订单ID
    /// </summary>
    public long OrderId { get; set; }
    
    // ============ 物料信息 ============
    
    /// <summary>
    /// 物料ID
    /// </summary>
    public int MaterialId { get; set; }
    
    /// <summary>
    /// 物料编码（冗余字段，避免频繁JOIN）
    /// </summary>
    public string MaterialCode { get; set; }
    
    /// <summary>
    /// 任务数量
    /// </summary>
    public decimal Quantity { get; set; }
    
    /// <summary>
    /// 计量单位
    /// </summary>
    public string UOM { get; set; }
    
    // ============ 工艺信息 ============
    
    /// <summary>
    /// 工序序号（如010、020、030）
    /// </summary>
    public int OperationSeq { get; set; }
    
    /// <summary>
    /// 工序代码（第 1 层：具体工序，执行粒度；如 NC / MC / 切断 / 精修）
    /// </summary>
    public string OperationCode { get; set; }
    
    /// <summary>
    /// 工序名称
    /// </summary>
    public string OperationName { get; set; }
    
    /// <summary>
    /// 工艺类型 — 第 2 层：辅助分类标签（加工、装配、检验等）
    /// ⚠️ v2.4：值域见 ProcessTypeDict（骨架期 IsActive=0）；
    ///    本字段**不参与 BOM↔Routing 对接**，仅用于报表/粗分组/统计
    /// </summary>
    public string ProcessType { get; set; }
    
    /// <summary>
    /// 大工艺阶段码 — 第 3 层：BOM↔Routing 对接主键之二（v2.4 新增）
    /// ⚠️ 必须取自 StageDict（如 TJ_MACH / BJ_PAINT）；
    ///    1 号位生成 Task 时必填；决定 Task 落在哪个工厂的产能队列（工厂前缀）；
    ///    R20 跨组织场景 = 目标工厂视角（父件 TJ + 指派 BJ → BJ_MACH）。
    /// </summary>
    public string StageCode { get; set; }
    
    // ============ 资源信息 ============
    
    /// <summary>
    /// 资源ID（具体设备）
    /// 排程后赋值
    /// </summary>
    public int? ResourceId { get; set; }
    
    /// <summary>
    /// 工序编码（v5.0：替代原ResourceGroupId）
    /// 排程前赋值，通过 OperationResourceEligibility 动态确定可用资源
    /// </summary>
    public string? OperationCode { get; set; }
    
    // ============ 时间信息 ============
    
    /// <summary>
    /// 计划开始时间
    /// 由1号位排程引擎计算
    /// </summary>
    public DateTime? PlannedStartTime { get; set; }
    
    /// <summary>
    /// 计划结束时间
    /// 由1号位排程引擎计算
    /// </summary>
    public DateTime? PlannedEndTime { get; set; }
    
    /// <summary>
    /// 标准工期（小时）
    /// 从工艺路线获取
    /// </summary>
    public decimal Duration { get; set; }
    
    /// <summary>
    /// 准备时间（小时）
    /// 换型时间
    /// </summary>
    public decimal SetupTime { get; set; }
    
    // ============ 状态标识 ============
    
    /// <summary>
    /// 任务状态
    /// PENDING/SCHEDULED/FROZEN/RELEASED/COMPLETED
    /// </summary>
    public string Status { get; set; }
    
    /// <summary>
    /// 是否锁定（不允许重排）
    /// </summary>
    public bool IsLocked { get; set; }
    
    /// <summary>
    /// 是否在制品（WIP）
    /// 已开工但未完工的任务
    /// </summary>
    public bool IsWip { get; set; }
    
    /// <summary>
    /// 是否冻结（已下发MES）
    /// 冻结任务不允许修改
    /// </summary>
    public bool IsFrozen { get; set; }
    
    /// <summary>
    /// 是否关键路径
    /// 由1号位排程引擎标识
    /// </summary>
    public bool IsCriticalPath { get; set; }
    
    // ============ 业务属性 ============
    
    /// <summary>
    /// 任务类型
    /// PRODUCTION/SETUP/MAINTENANCE/SHIPPING
    /// </summary>
    public string TaskType { get; set; }
    
    /// <summary>
    /// 优先级分数（继承自订单）
    /// </summary>
    public decimal PriorityScore { get; set; }
    
    /// <summary>
    /// 拆批索引（同一订单同一工序的第几批）
    /// </summary>
    public int SplitIndex { get; set; }
    
    /// <summary>
    /// 换型属性（用于判断是否需要换型）
    /// 由5号位ISetupAttributeRule插件计算
    /// </summary>
    public string SetupAttribute { get; set; }
    
    // ============ 审计字段 ============
    
    /// <summary>
    /// 创建时间
    /// </summary>
    public DateTime CreatedAt { get; set; }
    
    /// <summary>
    /// 更新时间
    /// </summary>
    public DateTime UpdatedAt { get; set; }
}
```

## 2.3 Order（订单实体）

**业务用途**：订单是排产的需求来源，分为MTS（按库存生产）和MTO（按订单生产）两类。

```csharp
/// <summary>
/// 订单实体
/// </summary>
public class Order
{
    // ============ 基础标识 ============
    
    /// <summary>
    /// 订单ID（数据库主键）
    /// </summary>
    public long Id { get; set; }
    
    /// <summary>
    /// 订单编号（业务主键）
    /// </summary>
    public string OrderNo { get; set; }
    
    /// <summary>
    /// 订单类型（v5.0.24重分类）
    /// SALES_ORDER（客户订单，原SO/MTO）/ PRODUCTION_INSTRUCTION（生产指示，原MTS/SS/SS_U）
    /// </summary>
    public string OrderType { get; set; }
    
    // ============ 物料信息 ============
    
    /// <summary>
    /// 物料ID
    /// </summary>
    public int MaterialId { get; set; }
    
    /// <summary>
    /// 物料编码（冗余字段）
    /// </summary>
    public string MaterialCode { get; set; }
    
    /// <summary>
    /// 订单数量
    /// </summary>
    public decimal Quantity { get; set; }
    
    /// <summary>
    /// 计量单位
    /// </summary>
    public string UOM { get; set; }
    
    // ============ 组织信息 ============
    
    /// <summary>
    /// 产品族ID（用于分域计算）
    /// </summary>
    public int ProductFamilyId { get; set; }
    
    /// <summary>
    /// 工厂ID
    /// </summary>
    public int FactoryId { get; set; }
    
    /// <summary>
    /// 域标识（冗余字段）
    /// 格式：ProductFamily_{Code} 或 Factory_{Code}
    /// </summary>
    public string DomainKey { get; set; }
    
    // ============ 时间信息 ============
    
    /// <summary>
    /// 客户要求交期
    /// </summary>
    public DateTime CustomerDueDate { get; set; }
    
    /// <summary>
    /// 承诺交期（APS计算后给客户的承诺）
    /// </summary>
    public DateTime? PromisedDate { get; set; }
    
    // ============ 优先级信息 ============
    
    /// <summary>
    /// 优先级（1-100，数字越大优先级越高）
    /// 由业务人员手工设置或系统规则计算
    /// </summary>
    public int Priority { get; set; }
    
    /// <summary>
    /// 优先级分数（由5号位IOrderPrioritizationRule插件计算）
    /// 综合考虑交期、客户等级、订单金额等因素
    /// </summary>
    public decimal? PriorityScore { get; set; }
    
    // ============ 状态信息 ============
    
    /// <summary>
    /// 订单状态
    /// PENDING/SCHEDULED/RELEASED/COMPLETED/CANCELLED
    /// </summary>
    public string Status { get; set; }
    
    // ============ 来源信息 ============
    
    /// <summary>
    /// 来源系统（ERP/MES/MANUAL）
    /// </summary>
    public string SourceSystem { get; set; }
    
    /// <summary>
    /// 来源系统订单ID
    /// </summary>
    public string SourceOrderId { get; set; }
    
    /// <summary>
    /// 来源系统MasterID（ERP物料主数据ID）
    /// </summary>
    public int? SourceMasterID { get; set; }
    
    // ============ BOM信息 ============
    
    /// <summary>
    /// BOMNO（BOM编号）
    /// 用于BOM展开
    /// </summary>
    public string BOMNO { get; set; }
    
    /// <summary>
    /// MTS生产指示编号
    /// 仅MTS订单有值
    /// </summary>
    public string MTS_InstructionNo { get; set; }
    
    // ============ 客户业务衍生字段（v5.0.24澄清）============
    
    /// <summary>
    /// 客户区分（APS衍生，通过CustomerCodeMap查表得到）
    /// JAPAN/DOMESTIC/OVERSEAS/VIETNAM/INTER_FACTORY/OTHER；无匹配/失效默认OVERSEAS
    /// </summary>
    public string? CustomerSegment { get; set; }
    
    /// <summary>
    /// 需求成熟度（v5.0.24收窄）
    /// PRE_CONFIRMED=事前确认 / FORECAST=预测SHIKOMI。DELAYED已拆出为DelayStatus独立字段
    /// </summary>
    public string? DemandMaturityStatus { get; set; }
    
    /// <summary>
    /// 客户分级（VIP>KEY_ACCOUNT>STANDARD>GENERAL）
    /// 当前主要启用VIP/GENERAL两档，KEY_ACCOUNT/STANDARD预留
    /// </summary>
    public string? CustomerTier { get; set; }
    
    /// <summary>
    /// 延迟状态（v5.0.24新增，独立维度）
    /// ON_TIME（未延迟）/ FIRST_DELAY（首次延迟）/ REPEATED_DELAY（二次及以上延迟）
    /// ⚠️ 禁止与DemandMaturityStatus混用
    /// </summary>
    public string? DelayStatus { get; set; }
    
    // ============ Pegging信息 ============
    
    /// <summary>
    /// Pegging账本（物料需求账本）
    /// 记录该订单的物料需求和供给匹配情况
    /// 运行时字段，不持久化
    /// </summary>
    [NotMapped]
    public PeggingLedger PeggingLedger { get; set; }
    
    // ============ 审计字段 ============
    
    /// <summary>
    /// 创建时间
    /// </summary>
    public DateTime CreatedAt { get; set; }
    
    /// <summary>
    /// 更新时间
    /// </summary>
    public DateTime UpdatedAt { get; set; }
}
```


## 2.5 PeggingLink（供需关系）

**业务用途**：Pegging连线记录需求与供给的匹配关系。

```csharp
/// <summary>
/// Pegging连线（供需关系）
/// </summary>
public class PeggingLink
{
    /// <summary>
    /// Pegging连线ID
    /// </summary>
    public long Id { get; set; }
    
    /// <summary>
    /// 计划版本ID
    /// </summary>
    public int PlanVersionId { get; set; }
    
    // ============ 需求侧 ============
    
    /// <summary>
    /// 下游任务ID（需求侧）
    /// </summary>
    public long DownstreamTaskId { get; set; }
    
    /// <summary>
    /// 下游物料ID
    /// </summary>
    public int DownstreamMaterialId { get; set; }
    
    // ============ 供给侧 ============
    
    /// <summary>
    /// 上游任务ID（供给侧）
    /// 如果是库存供给，则为NULL
    /// </summary>
    public long? UpstreamTaskId { get; set; }
    
    /// <summary>
    /// 上游物料ID
    /// </summary>
    public int UpstreamMaterialId { get; set; }
    
    /// <summary>
    /// 供给源类型
    /// INVENTORY（库存）/IN_TRANSIT（在途）/PLANNED_PRODUCTION（计划生产）
    /// </summary>
    public string SupplySourceType { get; set; }
    
    /// <summary>
    /// 供给源ID
    /// 如果是库存，则为InventoryRecord.Id
    /// 如果是在途，则为InTransitInventory.Id
    /// 如果是计划生产，则为Task.Id
    /// </summary>
    public long SupplySourceId { get; set; }
    
    // ============ 数量信息 ============
    
    /// <summary>
    /// Pegging数量
    /// </summary>
    public decimal Quantity { get; set; }
    
    /// <summary>
    /// 计量单位
    /// </summary>
    public string UOM { get; set; }
    
    // ============ 时间信息 ============
    
    /// <summary>
    /// 提前期（天）
    /// 从供给到需求的时间间隔
    /// </summary>
    public int LeadTimeDays { get; set; }
    
    /// <summary>
    /// 创建时间
    /// </summary>
    public DateTime CreatedAt { get; set; }
}
```

## 2.6 InventoryRecord（库存记录）

**业务用途**：库存记录是Pegging的供给源之一。

**⚠️ v2.8架构调整**：InventoryRecord 对应数据库的 `InventoryBalance` 表，已从"通用余额表"改造为"带产品族上下文的规则筛选结果表"。

```csharp
/// <summary>
/// 库存记录（对应InventoryBalance表）
/// v2.8：增加产品族上下文和计划批次号
/// </summary>
public class InventoryRecord
{
    /// <summary>
    /// 库存记录ID
    /// </summary>
    public long Id { get; set; }
    
    /// <summary>
    /// 物料编码（业务主键）
    /// </summary>
    public string MaterialCode { get; set; }
    
    /// <summary>
    /// 产品族ID（v2.8新增）
    /// 同一物料在不同产品族下，可用库存可能不同（因规则筛选范围不同）
    /// </summary>
    public int ProductFamilyId { get; set; }
    
    /// <summary>
    /// 工厂ID
    /// </summary>
    public int FactoryId { get; set; }
    
    /// <summary>
    /// 现有量
    /// </summary>
    public decimal OnHandQty { get; set; }
    
    /// <summary>
    /// 已分配量
    /// </summary>
    public decimal AllocatedQty { get; set; }
    
    /// <summary>
    /// 可用库存数量（计算属性）
    /// AvailableQty = OnHandQty - AllocatedQty
    /// </summary>
    public decimal AvailableQty => OnHandQty - AllocatedQty;
    
    /// <summary>
    /// 库存来源
    /// ERP/MES/BOTH
    /// </summary>
    public string Source { get; set; }
    
    /// <summary>
    /// 计划批次号（v2.8新增）
    /// 关联到PlanVersion.BatchNo，用于追溯库存快照
    /// </summary>
    public string BatchNo { get; set; }
    
    /// <summary>
    /// 最后更新时间
    /// </summary>
    public DateTime LastUpdatedAt { get; set; }
}
```

**架构说明**：
- 此实体对应数据库的 `InventoryBalance` 表
- `InventoryBalance` 是经过规则筛选后的排程可用库存，不是原始库存
- 原始库存存储在 `InventoryFact_ERP` 和 `InventoryFact_MES` 表中
- 规则筛选包括：产品族仓库范围规则（`ProductFamilyInventoryScope`）和来源优先/排除规则（`InventorySourceRule`）

## 2.8 数据结构使用说明

### 2.8.1 ScheduleContext的生命周期

1. **创建阶段**：2号位IDataLoader.LoadDomainDataAsync()创建并填充
2. **计算阶段**：5号位业务规则插件读取并返回凭证
3. **执行阶段**：2号位IVoucherExecutor根据凭证修改ScheduleContext
4. **排程阶段**：1号位排程引擎读取Tasks和ResourceCalendar，计算时间
5. **持久化阶段**：2号位IBulkPersistence批量写入数据库

### 2.8.2 Task的生成时机

**⚠️ 架构红线**：Task由2号位根据5号位返回的SplitVoucher统一生成，5号位绝对禁止直接new Task！

生成流程：
1. 5号位ITaskSplitRule.CalculateSplit()返回SplitVoucher
2. 2号位IVoucherExecutor.ExecuteSplitVoucher()根据凭证new Task
3. Task加入ScheduleContext.Tasks列表

### 2.8.3 PeggingLink的生成时机

生成流程：
1. 5号位IPeggingRule.CalculatePegging()返回PeggingVoucher
2. 2号位IVoucherExecutor.ExecutePeggingVoucher()根据凭证new PeggingLink
3. PeggingLink加入ScheduleContext.PeggingLinks列表
