## 🎯 二、需求确认摘要

基于与用户的详细需求澄清，确认以下关键决策：

### 2.1 业务范围
- ✅ V1.0 先做核心高风险动作的权限控制
- ✅ 需要**多级审批**（不需要会签/或签、超时升级、审批撤回）
- ✅ 数据范围：**工厂级 + 产品族级 + 资源组级**
- ✅ 用户**自己维护**（不集成企业统一认证）
- ✅ 审批流**自己实现**（V1.0 不集成 OA）
- ✅ 审计日志**基本功能**（数据量不大）

### 2.2 架构决策
- ✅ 权限表**单独创建 APS_Auth 数据库**
- ✅ 每次排程**记录发起人**（PlanVersion.CreatedByUserId）
- ✅ 版本发布**不需要审批**
- ✅ ODS 批次重跑**不需要审批**
- ✅ MaterialSupplyContext 修改**只需权限控制和日志，不需要审批**
- ✅ 库存筛选规则暂时**只有 APS 管理员可修改，不需要审批**

### 2.3 技术选型
- ✅ 后端：**ASP.NET Core Identity + 自定义扩展**
- ✅ 前端：**Vue 3 + JWT Token**（2小时过期，无 Refresh Token）
- ✅ 密码策略：**简单策略**（V1.0）

## 🗄️ 三、数据库设计

### 3.1 APS_Auth 数据库

**库名**：`APS_Auth`  
**表数量**：13 张表  
**用途**：存储权限、审批、审计相关数据

**核心表清单**：

| 序号 | 表名 | 用途 | 记录数量级 |
|------|------|------|-----------|
| 1 | User | 用户表 | 10-100 |
| 2 | Role | 角色表 | 7-20 |
| 3 | Permission | 权限表 | 50-200 |
| 4 | UserRole | 用户角色关联表 | 10-200 |
| 5 | RolePermission | 角色权限关联表 | 100-500 |
| 6 | DataScopePolicy | 数据范围策略表 | 10-100 |
| 7 | UserDataScope | 用户数据范围表 | 10-200 |
| 8 | RoleDataScope | 角色数据范围表 | 10-50 |
| 9 | AuditLog | 审计日志表 | 10K-1M |
| 10 | ApprovalFlow | 审批流表 | 100-10K |
| 11 | ApprovalNode | 审批节点表 | 200-30K |
| 12 | ApprovalRecord | 审批记录表 | 200-30K |
| 13 | ApprovalRule | 审批规则表 | 10-100 |

### 3.2 预置数据

**预置角色**（7个）：
- `aps.admin.system`：系统管理员
- `aps.admin.aps`：APS 管理员
- `aps.planner`：计划员
- `aps.supervisor.workshop`：车间主管
- `aps.coordinator.material`：物料协同人员
- `aps.viewer.management`：管理层查看
- `aps.service.api`：系统接口账号

**预置权限**（23个核心权限）：
- 计划模块：3个（view, run, publish）
- 任务模块：4个（view, adjust, freeze.override, started.override）
- CTP模块：3个（view, evaluate, commit）
- 配置模块：6个（supply_context, inventory_rule, resource 各2个）
- 审批模块：2个（view, approve）
- 审计模块：1个（view）
- 用户管理：4个（user, role 各2个）

**预置用户**：
- 默认管理员：`admin`（密码需立即修改）

### 3.3 APS_Production 库的表结构调整

**PlanVersion 表新增字段**：
- `CreatedByUserId INT NULL`：发起排程的用户ID
- `CreatedByUserName NVARCHAR(100) NULL`：发起排程的用户名（冗余）

**MES_API_BOM_Request 表新增字段**：
- `TriggeredByUserId INT NULL`：触发批次的用户ID
- `TriggeredByUserName NVARCHAR(100) NULL`：触发批次的用户名（冗余）

## 🚫 五、架构红线更新

### 5.1 新增红线（.windsurf/rules.md v2.3）

**红线13：权限校验双重防护**
- 接口层：使用 `[ApsAuthorize]` 特性声明式鉴权
- 应用层：使用 `IDataScopeService` 校验数据范围
- 严禁只在前端做权限控制
- 权限校验失败必须记录审计日志

**红线14：审计日志必须记录关键动作**
- 必须记录的动作：排程、任务调整、插单评估、配置修改、审批、用户管理
- 审计日志必须关联 UserId、PlanVersionId、BatchNo
- 审计日志只增不改不删

**红线15：高风险动作必须走审批流**
- 必须走审批流：冻结区任务变更、牺牲 SO、已开工任务变更
- 审批流必须支持多级审批
- 严禁绕过审批流直接执行高风险动作

**红线16：数据范围必须严格校验**
- 所有查询和修改操作必须校验数据范围
- 数据范围包括：工厂、产品族、资源组
- 严禁跨数据范围访问或修改数据

**红线17：权限数据库独立部署**
- 权限相关表必须部署在独立的 APS_Auth 数据库
- 严禁将权限表与业务表混在同一个库
- APS_Production 库通过跨库查询访问 APS_Auth 库

## ✅ 七、验收标准

### 7.1 功能验收

**阶段一验收标准**：
- [ ] 用户可以登录/登出
- [ ] 用户可以根据角色访问不同的功能
- [ ] 用户只能访问自己数据范围内的数据
- [ ] 所有关键操作都记录了审计日志
- [ ] 前端路由守卫生效
- [ ] 前端按钮级权限控制生效

**阶段二验收标准**：
- [ ] 冻结区任务变更需要审批
- [ ] 牺牲 SO 需要审批
- [ ] 审批流支持多级审批
- [ ] 审批通过后才能执行业务操作
- [ ] 审批拒绝后业务操作被阻止
- [ ] 前端审批管理页面可以查看和处理审批

**阶段三验收标准**：
- [ ] 已开工任务变更需要审批
- [ ] 审批超时策略生效（可选）

### 7.2 性能验收

- [ ] 权限校验响应时间 < 50ms
- [ ] 数据范围校验响应时间 < 100ms
- [ ] 审计日志写入不阻塞业务操作
- [ ] 审批流查询响应时间 < 200ms

### 7.3 安全验收

- [ ] 密码使用 BCrypt 加密存储
- [ ] JWT Token 过期时间为 2小时
- [ ] 所有接口都有权限校验
- [ ] 所有数据访问都有数据范围校验
- [ ] 审计日志不可修改、不可删除
- [ ] 敏感数据不记录到审计日志

### 9.2 关键注意事项

1. **严禁只在前端做权限控制**：前端权限控制只是 UI 优化，后端必须校验
2. **严禁跨数据范围访问数据**：所有查询和修改都必须校验数据范围
3. **严禁绕过审批流执行高风险动作**：审批流必须与业务操作原子性绑定
4. **审计日志只增不改不删**：审计日志是合规要求，不可篡改
5. **权限数据库独立部署**：APS_Auth 库与 APS_Production 库分离
