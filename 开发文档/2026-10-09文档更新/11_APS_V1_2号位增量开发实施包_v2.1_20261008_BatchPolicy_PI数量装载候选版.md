## 本轮统一执行红线（Q1～Q4）

1. **真实RouteCode / PathId**：凡属业务真值、持久化、接口追溯、FinalTask、Task、MES执行身份的`RouteCode / PathId`必须保存真实值；`DEFAULT / 1`不得作为归一化后的业务真值。`NormalizeToSingleRoute`如存在，仅允许作为1号位内部技术适配，且必须能够恢复真实Route/Path。
2. **MES工单创建作用域**：A桶继续原MES工单；B桶FinalTask后由2号位生成新TaskNo并绑定原MES工单，不创建第二MES工单；只有C桶在FinalTask后创建新MES工单，并保存实际RouteCode/PathId/Operation身份。
3. **ContinuationKey作用域**：一个ScheduleRun内，一个MESWorkOrderNo一个且仅一个ContinuationKey；同一MES工单多个Slice共享同一Key；不得把LogicalDemandKey拼入Key造成同一MES工单裂分；不新增Continuation永久状态平台。
4. **PreferredResource软偏好**：5号位保留Operation级`LastReportResourceCode`真实事实；2号位关联当前Continuation Slice并校验当前Operation Eligibility，合法可靠时形成`PreferredResourceCode`，否则为NULL；1号位对非空值必须作为资源连续性软偏好消费，但不得升级为Hard Lock，不得突破Eligibility、Calendar、Firm/Frozen、Material、Routing等硬约束。


## 2号位本轮主链

### 批量三类参数与Stage执行批约束（本次正式候选）

1. 当前有效且拟发布/启用的`TaskSplitRuleConfig`按`MaterialId + ProductionDepartmentId`精确定位。`PreferredBatchQty`业务生效必填且`>0`，处于已配置硬Min/Max合法范围内；它是车间业务软偏好，不等于最终必须切成此数量。存量`ProductionDepartmentId INT NULL`、`PreferredBatchQty DECIMAL(18,4) NULL`物理列保持兼容，不以直接SQL `NOT NULL`替代3号位后端发布校验。无匹配不等于“存在但生效校验失败”，后者不得走缺配兜底；NULL部门历史记录不默认为所有部门的生效规则。
2. `MaxOptimizationSplitCount`和`MaxBatchCandidates`不再作为`Material+Department`普通Batch Policy业务配置或旧列预算真相；前者是优化拆分尝试的技术预算，后者是单个问题的候选方案评估预算，均由1号位确定精确计数范围、边界和压测默认。3号位仅在现成、确有真实值载体的参数版本体系中治理，2号位在Run开始时装载冻结求解上下文；无现成动态载体可先使用1号位**有界、可追溯的版本化安全默认**，不能假设`ParameterSetVersion`自带参数明细，不能把历史`3/8`写死为通用业务上限，更不能让预算限制硬Max强制拆批。
3. `BottleneckSplitStrategy`、`NonBottleneckStrategy`是历史兼容列，V1主链无论NULL或非NULL均不得消费其拆/合批倾向；既有动态瓶颈和Anchor策略不被覆盖。硬约束→Demand Protection及优先需求→客户承诺确保率→延期/WIP/Setup/利用率/稳定性等次级优化的目标顺序不变。
4. 1号位对**C桶**只在**Stage Execution Batch**层级作最终拆/合批，一批可有N个Operation级Task并共享执行批身份；各Operation的实际剩余/预计加工量可因报工、良率等不同。**A/B**既有执行批与真实执行身份不参与普通优化拆合批；2号位只在FinalTask后归组TaskNo并进行MES身份闭环，不预拆最终Task。

### 明确MTS PI来源时的运行时数量硬上限与缺配兜底

- 必须能**唯一、合法、可追溯地关联**同一MTS PI、Stage和当前Run的C桶合法自由份额；不能仅凭MaterialCode相同猜PI归属。`PI OriginalQty`（ERP原始生产指示数量逻辑名）、`PI RemainingQty`（ERP当前剩余总量）与`StageFreeEligibleQty`（PI Position/NextOperationContext、A/B已执行、Q→A/B/C及已被新增批占用事实限定的当前Stage自由可新成批量）是**不同数量边界**，沿用现有ERP/MES字段映射，不据逻辑名新建物理列/DTO/表。ERP PI RemainingQty仍为总剩余，PI Position只是内部位置分布，不可再扣一次在制/XC/在途或把Position另建Supply。
- **单个新增Stage执行批的运行时上限**为所有适用量的最小值：`min(已匹配规则MaxExecutionBatchQty（非NULL才参与）, PI OriginalQty, PI RemainingQty, 当前PI/Stage尚未被占用的StageFreeEligibleQty)`。同PI同Stage多个新增批总量不能超过可新成批自由量；**同一个执行批的多个Operation Task不能重复扣量，不同Stage同批流转也不跨Stage重复加总**。PI数量、Q与预计加工量按已冻结的同口径/良率关系比较，绝不把运行时上限回写物料级Max或因ERP PI总量大而扩大本轮Q。
- **完全没有命中有效Batch Policy**且有唯一可靠MTS PI/Stage归属的C桶，取本次合法自由份额`Q_C`为仅本Run的一次性最小成批目标，取上述PI Original/Remaining/Stage自由量最小值为临时上限。`0 < Q_C ≤ 上限`且既有硬约束可满足时，**优先生成一个大小为Q_C的保守Stage执行批候选**，不启动缺配时的经济优化拆合批，不建永久Min/Max/Preferred。缺配需可追溯并进入已有待维护/问题机制，不自动套其他部门、旧MOQ/EOQ或NULL部门历史配置。
- 若`Q_C`超合法Stage自由量、来源不唯一、UNLOCATED、位置不可信、或配置Min高于运行上限，则**不伪造可行、不断言满足、不改小Q冒充全部满足**，沿用现有未满足/不可行/Issue/MES资格框架；不能自行发明新枚举、字段或“一律缺配置不得下发”的新红线。**没有明确MTS PI来源的其它C桶不适用这一兜底**。

**2号位具体装载/落库验证**：有效Batch Policy按MaterialId+ProductionDepartmentId和启用/有效期/版本唯一匹配，拟生效缺Preferred须保持“规则存在但无效”状态，禁止走完全无命中兜底。关联现有ERP PI原始量、剩余量、5号位PI Position/NextOperationContext、同Stage A/B占用及本Run已形成C桶批的余额，形成当前Stage合法可新增数量的**可审计同口径事实**，一次性传给Solver或让其从现有Contract无歧义构造；不能新建事实源或用相同Material猜PI。FinalTask归组后按同PI同Stage核验多批新增总量与Q，不按Operation重复扣减；无命中缺配进入现有问题/待补清单。技术输入缺口只记录待审，不自设新DTO。


1. 完成当前LogicalProductionDemand Q数量真相后，再消费5号位ExistingExecution事实识别A/B/C。
2. 一个ScheduleRun内按MESWorkOrderNo生成一个ContinuationKey；同WO多Slice共享Key，不拼接LogicalDemandKey。
3. 对每个Continuation Slice关联5号位Operation级LastReportResourceCode并校验当前Operation Eligibility；合法可靠时赋`PreferredResourceCode`，否则NULL。
4. A：继承旧TaskNo、原MES工单、真实Route/Path；B：Solver前TaskNo=NULL，FinalTask后生成一个新TaskNo并绑定原MES工单；C：Solver后按ExecutionBatchDraftKey生成TaskNo并创建新MES工单。
5. A/B向1号位发送固定Route/Path；C发送全部合法`RoutingCandidates[]`；禁止预先压成DEFAULT/1。
6. FinalTask持久化Operation级Task，保存真实ProductionDepartment/Stage/Route/Path/Operation，并建立TaskNo↔MESWorkOrder可追溯关系。
7. Material进入Pegging前完成标准化：出口库/最终可销售层级使用既有裁决形成`FINAL_ + 原标准MaterialCode`，普通物料保持原MaterialCode；FINAL不是MaterialType。2号位只消费5号位/防腐层已标准化Material身份。Routing Operation / Dependency / Eligibility装载必须以ODS显式携带的**标准化MaterialCode**进入`MaterialMapping → MaterialId`链；`MES_ID / Model`仅保留源追溯与一致性校验，不得再作为无法区分普通/FINAL层级的唯一Material绑定依据。MaterialMapping继续保留SourceID+Warehouse/Location源追溯；不得从Routing反推FINAL，也不得把一般Warehouse差异全部拆成新Material。
8. 2号位拥有APS运行结果数据库写入；不接管5号位ODS事实、不接管3号位Auth/规则治理、不让1号位直接碰数据库。
