## 四、3号位 域内单域走查执行步骤（建议顺序）

1. **前置治理核查**（G1，P0）：确认目标单域（如 FAMILY_VALVE）存在启用 Domain（DomainKey/ScopeType/ProductFamilyId 正确），且其默认 SPV→RSV/PSV 的 `ContentSnapshotJson` 六块全部非空真值；10-10 补数占位（664 RSV/663 PSV 快照 NULL）须先治理，否则走查 Run 必 ComputeFailed。
2. **Scope 组合唯一**（G2）：走查前确认无同 scope 组合重复启用域（`ExistsActiveScopeComboAsync` 判重已落码）。
3. **BatchPolicy 发布校验**（G3）：走查前执行 `GetActiveRulesForSnapshotAsync` 发布资格预检（存量非法行/窗口重叠均阻断——CANDIDATE-P0-01 + R02），确认第⑧块可注入。
4. **Candidate/Run 创建三要件**（G4）：走查候选 Run 创建时 StrategyProfileVersionId 同步写入、DataCutoffTime NOT NULL、ScopeJson Schema v2、ExpectedDomainKeysJson 恰 1。
5. **触发并走查闭环**：由 2号位 主流程执行（RunSchedulingAndFinalizeAsync）→ 走查 09 §四主链 + 数量/资源/时间/状态闭合（该步归 2号位 主导，3号位 提供治理真值）。

## 五、结论

3号位 域内 G5 预检清单**已建立**：覆盖 04 §十三 6 项（3号位 承担 1/2/4/6 项，3/5 项归他号位）、09 总体验收 8 项（承担 ④⑤⑧）、12 §十 7 项（全 7 项有 3号位 落点），逐项注明依据节号与代码落点。
**前提缺口仍为 G1（P0）**：目标域无真值策略包 + 占位 SPV 批量存在，须先治理后走查。
其余号位验收点（有限产能/解释链/人工资源等）归 1/2/5/4号位 各自实施包，不在本文档范围。
