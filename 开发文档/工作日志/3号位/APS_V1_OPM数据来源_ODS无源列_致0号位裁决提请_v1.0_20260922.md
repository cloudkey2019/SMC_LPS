## 〇、背景事实

1. **0号位 既有裁决**：OPM 属 `RoutingOperation` 工艺数据（三态、NVARCHAR(32) DEFAULT+CHECK），**3号位 维护**，不新增表（五.1/五.2）；配品分类=**业务拍板**、3号位 维护入口（R8）。
2. **已登记待办（S1 源数据前置）**：《三项待办收口登记》§四 登记两项：
   - ① ODS 契约视图 `ext_MES_APS_Routing_Operation_View` **透出 OperationPlanningMode 列**（3号位 登记契约 + 2号位 执行，红线 #6）；
   - ② `sp_SyncRoutingData` **补 SELECT/MERGE OperationPlanningMode**（2号位）。
3. **新事实（2026-09-22 更正）**：核实 **ODS/MES 源侧根本没有 `OperationPlanningMode` 列**——
   - 视图只能 SELECT 源表已存在的列 → 源无此列，视图**无法透出**；
   - 存储过程从视图取值 MERGE → 视图无此列，**无值可 MERGE**；
   - 故待办 ① ② **不成立、无法执行**。
4. **定性（0号位 确认）**：OPM 属 **APS 内部工艺规划属性（治理配置）**，非 ERP/MES 事实数据 → 源侧天然无此列，**非"待补"缺口**，不应为同步链路完整而强行扩展 MES/ODS。
5. **Q4 拆出说明**：M5 详设终裁（`InScopeLogicalDemandKeys` / `PriorityMode=EXPEDITE`）经 0号位 指明属**另一条独立链路**，不混入 OPM 裁决——本件不再含 M5；按 1号位 已另发《M5详设与日历表维度确认 致0号位》单独看（0号位 2026-09-23）。

## 三、字段三来源原则 + 判断流程（0号位 裁决 七，落档）

> 与之前 Resource Calendar 问题类似——**不要出现「字段存在于 APS 数据库，所以认为应该来自 ODS」**；**不能再默认「所有 Routing 相关字段都应该来自 MES」**。

**判断流程（0号位 裁决 七）**：看到字段在 ODS / MES / 接口均无 → **先判断该字段属于哪一类**：

| 类型 | 处理 |
|---|---|
| 外部事实 | **补 ODS/接口** |
| APS 计算事实 | **APS 产生** |
| APS 治理属性 | **APS 维护** |

> **OPM 属第三类（APS 治理属性）→ APS 维护**（3号位 治理侧直维护），不是 ODS 事实。
