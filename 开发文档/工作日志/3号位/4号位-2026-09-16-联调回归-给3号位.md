## 二、🔴 P0 回归 — `POST /api/rbac/roles` + `POST /api/rbac/permissions` 当前 400

**实测响应**（admin token 直接调）：
```
POST /api/rbac/roles
{"code":400,"message":"Record type 'LPS.APS.Core.Dto.CreateRoleRequest' has validation
metadata defined on property 'RoleCode' that will be ignored. 'RoleCode' is a parameter
in the record primary constructor and validation metadata must be associated with the
constructor parameter.","data":{"exception":"InvalidOperationException",...}}
```

**根因**（[RbacManagementDtos.cs:73-77](lps/LPS.APS.Core/Dto/RbacManagementDtos.cs) + [86-92](lps/LPS.APS.Core/Dto/RbacManagementDtos.cs)）：

3号位 在落实 §八.②「`aps.` 前缀 CHECK」时，把 `[RegularExpression("^aps\\..+")]` 写成了 `[property: RegularExpression(...)]`。但 ASP.NET Core 的 record 模型校验**只读构造函数参数上的 attribute**（`param:` 是 record 默认 target），**自动生成的 property 上的 attribute 会被 ModelMetadata 检测到后拒绝**——所以整个 POST 端点直接抛 `InvalidOperationException`，**不是返回 422 校验失败，是 500 级别的元数据配置错误**。

**对比**：旁边的 `CreateUserRequest`（L58-63）没有用 `[property:]`，所以 `POST /api/rbac/users` 工作正常（实测 `code=200 newId=41`）。

**影响范围**：
- `POST /api/rbac/roles` → 任何 roleCode 都 400（甚至 `aps.admin.system` 也无法新建/恢复）
- `POST /api/rbac/permissions` → 同上
- 直接后果：**前端 RbacRoles.vue「新建角色」+ RbacPermissions.vue「新建权限码」按钮永远调不通**

---

## 三、建议修复（最小改动）

把 `[property: RegularExpression(...)]` 改成 bare attribute（默认 target = `param:`，落在构造函数参数上，ASP.NET 才会读）：

```csharp
// 当前（错误，落在自动生成 property 上）
public sealed record CreateRoleRequest(
    [property: System.ComponentModel.DataAnnotations.RegularExpression("^aps\\..+", ErrorMessage = "...")]
    string RoleCode,
    string RoleName,
    string? Description = null);

// 改为（正确，落在构造函数参数上）
public sealed record CreateRoleRequest(
    [System.ComponentModel.DataAnnotations.RegularExpression("^aps\\..+", ErrorMessage = "角色编码必须以 aps. 前缀开头")]
    string RoleCode,
    string RoleName,
    string? Description = null);
```

`CreatePermissionRequest`（L86）同样改法。

**预期效果**：
- `POST /api/rbac/roles` body=`{"roleCode":"aps.verify.role.xxxx"}` → 200 + newId
- `POST /api/rbac/roles` body=`{"roleCode":"verify-no-prefix"}` → 422 + `message="角色编码必须以 aps. 前缀开头"`（这才符合 §八.②「前端 → 422 / 后端 → 422」设计）
