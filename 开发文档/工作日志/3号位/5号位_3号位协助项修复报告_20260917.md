## 三、A类修复详情（Moq 代理失败，12个）

### 3.1 根因分析

`DatabaseConnectionManager` 存在两层 mock 障碍：

| 层次 | 问题 | 错误信息 |
|------|------|----------|
| 构造层 | 仅有 `DatabaseConnectionManager(IOptions<DatabaseOptions>)` 构造 | `Could not find a parameterless constructor` |
| 方法层 | `QueryAsync<T>` 非 `virtual` | `Non-overridable members may not be used in setup` |

### 3.2 修复方案

**构造层**：在测试项目内创建 `TestableDatabaseConnectionManager` 子类，内含无参构造（自动传入合法 `IOptions<DatabaseOptions>`）：

```csharp
// LPS.APS.BusinessRules.Tests/Helpers/TestableDatabaseConnectionManager.cs
public class TestableDatabaseConnectionManager : DatabaseConnectionManager
{
    private static readonly IOptions<DatabaseOptions> DefaultTestOptions = Options.Create(new DatabaseOptions
    {
        APS = new DatabaseConnectionOptions { ConnectionString = "Server=test;Database=APS_Test;Trusted_Connection=true;" },
        ODS = new DatabaseConnectionOptions { ConnectionString = "Server=test;Database=ODS_Test;Trusted_Connection=true;" },
        Auth = new DatabaseConnectionOptions { ConnectionString = "Server=test;Database=Auth_Test;Trusted_Connection=true;" }
    });

    public TestableDatabaseConnectionManager() : base(DefaultTestOptions) { }
}
```

**方法层**：在 `DatabaseConnectionManager.QueryAsync<T>()` 添加 `virtual` 关键字（⚠️ 跨边界，需告知2号位）。

测试中改用 `Mock<TestableDatabaseConnectionManager>`：

```csharp
_mockConnectionManager = new Mock<TestableDatabaseConnectionManager>();
_loader = new TimedSupplyFactLoader(_mockConnectionManager.Object);
```

## 四、B类修复详情（断言漂移，6个）

### 4.1 F07_StrongFactCorrection — 测试数据缺陷

**根因**：`ReceivedFact` 缺少 `DocumentType` 字段，触发计算器 `RECEIVED_MISSING_DOCUMENT_TYPE` 拒绝规则，StrongFact 未被应用，Stage 数量未被扣减。

| 修复前 | 修复后 |
|--------|--------|
| `DocumentNo = "RECEIVED-001"`（无 DocumentType） | `DocumentNo = "PI-F07-001", DocumentType = "PI"` |
| S10 保持 40m（未被扣减） | S10 = 40 - 30 = **10m** ✅ |

### 4.2 F05_TransitIndependent — Transit 去重逻辑已实现，断言未同步

**根因**：计算器已实现 Transit 从 Stage 扣除的去重逻辑（`DeduplicatePositions`），但测试仍期望 Transit 与 Stage 独立共存。

| 项目 | 旧期望 | 新实际 | 说明 |
|------|--------|--------|------|
| Stage | 60m | **35m**（60 - 25） | Transit 25 从 Stage 扣除 |
| Transit | 25m | 25m | 不变 |
| UNLOCATED | 15m | **40m**（100 - 35 - 25） | 总量闭合 |

### 4.3 F09-F12 — 跨厂订单链场景，不属 PI Position Calculator 职责

**根因**：测试代码中已有 P0-11 警告注释明确说明 F09-F12 属于 `INTER_FACTORY_ORDER`（跨厂订单链），不属 PI Position Calculator 职责。计算器的行为是正确的：

- **Transit 去重 Stage**（`DeduplicatePositions`）：Transit 作为强事实优先，从 Stage 扣除
- **SH Received 拒绝**（`ApplyStrongFacts`）：`DocumentType = "SH"` 触发 `RECEIVED_SHIPPING_IN_PI_POSITION`，StrongFact 被拒绝并生成 Issue

| 用例 | 旧断言 | 新断言 | 说明 |
|------|--------|--------|------|
| **F09** | `stagePosition != null, qty=50` | `stagePosition == null, UNLOCATED=50` | Transit(50)=Stage(50)，Stage 被完全扣除 |
| **F10** | `transitPosition=30m, UNLOCATED=70m` | `transitPosition=60m, UNLOCATED=40m` | SH 被拒绝，Transit 不扣减；Stage(30) 被 Transit(60) 覆盖 |
| **F11** | `transitPosition=60m` | `transitPositions.Count=2, Sum=100m` | SH 被拒绝，两笔 Transit 完整保留 |
| **F12** | `transitPosition==null` | `transitPosition=50m, UNLOCATED=50m` | SH 被拒绝，Transit(50) 完整保留 |

所有 F10-F12 断言增加 `RECEIVED_SHIPPING_IN_PI_POSITION` Issue 验证。

## 六、跨边界改动通知（致2号位）

### 6.1 DatabaseConnectionManager.QueryAsync<T> 添加 virtual

**文件**：`LPS.APS.Engine/Data/DatabaseConnectionManager.cs`
**改动**：第 145 行 `public async Task<IEnumerable<T>> QueryAsync<T>(...)` → `public virtual async Task<IEnumerable<T>> QueryAsync<T>(...)`
**原因**：Moq 通过 Castle DynamicProxy 只能拦截 `virtual`/`abstract` 方法；测试需 mock `QueryAsync` 来隔离数据库
**影响**：零运行时影响（仅改变方法的可覆写性，不改变任何执行逻辑）

### 6.2 建议后续优化

建议2号位考虑抽取 `IDatabaseConnectionManager` 接口，从根本上解决 mock 友好性问题：

```csharp
public interface IDatabaseConnectionManager
{
    Task<IEnumerable<T>> QueryAsync<T>(string sql, object? parameters = null, ...);
    Task<T?> QueryFirstOrDefaultAsync<T>(string sql, object? parameters = null, ...);
    Task<int> ExecuteAsync(string sql, object? parameters = null, ...);
    // ...
}
```

这样测试可直接 `Mock<IDatabaseConnectionManager>()`，无需子类化。
