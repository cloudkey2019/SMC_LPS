## 一、[P1] Login / Logout 不写审计日志（§22.6 覆盖缺口，U42 验收口径）

**现状（09-20 代码走读）**：`AuthService` / `AuthController` 全链路**无任何 AuditLog 写入点**。dev 库去重后实际 actionCode 仅 13 个：

```
Create / Update / Delete / Enable / Disable / Publish /
AssignRoles / AssignPermissions / AssignScopes /
ConfirmCandidate / ActivateCandidate / CreateCandidateRun / RecoverFailedRun
```

**冲突**：冻结文档 §22.6 明确要求审计查询覆盖 Login / Logout；U42「关键动作可追溯」验收口径下登录动作不可追溯 = 验收缺口。**该写入点在后端，4 号位 无法自行补齐。**

**请求 3 号位**：确认是否补 Login / Logout 审计写入点；如补，建议字段映射（供参考，以 3 号位 设计为准）：

| 字段 | 建议值 |
|---|---|
| actionCode | `Login` / `Logout` |
| module | `Auth` |
| entityType / entityId | `User` / userCode |
| result | Success / Failed（密码错、账号停用等失败也要记，errorMessage 写原因） |
| clientIp / userAgent | 已有现成字段，直接填 |

**⚠️ 红线（U42 脱敏）**：补写入点时**严禁**把 password / token 序列化进 requestData（§22.6 末行：不得整对象序列化含密 DTO）。登录失败审计只记原因类别，不记密码原文。

**4 号位 配合**：写入点落地后，前端仅需 `frontNew/src/api/aps-v1/types/audit.ts` `AUDIT_ACTION_CODES` 追加 2 枚举 + 筛选下拉自动多出 2 项（≈0.1 人天），Audit.vue 页面零返工。

**期望答复**：09-25 合入节点前给「补 / 不补 + 排期」结论；不补则提请 0 号位 裁定 U42 验收口径。

## 三、[P2 可选] audit-logs 端点两项增强（不阻塞，前端可随时适配）

1. **`result` 过滤参数**：现端点仅 userId / action / from / to 4 个过滤参数。前端因此**只做 Result 列展示、不做 Result 筛选**（避免客户端假过滤误导用户）。如后端补 `result` 参数，前端加一个下拉即可。

**请求 3 号位**：评估排期，书面结论即可、不限期；落地前前端维持现状（hasMore 分页已在页面注明「后端按发生时间倒序返回，不提供总数」）。
