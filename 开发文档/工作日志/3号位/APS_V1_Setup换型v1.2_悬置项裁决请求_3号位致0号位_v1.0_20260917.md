## 一、裁决项 1：Setup 三项算法预算参数的冻结值（核心）

**问题**：§8.2 要求进 `ParameterSetVersion` 的三参数——`有界搜索预算` / `最大邻域尝试次数` / `单生产日保护阈值`——**只给了名称，没有数值**（已核全 `开发文档/`，历史文档均无这三个数）。

**可依的旧锚**（唯一历史数值，均属旧模型、不能直接换名复用）：
- `SetupLookAheadSize = 5`（旧固定 look-ahead，将被「有界搜索」取代）
- 1号位 `SetupOptimizer` default = 30min（全局默认，v1.2 已禁）

**草案默认值（供校准，非冻结）**：

| 参数 | 草案默认值 | 说明 |
|---|---|---|
| 有界搜索预算 | 500 | 单 `Resource × 生产日 × 可移动段` 的评分/尝试次数上限 |
| 最大邻域尝试次数 | 50 | 单轮 swap / insertion / block-move 的尝试上限 |
| 单生产日保护阈值 | **待明确** | 语义与数值均未定义（§8.2 仅列名） |

## 二、裁决项 2：Setup 规则在 `FrozenStrategySnapshot` 的承载方式（§六.1）

**问题**：现行 `SolverStrategyBlock.Setup` 三字段已全失义；Setup 规则按 §8.2 归 RuleSetVersion、算法数值归 ParameterSetVersion。那 Snapshot 怎么承载？

- **方案 A（建议）**：Snapshot 不新增块；Setup 规则随 `RuleSetVersionId` 锚由 2号位 装载（与 C2-1「Run 绑版本、不再漂移」一致）。
- **方案 B**：Snapshot 新增块（如 `SetupTransitionBlock`）直接携本 Run EXACT/DEFAULT 规则清单，2号位 快照即用、不二次查库。
- **方案 C**：Snapshot 只加「Setup 优化开关 + 预算」参数，规则仍按版本装载。

**请 0号位**：定 A/B/C。
