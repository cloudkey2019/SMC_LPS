# 〇、公共约定（4号位必读）

## 0.1 响应包络（两套并存，逐一标注）

| 控制器 | 成功 | 失败 | 说明 |
|---|---|---|---|
| `GovernanceController` | `{ success:true, data, message? }` | `{ success:false, error:"..." }`（400/404） | 创建返回 201 |
| `GovernanceController` 的 **diff / validate 端点** | **裸 DTO**（无包络，直接 `Ok(dto)`） | `{ success:false, error:"..." }`（400/404） | ⚠ 与其它 Governance 端点不同，4号位须特判 |
| `ScheduleController` | `ApiResponse<T>`：`{ success, data, error:null, meta }` | `{ success:false, error, data:null, meta }` | 统一走 Shared.ApiResponse |

> 联调建议：3号位后续**新增接口一律走 `ApiResponse<T>`**；既有接口本轮不改造，以本表为准。

## 0.2 通用错误格式

- `400`：`{ "success": false, "error": "<中文可读错误消息>" }`
- `404`：`{ "success": false, "error": "<实体不存在消息>" }`
- 错误消息即 `InvalidOperationException.Message`，4号位可直接展示。

## 0.3 版本状态机（三张版本表共用，`GovernanceVersionStatus`）

`DRAFT → SUBMITTED → APPROVED → PUBLISHED`，另有 `DISABLED / ARCHIVED`。
- 新建强制 `DRAFT`（入参 Status 一律被忽略覆盖）；
- 仅 `DRAFT/SUBMITTED/APPROVED` 可编辑、可发布；
- `PUBLISHED` 不可原地修改（须建新版本）、不可再发布（历史不可覆盖 R01）；
- `DISABLED/ARCHIVED` 不可编辑、不可发布；被停用版本不可被新 Run 引用（Snapshot 装载仅放行 PUBLISHED）；
- V1 页面只消费：新建 DRAFT、编辑 DRAFT、发布 PUBLISHED、停用 DISABLED（**停用端点待补，见 §五 G2**）。

## 0.4 内容载体（P0-01 方案 A，契约 §6.10.5）

六块配置内容统一持久化到 `ContentSnapshotJson`；**GET 详情已投影回主题 JSON 字段**（`DemandPriorityJson` / `LockJson` / `SupplyJson` / `ProcurementJson` / `SolverStrategyJson` / `CandidateGuardrailJson`），前端读写这些字段即可，不感知快照内部结构。JSON 块结构见 §三。

### A4. 创建规则集版本　✅

| 项 | 规格 |
|---|---|
| 方法+URL | `POST /api/Governance/rule-set/version` |
| 用途 | 新建 DRAFT（含"复制当前版本为新 DRAFT"场景） |
| 入参-Body | `RuleSetVersion`：`RuleSetId`(long, 必填>0)、`VersionCode`(string, 必填)、`DemandPriorityJson`(string, 必填, §三-①结构)、`EffectiveFrom/EffectiveTo`(datetime?, 可选)、`Remarks`(string?, 可选)、`CreatedBy`(string, 建议必传=登录用户，服务用作创建人) |
| 服务端强制 | `Status=DRAFT`、`CreatedAt=now`、`PublishedAt/PublishedBy/ApprovedAt/ApprovedBy=null`（入参 Status 一律忽略） |
| 出参-201 | `data: RuleSetVersion`（含新 Id） |
| 校验规则 | RuleSetId>0；VersionCode 非空；DemandPriorityJson 可反序列化为 §三-①（不可则异常拒绝）；EffectiveFrom<EffectiveTo（若均传） |
| 详细需求 | **必须产生新记录，绝不覆盖任何历史**（R01）；前端"复制当前版本"=取 A3 详情内容+新 VersionCode 调本接口；JSON 合法性与业务约束在发布前 A6/E1 validate 兜底 |

### A5. 更新规则集版本　✅

| 项 | 规格 |
|---|---|
| 方法+URL | `PUT /api/Governance/rule-set/version/{versionId}` |
| 用途 | 编辑 DRAFT 内容（Segment 配置保存） |
| 入参-Path | `versionId`(long, 必填>0) |
| 入参-Body | `RuleSetVersion`：可编辑字段=VersionCode、DemandPriorityJson、EffectiveFrom/To、Remarks |
| 服务端强制 | `Id/RuleSetId/Status/CreatedAt/CreatedBy/PublishedAt/PublishedBy/ApprovedAt/ApprovedBy` 以现有记录为准（前端传了也覆盖为现有值，禁止越权改状态） |
| 出参-200 | `{ success:true, data: <入参对象> }`（⚠ 返回入参原文，非服务端规范化后对象；如需最新值请重新 GET A3） |
| 出参-400 | `{ success:false, error }`（状态机拒绝等） |
| 校验规则 | 版本存在（缺→400"规则集版本不存在"）；**状态机**：PUBLISHED→400"已发布，不可原地修改（历史不可变，须创建新版本）"；DISABLED/ARCHIVED→400"版本状态不可修改"；仅 DRAFT/SUBMITTED/APPROVED 可编辑；DemandPriorityJson 反序列化失败拒绝 |
| 详细需求 | 编辑按钮按 Status 置灰（PUBLISHED/DISABLED/ARCHIVED）；保存后历史版本不变 |

### A6. 发布规则集版本　✅

| 项 | 规格 |
|---|---|
| 方法+URL | `POST /api/Governance/rule-set/version/{versionId}/publish` |
| 用途 | 发布按钮（4号位流程：先调 E1 validate → IsValid=false 禁用发布 → true 才调本接口） |
| 入参-Path | `versionId`(long, 必填>0) |
| 入参-Body | `PublishRequest`：`PublishedBy`(string, 必填) |
| 出参-200 | `{ success:true, message:"规则集版本 {id} 已发布" }` |
| 出参-400 | `{ success:false, error }`（校验失败/状态不可发布） |
| 校验规则（服务端强制链，无绕过） | ① 版本存在；② 完整发布前校验（E1）：状态可发布、VersionCode 非空、EffectiveFrom<EffectiveTo、DemandPriorityJson 非空且 DemandPriorityValidator 通过；③ 状态机：PUBLISHED→400"历史不可覆盖"；DISABLED/ARCHIVED→400；④ 发布时聚合 `ContentSnapshotJson` |
| 详细需求 | 发布产生新 PUBLISHED 记录，旧版本记录不变（R02：新 Run 可引用新版本、旧 Run 引用不变）；发布写入审计日志（EntityType=RuleSetVersion，OperationType=Publish） |

- `EMPTY_PARAMETER`：五主题 JSON 任一缺失/空
- `INVALID_YIELD`：PlanningYield 越界（0 < YieldPercent ≤ 100）
- `INVALID_PURCHASE_LT`：DefaultLtDays ≤ 0
- `INVALID_OFFSET`：OffsetHours < 0
- `INVALID_OVERDUE_MARGIN`：MarginPercent ∉ 0~100 或 MinimumExtraDays < 0
- `INVALID_WAREHOUSE_PRIORITY`：Supply 或 Procurement 的 WarehousePriority 含重复 Warehouse（优先级歧义）
- `INVALID_LOCK_TRIGGER`：UseRemainingTimeThreshold=true 且 RemainingTimeThresholdHours ≤ 0
- `INVALID_SOLVER_STRATEGY` / `INVALID_CANDIDATE_GUARDRAIL` / `EMPTY_SOLVER_STRATEGY` / `EMPTY_CANDIDATE_GUARDRAIL`：Solver/Guardrail 块缺失、JSON 损坏或业务约束不满足（SolverStrategyValidator / CandidateGuardrailValidator，含 OnTimeTarget 0~100、Guardrail 全为正等）

## B. Demand Priority Segment 配置模型（联调项 4）

**承载**：A4/A5 的 `DemandPriorityJson`。结构见 §三-①。**红线**：无全局 PriorityScore（R06/U21）、第一命中（R04）、同 Segment 多 Sort 稳定（R05）。
**4号位 Segment 配置页**：编辑 Segments 列表（SegmentOrder/SegmentName/IsEnabled/MatchConditions/SortFields/StableTieBreakFields）→ 保存走 A5 → 发布前调 E1 validate（错误码 `INVALID_DEMAND_PRIORITY`）。
**校验规则（DemandPriorityValidator，E1 内）**：Field/Operator 必须在白名单（§三-①枚举）；MatchConditions 重复/冲突、SortFields 为空、StableTieBreak 非 SortFields 字段、SegmentOrder 重复等 → 拒绝发布。
**页面展示要求（U21）**：按 Segment 展示配置，**不展示任何全局 PriorityScore**。

# 三、JSON 块结构（4号位参数/Segment 页面编辑模型）

> 六块模型与 `FrozenStrategySnapshot` 一致（契约 §6.10.5）。字段名大小写不敏感（反序列化忽略大小写）。

## ① `DemandPriorityJson`（RuleSetVersion；联调项 4）
```jsonc
{
  "Segments": [
    {
      "SegmentOrder": 1,              // int，升序，第一命中即止；不可重复
      "SegmentName": "Delayed_SO",    // string，可解释名
      "IsEnabled": true,              // bool
      "MatchConditions": [            // AND；全部满足才命中
        { "Field": "DelayStatus", "Operator": "Equals", "Value": "Delayed" },
        { "Field": "OrderType", "Operator": "In", "Value": ["SO","WO"] }
      ],
      "SortFields": [                 // 命中后内部排序，依次生效
        { "Field": "DueDate", "Direction": "Asc" },
        { "Field": "CustomerTier", "Direction": "Desc" }
      ],
      "StableTieBreakFields": ["IssueDate"]
    }
  ]
}
```
- `Field` 白名单（`DemandField`）：`RemainingTimeHours / DelayStatus / CustomerTier / OrderType / IsPmcProtected / PriorityLevel / DueDate / IssueDate`
- `Operator`（`ConditionOperator`）：`Equals / NotEquals / LessThan / LessOrEqual / GreaterThan / GreaterOrEqual / In`（In 时 Value 为数组）
- `Direction`（`SortDirection`）：`Asc / Desc`

## ② `LockJson`（Demand Protection；联调项 5）
```jsonc
{
  "Trigger": {
    "UseRemainingTimeThreshold": false,   // RemainingTime < NormalLT 触发
    "RemainingTimeThresholdHours": 0,     // >0 当 Use=true（INVALID_LOCK_TRIGGER）
    "ProtectDelayed": true,               // DelayStatus=DELAYED 触发
    "ProtectVipTier": true,
    "VipTierValue": "VIP",
    "ProtectedOrderTypes": ["SO"],
    "AllowPmcManualProtection": true
  },
  "Sticky": {
    "RequireReleaseRecord": true,         // 手工释放须记录 Actor/Time/Reason
    "ProtectUntilCompletion": true,
    "ProtectUntilSupplyInvalid": true
  }
}
```

## ③ `SupplyJson`（联调项 6 前半）
```jsonc
{
  "Inventory": {
    "IsEnabled": true,
    "WarehousePriority": ["WH01","WH02"],   // 有序，隐含优先级，不可重复
    "RequireFactoryContext": false,
    "RequireProductFamilyContext": false
  },
  "PiSort": {
    "SortBy": "IssueDateAsc",               // IssueDateAsc / CreatedAtAsc / StablePiNoAsc
    "UseStablePiNoTieBreak": true
  }
}
```

## ④ `ProcurementJson`（联调项 6 后半；**0号位 8-28 裁决：无 Enable/Disable 开关，排序链为冻结 Invariant**）
```jsonc
{
  "WarehousePriority": ["WH01","WH02"],          // 采购排序链"Warehouse Priority"步
  "DefaultPurchaseLt": [                          // Warehouse + 必要 Material 维度
    { "WarehouseCode": "WH01", "MaterialId": null, "DefaultLtDays": 5 }   // 空=Warehouse 级默认
  ],
  "OverdueMargin": { "MarginPercent": 10, "MinimumExtraDays": 2 },        // 0~100 / >=0
  "ArrivalToUsableOffsets": [ { "WarehouseCode": "WH01", "OffsetHours": 8 } ],  // >=0
  "PlanningYields": [ { "MaterialId": "M001", "StageCode": null, "YieldPercent": 95 } ]  // 0<X<=100；红线：已有 PI Supply 不得按 Yield 放大
}
```
> ETA 优先级 `Manual ETA > ERP ETA > DefaultLT` 为冻结 Invariant，**不做成可配置规则**。

## ⑤ `SolverStrategyJson`（联调项 7）
```jsonc
{
  "Mode": "Mixed",                       // Forward / Backward / Mixed
  "BottleneckMode": "Auto",              // Auto / PreferAnchor / ForceAnchor / NotAnchor
  "OnTimeTarget": { "TargetPercent": 95, "IsPrimaryObjective": true },   // 0~100；业务目标不被 Setup/WIP/Utilization 反向压过
  "Split": { "MaxOptimizationSplitCount": 3, "LimitMandatorySplit": true, "MinBatchQty": 100 },
  "Setup": { "Dimensions": ["Mold","Tool"], "DefaultSetupMinutes": 30, "SetupLookAheadSize": 5 },

```
