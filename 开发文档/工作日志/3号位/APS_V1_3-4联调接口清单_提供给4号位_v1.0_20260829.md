## B. Demand Priority Segment 配置模型（联调项 4）

**承载**：`RuleSetVersion.DemandPriorityJson`（发布时归一化到 `ContentSnapshotJson.DemandPriority` 子块，GET 详情投影回 DemandPriorityJson——前端照常读写该字段即可）。
**红线**：无全局 PriorityScore（验收 R06/U21）；第一命中（验收 R04）；同 Segment 多 Sort 字段稳定（验收 R05）。

4号位 Segment 配置页编辑的 JSON 结构（强类型模型 `DemandPriorityBlock`）：

```jsonc
{
  "Segments": [
    {
      "SegmentOrder": 1,             // 升序，第一命中即止
      "SegmentName": "Delayed_SO",
      "IsEnabled": true,
      "MatchConditions": [           // AND 列表，全部满足命中；不建 DSL
        { "Field": "DelayStatus", "Operator": "Equals", "Value": "Delayed" },
        { "Field": "OrderType", "Operator": "Equals", "Value": "SO" }
      ],
      "SortFields": [                // 命中后内部排序，依次生效
        { "Field": "DueDate", "Direction": "Asc" },
        { "Field": "CustomerTier", "Direction": "Desc" }
      ],
      "StableTieBreakFields": ["IssueDate"]   // 并列最终稳定顺序
    }
  ]
}
```

**Field 枚举白名单**（`DemandField`）：`RemainingTimeHours / DelayStatus / CustomerTier / OrderType / IsPmcProtected / PriorityLevel / DueDate / IssueDate`
**Operator**：`Equals / NotEquals / LessThan / LessOrEqual / GreaterThan / GreaterOrEqual / In`
**SortDirection**：`Asc / Desc`
**校验**：发布前经 `GET /api/Governance/rule-set/version/{versionId}/validate`（DemandPriorityValidator：重复 Segment、非法 Field/Operator、循环引用等；错误码 `INVALID_DEMAND_PRIORITY`）。

## C. Demand Protection / Supply / Procurement / Solver Strategy 参数（联调项 5/6/7）

**承载**：`ParameterSetVersion` 五个主题 JSON，发布时归一化到 `ContentSnapshotJson` 五子块，GET 详情投影回五主题 JSON。4号位参数维护页分别编辑：

### ① `LockJson`（Demand Protection，联调项 5）
模型 `LockBlock` → `Trigger`（触发条件治理）+ `Sticky`（Sticky 语义）：
- `Trigger.UseRemainingTimeThreshold` / `RemainingTimeThresholdHours`（RemainingTime < NormalLT 触发）
- `Trigger.ProtectDelayed` / `ProtectVipTier`+`VipTierValue` / `ProtectedOrderTypes[]` / `AllowPmcManualProtection`
- `Sticky.RequireReleaseRecord`（手工释放须记录 Actor/Time/Reason）、`ProtectUntilCompletion`、`ProtectUntilSupplyInvalid`
- 校验：启用 RemainingTime 阈值时其值必须为正（`INVALID_LOCK_TRIGGER`）；最终 Lock 创建/扣减由 2号位执行，3号位只治理触发条件。

### ② `SupplyJson`（Inventory Availability + PI 排序，联调项 6 前半）
模型 `SupplyBlock` → `Inventory` + `PiSort`：
- `Inventory.IsEnabled` / `WarehousePriority[]`（有序列表，优先级隐含于顺序，重复报 `INVALID_WAREHOUSE_PRIORITY`）/ `RequireFactoryContext` / `RequireProductFamilyContext`
- `PiSort.SortBy`（`IssueDateAsc / CreatedAtAsc / StablePiNoAsc`）+ `UseStablePiNoTieBreak`

### ③ `ProcurementJson`（采购/良率参数，联调项 6 后半）
模型 `ProcurementBlock`（**0号位 2026-08-28 裁决后无 Enable/Disable 开关，排序链为冻结 Invariant，3号位只治理参数值**）：
- `WarehousePriority[]`（采购排序链 "Warehouse Priority" 步的仓库优先级）
- `DefaultPurchaseLt[]`：`{ WarehouseCode, MaterialId?, DefaultLtDays }`（Warehouse + 必要 Material 维度，不增加 ProductFamily；`INVALID_PURCHASE_LT` 要求 >0）
- `OverdueMargin`：`{ MarginPercent(0~100), MinimumExtraDays(>=0) }`
- `ArrivalToUsableOffsets[]`：`{ WarehouseCode, OffsetHours(>=0) }`（ArrivalTime → AvailableTime）
- `PlanningYields[]`：`{ MaterialId, StageCode?, YieldPercent(0~100] }`（红线：已有 PI Supply 不得按 Yield 放大）
- ETA 优先级 `Manual ETA > ERP ETA > DefaultLT` 为冻结 Invariant，**不做成可配置规则**（实施包十、0号位裁决 D）。

### ④ `SolverStrategyJson`（联调项 7）
模型 `SolverStrategyBlock`：
- `Mode`：`Forward / Backward / Mixed`（冻结 E1）
- `BottleneckMode`：`Auto / PreferAnchor / ForceAnchor / NotAnchor`
- `OnTimeTarget`：`{ TargetPercent(0~100), IsPrimaryObjective }`（业务优化目标，不被 Setup/WIP/Utilization 反向压过）
- `Split`：`{ MaxOptimizationSplitCount(如3), LimitMandatorySplit, MinBatchQty }`
- `Setup`：`{ Dimensions[]（Mold/Tool/Material/Color）, DefaultSetupMinutes, SetupLookAheadSize }`
- `StageOverlap`：`{ AllowOverlap, TransferBatchQty, ThresholdQty, ThresholdPercent }`

### ⑤ `CandidateGuardrailJson`（技术 Guardrail，联调项 7 附）
模型 `CandidateGuardrailBlock`：
- `NormalMs=60000 / SoftMs=90000 / LocalHardMs=180000 / ImpactedTaskWarningPercent=30 / MaxRepairAttempts=5 / MaxPropagationRounds=10 / ResourceTopN=5 / SplitAlternatives=3 / WarnOnlyOnMaxImpacted=true`
- 红线（清单 35/R17）：MaxImpactedOrders 超阈值仅 Warning + 人工确认，不得停止传播返回伪可行结果。

**统一校验**：发布前 `GET /api/Governance/parameter-set/version/{versionId}/validate` 返回 `PublishValidationResult`（IsValid + Errors[]，含 Code/Message/FieldName/Details）。错误码：`EMPTY_PARAMETER / INVALID_YIELD / INVALID_PURCHASE_LT / INVALID_OFFSET / INVALID_OVERDUE_MARGIN / INVALID_WAREHOUSE_PRIORITY / INVALID_SOLVER_STRATEGY / INVALID_CANDIDATE_GUARDRAIL / EMPTY_SOLVER_STRATEGY / EMPTY_CANDIDATE_GUARDRAIL` 等。

# 四、联调契约约定（4号位必读）

1. **响应包络**：现有 `GovernanceController` 返回 `{ success, data, error, message }`；`ScheduleController` 返回 `Shared.Models.ApiResponse<T>`（`{ success, data, error, meta }`）。**4号位需同时兼容两套包络**；建议 3号位后续补建接口统一走 `ApiResponse<T>`，本轮以现场联调记录为准，不再改已有接口。
2. **状态机**：新建强制 DRAFT；已发布不可原地修改（须建新版本）；历史不可覆盖。页面编辑按钮须按 Status 置灰。
3. **内容载体**：六块配置内容统一经 `ContentSnapshotJson` 持久化（契约 §6.10.5）；GET 详情已投影回主题 JSON（DemandPriorityJson/LockJson/SupplyJson/ProcurementJson/SolverStrategyJson/CandidateGuardrailJson），前端读写这些字段即可，不感知快照内部结构。
4. **发布前校验语义**：validate 只读不写；publish 后端二次强制校验；`IsValid=false` 时页面禁用发布并展示 `Errors[]`（Code/Message/FieldName）。
5. **冻结语义**：Run 启动后冻结 StrategyProfileVersion/RuleSetVersion/ParameterSetVersion/ExpectedDomainKeysJson/DataCutoffTime；运行中发布新规则不影响本 Run（验收 R03）。
6. **无逐笔 RPC**：4号位页面不触发逐笔规则判断；2号位/1号位在 Run 内使用一次性 Snapshot（B-5 缓存 Key=VersionId）。
7. **Candidate 语义**：CTP/Impact Analysis 永不激活；确认≠激活；激活原子替换。
