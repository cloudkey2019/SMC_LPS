## 一、问题陈述（09-29 联调实测）

Domain 维护页（`/aps/domain`）前端闭环后做穿透校验，**admin token** 对后端 `POST /api/governance/domain-definition` 与 `PUT /api/governance/domain-definition/{id}` 做了字段边界探测，**4 类字段未做或校验过松**——脏数据可静默入库：

| # | 字段 | 实测缺口 | 影响 |
|---|---|---|---|
| **F1** | `sortOrder` | 无 0-9999 边界（`-1` 和 `10000` 都 accepted） | 排序展示可出现负数 / 越界值，前端排序逻辑未定义 |
| **F2** | `domainKey` | 无字符集（中文 / 空格 / `.` / `'` / `;` 都 accepted）、无下限（2 字符 accepted） | DomainKey 是 DomainKeyPath 一部分；中文 / SQL 注入字符入库污染 |
| **F3** | `scopeType` | 大小写不敏感（`"family"` accepted，应仅 `"FAMILY"` / `"FACTORY_FAMILY"`） | 前端枚举字面量与 DB 字面量漂移；后端 enum 映射 silently fall through |
| **F4** | `domainName` | 无最大长度（100 字符 accepted） | DB 列宽未限可截断 / 中文 UI 折行；与角色名 / 权限名 32 上限不一致 |

> **已对齐（无需改）**：DomainKey 唯一性 400 ✓、FACTORY_FAMILY 必填 factoryId 400 ✓、ProductFamily/Factory FK 引用 400 ✓、DomainName 空串 / 纯空白 400 ✓、scopeType 空串 / null 400/422 ✓、sortOrder 小数 / 非数字 422 ✓。

## 三、建议的字段契约（4 号位 提议）

按"前端契约边界 + DB 列宽 + 与既有的 [RBAC 权限/角色/范围] 命名约定一致"原则：

| 字段 | 建议规则 | 理由 |
|---|---|---|
| `sortOrder` | `0 ≤ x ≤ 9999`（int） | DB 列宽 `[INT]`，下界 0 留扩展；9999 上界远大于 UI 实际需要 |
| `domainKey` | `^[A-Z][A-Z0-9_-]{3,49}$` | 与 RBAC `permissionCode` 的 `aps.<module>.<action>` 不一致（DomainKey 是 DomainKeyPath 一部分，不带 aps. 前缀）；上限 50 与现存 DB 列宽一致；下限 4 字符（保证可读性）；首字符必须大写字母 |
| `scopeType` | `enum: FAMILY | FACTORY_FAMILY`（严格大小写） | 与前端 TypeScript `DomainScopeType` 字面量类型对齐 |
| `domainName` | `2 ≤ len ≤ 64`（UTF-8 字符，非 byte） | 与角色名 32 / 权限名 32 / 用户名 32 一致；上限放宽到 64 留中文 / 业务术语空间 |

> 注：`domainKey` 现存 mock 数据 `FAMILY_INJECTION` / `BJ_FAMILY_INJECTION` 等均满足 `^[A-Z][A-Z0-9_-]{3,49}$`，**不会破坏既有数据**。

## 四、4 号位 已做的前端校验（仅供参考）

// src/views/Aps/Domain.vue（节选）
function validateDomainKeyFormat(_rule, value, cb) {
  if (!/^[A-Z][A-Z0-9_-]{3,63}$/.test(value.trim())) {
    cb(new Error('格式须大写字母/数字/_/-，首字符字母，长度 4-64'))
  } else { cb() }
}
const validateDomainKeyUnique = (_rule, value, cb) => {
  if (domains.value.some(d => d.domainKey === value.trim())) cb(new Error(...))
}

// sortOrder 边界
function validateSortOrder(_rule, v, cb) {
  if (typeof v !== 'number' || v < 0 || v > 9999) cb(new Error('排序权重须 0-9999'))
}
```

→ **前端校验仅做 UX 兜底**，**不可作为安全边界**（admin 直接 curl 可绕过）；后端必须独立校验。

## 五、3 号位 需要落地的 4 项 + 1 建议

### 项 1（F1）：`sortOrder` 边界 0-9999（P0）

在 `GovernanceController.cs` 的 `CreateDomainDefinition` / `UpdateDomainDefinition` 入口（或 `IDomainDefinitionGovernanceService.CreateAsync` / `UpdateAsync` 顶部）增加：

if (request.SortOrder < 0 || request.SortOrder > 9999)
    return BadRequest(new { code = 400, message = "sortOrder 须 0-9999" });
```

### 项 2（F2）：`domainKey` 字符集 + 长度下限（P0）

```csharp
// 建议正则
private static readonly Regex DomainKeyPattern =
    new(@"^[A-Z][A-Z0-9_-]{3,49}$", RegexOptions.Compiled);

if (!DomainKeyPattern.IsMatch(request.DomainKey))
    return BadRequest(new {
        code = 400,
        message = "domainKey 须以大写字母开头，4-50 字符，仅含 [A-Z0-9_-]"
    });
```

### 项 3（F3）：`scopeType` 严格大小写（P0）

```csharp
// 注意：C# 默认 enum 映射对大小写敏感，但 ASP.NET JSON 反序列化可能宽松
// 建议显式校验
if (request.ScopeType != DomainScopeType.FAMILY &&
    request.ScopeType != DomainScopeType.FACTORY_FAMILY)
    return BadRequest(new {
        code = 400,
        message = "scopeType 仅接受 FAMILY / FACTORY_FAMILY（严格大小写）"
    });
```

### 项 4（F4）：`domainName` 长度上限（P1，UX 影响）

```csharp
if (string.IsNullOrWhiteSpace(request.DomainName) ||
    request.DomainName.Length < 2 ||
    request.DomainName.Length > 64)
    return BadRequest(new {
        code = 400,
        message = "domainName 须 2-64 字符（UTF-8）"
    });
```

### 建议（项 5）：4 项集中校验

→ **建议**把上述 4 项校验抽到 `IDomainDefinitionGovernanceService.CreateAsync` / `UpdateAsync` 顶部（或独立 `DomainDefinitionValidator` 类），与既有的「唯一性 / FK 引用 / FACTORY_FAMILY 必填」校验并列。

**理由**：
- Controller 仅做 HTTP 适配（auth + scope + 序列化），业务规则放 Service 层利于复用 + 单测
- 与 `RbacController.cs` 既有的 `RbacValidator` 集中校验模式一致（参见 `RbacController.cs` 调 `IRbacValidator.ValidateCreateRoleRequest` 的现有模式）

→ **不强求**；若 3 号位 倾向把 4 项直接写在 Controller 内嵌代码，4 号位 也接受（契约行为一致即可）。
