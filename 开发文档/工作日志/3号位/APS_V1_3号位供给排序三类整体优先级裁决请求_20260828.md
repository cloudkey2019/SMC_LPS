# 八、0号位 裁决回执（2026-08-28 最终裁决）

**0号位 已裁决（A、B 均不采用）**——不存在需要冻结的"Inventory / PI / Procurement 三类 Supply 全局整体优先级"：

- **依据**：《APS_Pegging供需承接与分层计算业务说明_v1.1_冻结对齐版.md》明确 **V1 不建设 SupplyType 总优先表**。
- **语义澄清**：Inventory、PI、Procurement 在 3号位 实施包中并列出现，是因为三类具有**不同的类内资格/排序规则**，**不是因为它们是三个全局竞争组做组间排序**。
- **正式执行逻辑**：按**当前 Demand 的真实业务场景**决定允许进入的 Supply 链——

  | Demand 场景 | 允许供给链 | 冻结红线 |
  |---|---|---|
  | 顶层 SALES_ORDER | ERP 已扣成品库存，**APS 不得再次搜索普通成品库存** | 红线 #1 |
  | 自制需求 | 合资格库存 → PI → 生产缺口 | — |
  | 采购件 | 合资格库存 → 正式采购/VMI/已到厂未入库供给 → 必要时规划采购占位 | 红线 #8/#9 |
  | STAGE_HANDOFF | 目标 M → PI → PI Position → 新增生产 | 红线 #4/#13 |
  | INTER_FACTORY_ORDER | 目标 BS/KS → SH → 同SH Transit → 同SH Received → 未生产份额 | 红线 #14 |

- **落地约束**：
  1. 3号位 **不得新增** `SortCategoryPriority`；
  2. 3号位 契约**不得补写** Inventory → PI → Procurement 作为全局固定优先级；
  3. 2号位 **不得**把所有 Supply 按三大类别分组后固定依次消费；应先根据当前 Demand 业务身份/跨厂模式/供给链确定**当前允许使用的 Supply 集合**，再调用对应的类内排序规则；
  4. 3号位 现有 Inventory / PI / Procurement **类内规则继续保留并冻结**，不需要新增跨类别规则。
- **表述澄清**：此前"Inventory、PI、Procurement 三类分别执行"仅表示三类各自使用自己的排序规则，**不存在三类之间的总优先级**；若此前 PM 图示或临时答复被理解为 Inventory > PI > Procurement，该理解**明确废止**，以 Pegging 专项冻结业务说明为准。
- **本项定性**：**非业务缺口**，也无需 0号位 在 A/B 之间创造新规则——属于对**现有冻结业务语义的澄清**。
- **对 3号位 请求判断的纠正**：本请求 §四"三类整体先后未进 FrozenStrategySnapshot，属客观缺口"——**判断错误**。准确表述：FrozenStrategySnapshot 不存在"跨类别整体先后"，**不是缺口，而是符合设计**（Pegging 专项文档故意不建设 SupplyType 总优先表）。本请求 §五 方案 A/B、§六 方案 B 连带建议（"2号位 按固定顺序分组消费"）**均随裁决撤销**。
