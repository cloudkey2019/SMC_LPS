## 二、Batch Policy 两级承接（核心修订）

```
TaskSplitRuleConfig（主题规则表，维护真相；2号位 DDL/仓储）
        ↓ 3号位 发布/版本治理（复用参数/规则发布通道）
FrozenStrategySnapshot.BatchPolicy（运行冻结键控列表；3号位 Schema）
        ↓ 2号位 一次加载 → Dictionary<(Material, Dept), Entry>
1号位 内存查找（键控硬 Min/Max/Preferred/AllowSplit/AllowMerge）
```

### 2.1 主题规则表字段（对齐 0号位 §十四，红线 #6 走 DDL 申请）

| 拟定字段 | 语义 | 对照旧 `TaskSplitRuleConfig` |
|---|---|---|
| `MaterialId` | 物料 FK | 保留 |
| `ProductionDepartmentId` | 生产部门 FK（**新**） | 替换已废弃 `ResourceGroupId`（兼容保留） |
| `MinExecutionBatchQty` | 硬最小执行批 | 原 `MinimumOrderQuantity` 重释 |
| `MaxExecutionBatchQty` | 硬最大执行批 | 原 `EconomicOrderQuantity` 重释；**EOQ≠硬 Max，不再混义** |
| `PreferredBatchQty` | 软偏好切点 | **新**（仅候选生成偏好，不入权重总分） |
| `AllowSplit` / `AllowMerge` | 硬开关 | **新** |
| `IsActive` / `EffectiveFrom` / `EffectiveTo` | 生效区间 | 保留 |

- `BottleneckSplitStrategy` / `NonBottleneckStrategy`：**退出硬批量规则**，降为 Solver 软偏好（不进主题表，阶段 C 定去留）。
- **DDL 归属**：红线 #6，DB schema 变更 2号位 专属——3号位 只提 DDL 申请 + 业务字段口径，不落 DDL。

### 2.2 运行快照 `FrozenStrategySnapshot.BatchPolicy`

- 键控项列表：`{ MaterialId, ProductionDepartmentId, MinExecutionBatchQty, MaxExecutionBatchQty, PreferredBatchQty, AllowSplit, AllowMerge }`。
- 红线 #5 只增：新增第 ⑧ 子块，不动既有 7 块签名；`FrozenStrategySnapshotProvider` 加一装载 `DeserializeParameterSetBlock<List<BatchPolicyEntry>>` + `SolverStrategyValidator` 校验 fail-closed。
- 项目级承载：既有的 `ParameterSetVersion.ContentSnapshotJson` 继续作发布快照载体（主题表数据经发布装配进快照，而非大 JSON 当真相源）。

## 三、缺失策略兜底（fail-closed，修订 v1.0 §2.5）

```
① Material + ProductionDepartment 精确命中        → 采用该 Entry
② Material 默认（ProductionDepartment 为空，确有配置）→ 采用该默认
③ 正式发布的 Global Batch Default（3号位 发布/追溯）→ 采用全局默认
④ 仍无规则 → Strategy Snapshot 校验失败（BATCH_POLICY_MISSING）
```

- **删除 v1.0「缺策略回落全局软默认」**：Min/Max 是 MES 执行批硬业务约束，禁止 1号位 静默 `Min=0.1`（0号位 §十五）。
- `Min=0.1`（现有 `Split.MinBatchQty`）语义**降级为**「优化性拆批搜索下限」，非硬约束，注释/契约登记区分。

---

## 四、方向值域：仅 `Mode` 加 `AUTO`

- `SolverStrategyBlock.Mode` 原 `Forward/Backward/Mixed` 三值 → 加 **`AUTO`**（四值），**不新增 `Direction` 字段**（0号位 §十六.2）。
- 语义登记：`Mode` = Solver 时间搜索策略模式，非可破硬约束的「强制命令」；`AUTO` 由 1号位 依 Slack/Coverage/库存上下文动态选向，3号位 只配静态阈值（Slack 阈值、Coverage 阈值、搜索预算），不写动态 IF-THEN（红线 §七.2）。

---

## 五、策略 Scope 与权限 Data Scope 语义分离

- 接受 0号位 §十六.1：`StrategyProfile` **不因本轮加 ProductFamily/Factory/Stage/OrderType 列**。
- 技术底座可复用 `IDataScopeService`/Scope 解析，但**两个概念不混**：`BusinessScope`（权限 Data Scope）=「谁能动什么」；策略适用 Scope =「这套策略参数管哪个对象集合」。运行快照中策略适用范围**独立字段**表达，不挂在权限 Scope 名下。
