# 3号位契约 — 种子数据补齐（User / Role / DataScope）

**接收人**：3号位（认证 / 用户 / 角色 / 权限 / Domain 治理）
**来源**：4号位（前端页面与业务操作）
**生成日期**：2026-09-09
**前置文档**：[3号位契约-依赖与扩展项.md](3号位契约-依赖与扩展项.md)（v1.2 阶段依赖与扩展项）

## 二、3 号位需要落地的事项

### 任务 1 — 新增 User / Role / DataScope 种子服务

**新增文件**：`lps/LPS.APS.Engine/Services/Auth/UserRoleScopeSeedService.cs`
**对应接口**：`lps/LPS.APS.Core/Interfaces/IUserRoleScopeSeedService.cs`

#### 服务契约（参考 PermissionSeedService）

```csharp
public interface IUserRoleScopeSeedService
{
    /// <summary>确保 5 个 V1 mock 用户 + 5 个角色 + 关联 + Scope 策略已落库（幂等）。</summary>
    Task EnsureSeededAsync(CancellationToken cancellationToken = default);
}
```

#### 种子内容（5 用户 + 5 角色 + Scope）

**User 表（5 行）**：

| LoginName | DisplayName | PasswordHash | IsEnabled | 用途 |
|---|---|---|---|---|
| `viewer` | 查看员 | `PBKDF2$210000$<saltB64>$<hashB64>`（明文 `123456`） | true | 只读角色 |
| `pmc` | 计划员 | 同上 | true | 日常排程 / Candidate 确认 |
| `rule_admin` | 规则管理员 | 同上 | true | 规则 / 参数 / 策略编辑 |
| `rule_publisher` | 规则发布员 | 同上 | true | 规则 / 策略发布 |
| `sys_admin` | 系统管理员 | 同上 | true | 全部权限 + 范围管理 |

**实现要点**：
- 密码哈希必须用 `PasswordHasher.Hash("123456")` 生成，**不要硬编码 PBKDF2 字符串**
- 启动时为每个用户先查 `LoginName` 是否存在；存在则跳过，不存在则 INSERT

**Role 表（5 行）**：

| RoleCode | RoleName | IsSystemRole | IsActive | 挂的 PermissionCodes |
|---|---|---|---|---|
| `VIEWER` | 只读用户 | true | true | `aps.plan.view` / `aps.ctp.view` / `aps.candidate.view` / `aps.rule.view` / `aps.parameter.view` / `aps.strategy.view` / `aps.manual_eta.view` / `aps.demand_protection.view` / `aps.mes.view` |
| `PMC` | 计划员 | true | true | `aps.plan.view` / `aps.plan.run` / `aps.plan.compare` / `aps.plan.export` / `aps.ctp.view` / `aps.ctp.evaluate` / `aps.insert.impact.evaluate` / `aps.reschedule.local` / `aps.candidate.view` / `aps.candidate.confirm` / `aps.candidate.activate` / `aps.manual_eta.view` / `aps.manual_eta.edit` / `aps.manual_eta.cancel` / `aps.demand_protection.view` / `aps.mes.view` |
| `RULE_ADMIN` | 规则管理员 | true | true | `aps.plan.view` / `aps.rule.view` / `aps.rule.edit` / `aps.parameter.view` / `aps.parameter.edit` / `aps.strategy.view` / `aps.strategy.edit` |
| `RULE_PUBLISHER` | 规则发布员 | true | true | `aps.plan.view` / `aps.rule.view` / `aps.rule.publish` / `aps.parameter.view` / `aps.strategy.view` / `aps.strategy.publish` |
| `SYSTEM_ADMIN` | 系统管理员 | true | true | **全部 34 个 PermissionCode** |

**UserRole 表（5 行）**：
- viewer → VIEWER
- pmc → PMC
- rule_admin → RULE_ADMIN
- rule_publisher → RULE_PUBLISHER
- sys_admin → SYSTEM_ADMIN

**RolePermission 表（按上表挂权限码，通过 PermissionCode → Permission.Id 关联）**：
- 注意：写入时要先 `SELECT Id FROM Permission WHERE PermissionCode IN (...)` 拿到 Id 集合再批量 INSERT
- 幂等：每次启动先查 RolePermission 已有的 PermissionId 集合，差集补齐

#### DataScope 种子

**DataScopePolicy 表（推荐 9 条策略）**：

| ScopeType | ScopeValue | Description |
|---|---|---|
| `Global` | `*` | 全局放行（SYSTEM_ADMIN 用） |
| `Factory` | `BJ` | 北京工厂 |
| `Factory` | `SUZ` | 苏州工厂 |
| `ProductFamily` | `INJECTION` | 注塑产品族 |
| `ProductFamily` | `ASSEMBLY` | 装配产品族 |
| `ProductFamily` | `TEST` | 测试产品族 |
| `Department` | `PMC_DEPT` | 计划部 |
| `Domain` | `FAMILY_INJECTION` | 注塑域（v1.2 DomainKey 命名规范） |
| `Domain` | `FAMILY_ASSEMBLY` | 装配域 |
| `Domain` | `FAMILY_TEST` | 测试域 |

> 说明：`ResourceOrgGroup`（兼容字段）V1 mock 不挂，5 号位后续按需添加。

**RoleDataScope 表（推荐 6 条）**：
- VIEWER → Factory=BJ + ProductFamily=INJECTION（窄范围示例）
- PMC → ProductFamily=INJECTION+ASSEMBLY+TEST（跨产品族全放行，无工厂限制）
- RULE_ADMIN → Factory=BJ（规则只在北京工厂）
- RULE_PUBLISHER → Factory=BJ（同上）
- SYSTEM_ADMIN → Global=*

> UserDataScope 表：本批次**不挂**（用户直接范围由 SYSTEM_ADMIN 在 RBAC 管理页后续按需分配）

### 任务 2 — Program.cs 启动串行调用

**文件**：[lps/LPS.APS.Web/Program.cs:324-335](../../lps/LPS.APS.Web/Program.cs#L324-L335)

在现有 `IPermissionSeedService.EnsureSeededAsync()` **之后**追加：

```csharp
using (var scope = app.Services.CreateScope())
{
    var userRoleScopeSeeder = scope.ServiceProvider.GetRequiredService<IUserRoleScopeSeedService>();
    try
    {
        await userRoleScopeSeeder.EnsureSeededAsync();
    }
    catch (Exception ex)
    {
        Log.Warning(ex, "User/Role/Scope 种子播种失败（APS_Auth 可能不可用），不影响启动");
    }
}
```

> 警告级别 + 不阻断启动，与 PermissionSeedService 同策略。

## 三、验证步骤（4 号位端到端）

种子落地后，4 号位会用以下流程验证：

1. **启动后端**：`cd lps && dotnet run --project LPS.APS.Web`（端口 5163）
2. **登录 5 个用户**：依次用 `viewer` / `pmc` / `rule_admin` / `rule_publisher` / `sys_admin` + 密码 `123456` 调 `POST /api/auth/login`
3. **调 `/api/auth/me`**：校验 `roles` / `permissions` / `dataScope` 字段符合本表预期
4. **权限场景矩阵**：参照 [P1-14-15-权限场景测试矩阵.md](P1-14-15-权限场景测试矩阵.md) 跑 15 步端到端

具体每个用户期望的返回值：

| 用户 | Roles 期望 | permissions 期望长度 | dataScope 期望 |
|---|---|---|---|
| viewer | `[VIEWER]` | 9 | IsGlobal=false, factories=[BJ], productFamilies=[INJECTION] |
| pmc | `[PMC]` | 16 | IsGlobal=false, factories=[], productFamilies=[INJECTION,ASSEMBLY,TEST] |
| rule_admin | `[RULE_ADMIN]` | 7 | IsGlobal=false, factories=[BJ], productFamilies=[] |
| rule_publisher | `[RULE_PUBLISHER]` | 6 | IsGlobal=false, factories=[BJ], productFamilies=[] |
| sys_admin | `[SYSTEM_ADMIN]` | 34 | IsGlobal=true, 其余空数组 |

> `IsGlobal=true` 时后端 `dataScope` 应全空数组（见 [UserInfoDto.cs](../../lps/LPS.APS.Web/Dto/Auth/UserInfoDto.cs) 注释：`Global 时为全放行，各维度集合为空`）

## 五、风险与注意

| 风险 | 缓解 |
|---|---|
| 5 用户密码统一 `123456` 安全 | 仅 dev 环境使用，文档中明确「生产前删除种子」 |
| `RoleDataScope` 写入 PMC 时 3 个 ProductFamily 范围需多次 INSERT | 用循环 / 批量，幂等 |
| `PermissionCode` 字面量必须严格匹配 `PermissionCodes.All` | 复用 `PermissionCodes` 常量，不硬编码字符串 |
| 启动种子顺序：Permission 必须先于 RolePermission | 当前 PermissionSeedService 先跑，OK |
| 系统角色 `IsSystemRole=true` | RBAC Controller 删除逻辑应跳过系统角色（如果实现） |
