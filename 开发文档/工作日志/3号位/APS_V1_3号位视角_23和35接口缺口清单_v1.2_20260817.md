# 四、0号位实施裁决（2026-08-17，最终）

## 裁决 A：FrozenStrategySnapshot 归属 —— 已闭合（原开放点，不再询问"谁负责"）

> **3号位负责按已冻结 StrategyProfileVersion 构建并提供 FrozenStrategySnapshot；2号位负责在 ScheduleRun 开始时读取一次并按 VersionId 在本 Run 内存使用。**

建议轻量 Provider（类名不强制）：

```csharp
Task<FrozenStrategySnapshot> GetFrozenStrategySnapshotAsync(
    long strategyProfileVersionId,
    CancellationToken ct);
```

执行链固定：

```text
ScheduleRun
→ StrategyProfileVersionId 已冻结
→ 2号位调用 3号位 Snapshot Provider 一次
→ 得到 FrozenStrategySnapshot
→ 本 Run 内存缓存
→ 2号位执行 Demand/Pegging 规则
→ Solver 部分放入 DomainSolveRequest 给 1号位
```

**不需要做**：让 2号位自读六张治理表拼 Snapshot；为形式统一塞进 `IDataLoader`；新建 Snapshot 物理表；修改《关键接口冻结》。

**不构成 2号位新增整改项**：原 2号位实施包 + 已冻结审核"Frozen Solver Strategy / Context 不能硬编码"已含此要求。

## 裁决 B：不新增 PI Position "UNLOCATED 比例/容忍度"业务参数（删除补充点 1）

冻结规则明确：

```text
Position 无法定位 → 差额进入 UNLOCATED → 总量仍必须闭合
Σ PositionQty != ERP RemainingQty 且无法保守定位 → 严重 Issue / Domain 失败
```

**不得引入"容忍 5% 数量不闭合"类业务阈值。** 5号位实施包第十八章"Position 容错阈值"仅指事实计算的技术容差可能（如浮点/单位换算产生的 `0.000001` 级差异），**非业务容忍率**。

→ 从 3号位必需治理项中**删除**"将 PI Position 容错阈值纳入 3号位参数治理"的建议；D 阶段不新增该参数。

## 裁决 C：FrozenFactParameters = Snapshot 参数子集投影，非第二套 Snapshot（明确补充点 2）

> **FrozenFactParameters 只是 FrozenStrategySnapshot 中供 5号位复杂事实计算所需参数的最小投影，不是独立版本体系。**

V1 优先链路：

```text
3号位 FrozenStrategySnapshot
        ↓
2号位一次装载
        ↓
抽取 5号位真正需要的参数子集 → FrozenFactParameters
        ↓
5号位 PI Position / Timed Supply 计算
```

- **不新增** `FrozenFactParametersVersion`、不新增表、不新增独立版本号；
- 不让 5号位逐笔 RPC 调用 3号位；
- 一个 Run 只有一份规则真相（避免 2号位拿 Snapshot A、5号位又从 3号位拿 Snapshot B）。

## 裁决 D：ETA 优先级 = 冻结业务 Invariant（修正补充点 3）

```text
Manual ETA > ERP ETA > DefaultLT
```

是**当前 V1 固定业务口径（Invariant）**，**不做成可任意配置排序**（不配置化）。

职责拆分：
- **3号位治理**：Default Purchase LT、逾期 Margin、Arrival-to-Usable Offset 等参数；
- **5号位/ODS**：读取 Manual/ERP ETA → 按固定优先级得 Effective ETA → 应用冻结 DefaultLT/Margin/Offset → 输出 AvailableTime（事实标准化）；
- **2号位**：消费 `TimedSupplyFact`（AvailableTime / Commitment / Confidence）做 Supply 选择、Balance、Allocation。

清单表述修正：不写"ETA 优先级可配置治理"，写 **"ETA 优先级为冻结业务 Invariant；3号位治理 DefaultLT、Margin、Offset 等参数"**。

## 裁决 E：旧 AlgorithmType 退出 V1 主链（确认 #5）

- `FIFO / PRIORITY / GENETIC / SIMULATED_ANNEALING` 退出 V1 正式主链；
- 正式 Solver Strategy = `FORWARD / BACKWARD / MIXED` + 动态瓶颈 / On-time / Split / Setup / Overlap / Candidate Guardrail；
- 若物理删除成本大，可保留 `Deprecated`，正式调用路径为 0；
- **不做**架构清理式重构。

## 裁决 F：无新增 2号位整改项

- 本轮 3号位视角未产生任何新 2号位整改要求；
- 2号位仍严格按**已冻结代码审核报告全部意见 + P0-20** 执行；
- 审 3号位时以已冻结 2号位方案为输入，不反向改变 2号位。
