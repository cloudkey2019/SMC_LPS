## 四、2.3 Reschedule 端点 —— 确认

| 项 | 定案 |
|---|---|
| 端点 | `POST /api/governance/run/candidate`（L627），RunType 含 `MANUAL_RESCHEDULE`，即 triggerReschedule 官方入口 ✅ |
| 入参 | `CreateCandidateRunRequest`（非 `TriggerRescheduleInput`）；**不加 objectRefIds** |
| 权限码 | `aps.plan.run`（后端 L626 已挂）|

**入参 `CreateCandidateRunRequest` 字段**：

| 字段 | 类型 | 说明 |
|---|---|---|
| RunType | string | `MANUAL_RESCHEDULE` / `LOCAL_RESCHEDULE` / `INSERT_ORDER_WHATIF` |
| Purpose | string | 须 ∈ RunType×Purpose 冻结合法组合（见下）|
| DomainKey | string | 严格单 Domain |
| BasePlanVersionId | int? | 基于的 ACTIVE 计划版本（缺省按 DomainKey 解析 ACTIVE）|
| DataCutoffTime | DateTime? | 数据切片边界（缺省 now）|
| Remark | string? | 备注（替代前端 `reason`）|

**RunType×Purpose 冻结合法组合**（`RunLifecycleService.cs:65-71`）：

- `MANUAL_RESCHEDULE` → `MANUAL_ADJUSTMENT`
- `LOCAL_RESCHEDULE` → `INSERT_RESCHEDULE` / `MANUAL_ADJUSTMENT`
- `INSERT_ORDER_WHATIF` → `CTP` / `INSERT_IMPACT_ANALYSIS`（且永不可激活）

→ triggerReschedule 传 `RunType=MANUAL_RESCHEDULE, Purpose=MANUAL_ADJUSTMENT`；**objectRefIds 砍掉，reason → Remark**。
