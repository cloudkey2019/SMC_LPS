## 二、修复详情（按审核项）

### P0-01：Batch Policy 列表查询未实施 Business Scope 过滤

- **审核问题**：`ListAsync` 无 `actorUserId`、未解析有效部门/工厂 Scope，省略部门即全表返回，违反《APS权限与审批设计方案v1.1》§9.3「查询接口必须按照有效 Scope 返回数据」。
- **修复**：`ListAsync` 增 `actorUserId` 参数 → `ResolveAllowedDepartmentIdsAsync` 解析 Department 授权 Id 集——Global 授权→不按部门过滤；非 Global 无任何部门授权→fail-closed 空页；显式传入越权部门→`ScopeViolationException`→403（防 IDOR 探测）。COUNT 与分页同过滤逻辑。
- **修复结果**：集成反证 P0-01#1（显式越权 403）、P0-01#1b（无授权空页）通过；规则列表不传部门/显式 B/跨页 Total 均不泄露 B。

### P0-02：Batch Policy 编辑只检查新部门，存在跨部门篡改入口

- **审核问题**：`UpdateAsync` 只校验新部门，用户若仅授权 A、知道 B 部门规则 Id，可把 B 记录改成 A 并覆盖规则。
- **修复**：Update 先取旧记录，对**旧记录 `ProductionDepartmentId` 鉴权**，再对**拟变更新部门**鉴权——两处 `EnsureDepartmentScopeAsync` 双校验；首轮任一越界即拒绝（老归属越权时新部门不触达）。
- **修复结果**：集成反证 P0-02#2（A 用户改 B 记录并改部门为 A → 403、B 原记录不变）通过。

### P0-03：StageLeadTimeParam 治理列表与写入缺 Business Scope 后端校验

- **审核问题**：服务无 `IDataScopeService`，Factory/Department 参数为调用方可控筛选，不校验登录用户范围。
- **修复**：服务构造注入 `IDataScopeService`；List 按 Factory/Dept 授权集合 IN 过滤（维度未授权不约束、无任何授权→空列表不查库）；写路径 `EnsureTargetInScopeAsync`（Factory 必查、Dept 非空必查）→ 越界 `ScopeViolationException`→403；Controller `HandleError` 补 `ScopeViolationException`→403。
- **修复结果**：单测反证 4 条（IN 拼接 / 无授权空列表不查库 / 工厂越权 403 / 越权写拒绝）通过。

### P0-04：Batch Policy 有效期「相切不重叠」与有效判断矛盾

- **审核问题**：窗口排重严格 `<` 允许 `[10:00,11:00]` 与 `[11:00,12:00]` 相切，但 Projector 用 `EffectiveTo >= now` 判定，11:00 两条同时有效，向发布快照投影重复键。
- **修复**：统一半开区间 `[EffectiveFrom, EffectiveTo)`——治理写路径严格 `<`（既有）+ Projector 生效判定改 `EffectiveTo > now`；治理/投影/发布/读取链同一语义。
- **修复结果**：单测边界 2 条（相切时刻至多一条有效）通过；未借机重裁批量业务（技术口径保持一致）。

### CANDIDATE-P0-01：旧记录非法内容静默进入发布快照

- **审核问题**：`Project()` 只筛 IsActive/部门非空/有效期，不校验 Preferred 与 Min/Max 数值合法性，存量非法行可进新发布参数集快照。
- **修复**：`GetActiveRulesForSnapshotAsync` 加 `IsSnapshotEligible` 全量校验（`PreferredBatchQty` 非空且>0、`MinBatchQty ≤ MaxBatchQty`、`Preferred ∈ [Min, Max]`）——非法行阻断参数集发布并列出 Id（严禁默默当有效）。
- **修复结果**：集成反证（直连注入非法行 → 发布阻断）通过。

### P1-01：NULL 部门历史记录无法正常停用

- **审核问题**：`DeactivateAsync` 对 NULL 部门记录取值 `existing.ProductionDepartmentId!.Value` 可能 Null 异常（500）。
- **修复**：NULL 部门历史记录仅 Global 授权可停用（fail-closed），普通授权 403；保留审计留痕；非 NULL 路径正常 Scope 校验。
- **修复结果**：集成反证（NULL 部门行 + 非 Global → 403）通过。

### P1-02：有效期排重存在竞态窗口

- **审核问题**：`EnsureUniqueEffectiveWindowAsync` 的 SELECT COUNT 与后续 INSERT/UPDATE 分离，并发请求可均通过检查写入重叠窗口。
- **修复**：Create/Update 的「唯一有效期检查 + 写」收进 `ExecuteInTransactionAsync` 事务内，并持 `(MaterialId, DeptId)` SQL Server 独占应用锁（`sp_getapplock`，事务 Owner 自动释放）；新增 `AcquireExclusiveLockAsync` + 事务重载 `EnsureUniqueEffectiveWindowAsync`（`DECLARE @ret + SELECT @ret` 取锁返回值）。**零 DDL**。
- **修复结果**：双并发集成反证（同一键两并发 → `succeeded=1/rejected=1`）通过，验证应用锁串行化真实生效。

### P1-03：治理 DML 与 AuditLog 落地原子性未证明

- **审核问题**：Create/Update/Deactivate 先 DML 后审计，审计写失败可能「已生效但无追溯审计」。
- **修复**：以 `IAuditLogRepository.EnsureWritableAsync` 审计前置预检（开 Auth 库事务即回滚探测可写，fail-before-write）先于一切治理 DML——审计库不可写则整操作失败、业务零变更。接线范围：TaskSplitRuleConfig（6）+ StageLeadTimeParam（3）+ SetupRule（5）+ RoutingOperation（1）+ GovernanceVersionService Publish/Disable（6）+ DomainDefinition 既有（3）+ RunLifecycle 既有（1）。
- **残余窗口如实文档化**：跨库无 2PC，预检通过后 `AddAsync` 抛 → 异常向调用方传播（操作显式失败 500、可重试/人工核对），不作虚假「原子回滚」宣称。
- **修复结果**：说明件 `3号位致0号位_审计一致性契约与失败补偿说明_P1-03_20261009.md` + 失败注入集成反证 ×2（预检失败→业务键零落库 COUNT=0；AddAsync 抛→COUNT=1 已生效但操作报错，如实文档化）通过。

### P1-04：Scope 问题存在向其它治理服务扩散的迹象

- **审核问题**：SetupRuleService / StageLeadTimeParam 未见 `EnsureInScopeAsync` 使用点。
- **修复**：提交全治理服务功能权限×Scope 二次校验清单（`3号位致0号位_治理服务功能权限与Scope二次校验清单_P1-04_20261009.md`，8 服务矩阵）——确有业务范围字段的实体（含 `ProductionDepartmentId`）落写路径 Scope 校验 + 具体反证；无业务范围字段的实体（RuleSetVersion/GovernanceVersion 全局版本工件）如实判定「不设记录级 ACL」，未盲目上通用记录级 ACL 平台。本次补齐：`SetupRuleService`（Create×2 新部门 / Update×2 老+新 / Delete 老部门，5 写路径 `EnsureDepartmentScopeAsync`，部门不存在 404、越界 403 + 5 处审计预检）+ `RoutingOperationGovernanceService`（Update OPM 目标部门校验 + 预检）。
- **修复结果**：`SetupRuleServiceScopeTests` 8 条反证（Create 越权 403/404、DEFAULT 越权、Update 老+新双归属、Delete 越权、预检 fail-before-write×2）通过。
