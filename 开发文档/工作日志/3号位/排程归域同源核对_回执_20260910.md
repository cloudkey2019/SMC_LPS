## 证据（逐条对上 2号位侧代码）

### 问1：排程归域消费 `DomainDefinition`（同源）

1. **归域唯一入口** `sp_SyncOrdersToPartitionTable`（`Database/Scripts/APS/03_SQL脚本/sp_SyncOrdersToPartitionTable_Domain化_20260902.sql`）：
   - 读 `PlanVersion.DomainKey` → 查 `DomainDefinition WHERE DomainKey=@DomainKey AND IsActive=1` 定位域；
   - 按 `ScopeType`（FAMILY / FACTORY_FAMILY，含 `ProductFamilyId ↔ DomainKey`）筛订单归域；
   - 写回 `DomainKey = PlanVersion.DomainKey`（透传，非推导）；
   - **无有效 DomainDefinition 时 RAISERROR 拒跑**（不静默拼规则、不降级）。

2. **只读服务** `DomainDefinitionService.GetActiveDomainsAsync`（`LPS.APS.Engine/Services/Sync/DomainDefinitionService.cs`）：
   - `FROM DomainDefinition WHERE IsActive = 1`，返回 `DomainKey / ScopeType / ProductFamilyId / FactoryId`。

3. **排程侧 DomainKey 一律透传**，不重新推导：
   - `SchedulingOrchestrator.cs:83` 读 `GetExpectedDomainKeysAsync`（ScheduleRun.ExpectedDomainKeysJson）；
   - `SchedulingOrchestrator.cs:424` `DomainKey = planVersion.DomainKey`；
   - Pegging/ScheduleQuery 侧 `DomainKey` 均为「读上游落盘 / 比较」传参，非生成。

### 问2：不存在第二套 DomainKey 推导

- 旧 `FACTORY_{factoryId}` 命名推导已废，仅剩注释声明「不再以 FACTORY_{id} 推导 / 禁用 FACTORY_{factoryId} 冒充」：
  - `ScheduleQueryService.cs:105`、`GanttDataDto.cs:34`、`PeggingExecutionRequest.cs:19`。
- 旧 `JOIN ProductFamily.Code 冒充 DomainKey` 已删：
  - `SchedulingOrchestrator.cs:880` 注释「不再 JOIN ProductFamily.Code 冒充」。
- 全域检索无 `DomainKey = <拼接>` 生成逻辑；`DomainKey` 全部为「读 `DomainDefinition` / `Domain_Dependency`（真实 DomainKey 口径）/ 透传 `PlanVersion.DomainKey`」。

### 问3：异源整改排期

不适用——已确认同源、无第二套推导，无需整改。
