# 3号位 → 0号位/2号位：单域全流程跑通缺口评估（v1.0）

> 发件：3号位（规则/参数/Auth/RBAC/Scope 治理 Owner + dev seed 数据 Owner）
> 致：0号位 / 2号位
> 日期：2026-10-10 ｜ 版本：v1.0
> 依据：用户指令「要支持0号位和2号位组织单域全流程跑通，还有没有不足的部分？真实单Domain完整出计划——以同一个冻结的数据切面，从真实BOM、库存、PI/MES、Routing、Calendar到Solver，再到FinalTask、TaskShare和Explanation全部落库。必须证明数量、资源、时间和状态闭合。」
> 方法：4 个只读 Explore 并行调研（上游事实切面 / Solver 输入装配 / 结果落库 / 现有全流程测试），零代码改动。

## 〇、总体判断

**主链骨架已通**：订单归域 → 每域一 PV → BOM 接货 → Pegging → Solver → `Task` / `AllocationTaskShare` / `ScheduleExplanationFact` 同事务落库 → `ScheduleRun` / `PlanVersion` 状态收口（唯一状态断言在 `RealDomainFullRunTest.RunRealSeamAsync`）。

**但「同一个冻结数据切面 + 四闭合证明」两个前提目前均不成立**——这是支持单域全流程的最硬缺口，且绝大多数落在 2号位（数据引擎/编排）而非 3号位。3号位 域内收窄后共 5 项（§六，1 项 P0 预检、1 项可自决数据治理）。

| # | 缺口 | 位置 | 归属 |

| B2 | **采购在途连物料/工厂维度都不传** | `PeggingOrchestrator.cs:2082-2083`（SupplyFactScope 支持却不传）→ 全厂在途进本域池 | **2号位** |
| B3 | **PI B源跨域泄露** | 按物料宇宙从 `Order_Canonical` 补取，无工厂/域过滤（`PeggingOrchestrator.cs:3238-3265`） | **2号位** |
| B4 | **资源/日历全量读** | `LoadResourcesAndCalendarAsync`（:804-930）无域/工厂过滤，Resource 实测 7,768 行全载入 | **2号位** |
| B5 | **归域歧义** | 同 scope+同 ProductFamilyId 两启用域 → 订单跨 2 个 PV 分区（`BOMResultPullService.cs:420-427` 实测 FAMILY2 与 FAMILY_X 双命中） | **3号位/PM 定盘** |

## 七、判断依据（先自己判断再升级）

- **G1/G2/G3/G5 均不触冻结封闭枚举、不涉新语义** —— 属 3号位 自有治理数据完备性与 seed 责任，**可自决**，无需升级 0号位。
- G2 仅当「同 scope 双启用域的**归域优先级规则**」需定盘（不是删重而是语义取舍）时，才升级 0号位/PM——先做数据侧清理 + `DomainDefinition` 治理校验防再发生。
- G4 属 3号位 既有职责（MANUAL_RESCHEDULE Run 创建），正常执行，不升级。
- **需 0号位/PM 定盘（触及冻结数据模型）**：A1/A2/A3 是否给 BOM/库存/在途补 DataCutoffTime 冻结切面（DDL 变更）；B5 归域规则语义取舍。
