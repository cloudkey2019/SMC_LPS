## 一、端点契约补全（setupLookups.ts 封装依据）

路由前缀已核：`SetupRuleController` = `[Route("api/governance")]` → 完整路径如下。三端点均 `[Authorize(Policy = PermissionCodes.SetupView)]`（权限码 `aps.setup.view`），响应 `ApiResponse<IReadOnlyList<T>>`（`data` 数组）。

| 端点 | 查询参数 | 返回项（字段 = 契约名） | 排序 |
|---|---|---|---|
| `GET api/governance/lookups/departments` | `search?`（模糊 DeptCode） | `DepartmentLookupItem{MasterId, Code, StageCode}` | DeptCode |
| `GET api/governance/lookups/resources` | `search?`（模糊 ResourceCode/ResourceName） | `ResourceLookupItem{MasterId, Code, Name, ProductionDepartmentId}` | ResourceCode |
| `GET api/governance/lookups/materials` | `search?`（模糊 Code/Name/Spec）、`activeOnly?`（默认 false） | `MaterialLookupItem{MasterId, Code, Name, Spec, Uom, IsActive}` | IsActive DESC, MaterialCode |

- 共同：后端 `TOP 200` 上限；**不做去重**（红线 #4 恒返回列表）；`MasterId` = 源表 Id（落写端 payload Id 用）。

## 二、Q1–Q5 逐项回执

### Q1【关键】Stage / Operation —— **Stage 衍生、Operation 单独排期**

1. **Stage = 由 department 端点衍生**：`DepartmentLookupItem` **已含 `StageCode`**（实测 distinct 24 个）——撤 mock `stageOptions` 时，从 departments 响应取 distinct StageCode 即可，**无需新端点**；
2. **Operation = 单独排期（P2）**：本次未交付 operation 端点（`OperationResourceEligibility` 仅为「有合格资源」的工序，非工序主数据全集）；3号位 后续排期补 operation 读端点；
3. **本轮处置**：`operationOptions` **保留 mock**——operation 为 **Code 语义写端**（`operationCode`），非 Id 字段，**不阻塞** P0 三主数据（dept/resource/material）Code→Id 主流程。4号位 撤 mock 时只撤 departments/resources/materials 三项（含 stage 一并切真实）。

### Q2【关键】物料重码 —— **活动优先 + spec/uom 区分，不唯一化**

- 后端已实现口径（无需 4号位 二次判定）：
  1. **不做去重**（红线 #4）；排序 `IsActive DESC, MaterialCode`——**活动项恒在前**；
  2. `activeOnly=true` → 直接过滤 `IsActive=1`；
  3. **无版本时间倒序取最新**（Material 无版本时间列，此方案不采用）。
- **前端渲染规则**（采纳 4号位 方案①）：
  - 默认 `activeOnly=false`（全量、活动优先序），label 拼 `${code}（${name}${spec ? ' · ' + spec : ''}）`；
  - **同 code 重码并存**时，以 **spec/uom 后缀区分**（数据已带 Spec/Uom）；活动项在前由 IsActive 排序保证；
  - 仅需活动项的业务场景传 `activeOnly=true` 收紧。

### Q3 数据量级 —— **实测三表均超 200，前端 search 驱动（对交付通知的关键修正）**

实测（APS_Production，2026-09-21）：

| 表 | 行数 | 与 200 上限 |
|---|---|---|
| ProductionDepartment | 287 | 超 |
| Resource | 7,768 | 超 |
| Material | **900,995**（活动 870,912） | **90 万级，绝不可全量** |
| distinct StageCode | 24 | 可全量 |

- **修正**：交付通知「主数据量级可直接全量渲染」假设**不成立**——三表均超 200，后端 `TOP 200` 下默认查询即截断；
- **分页策略**：本轮**不加分页**；前端三下拉一律 **search 驱动**（输入 ≥1 字符即查，返回命中 ≤200 展示）——4号位 原「按 ≤200 全量渲染接入」改为「search 收窄 + 命中展示」；
- 可选（P2）：端点加 `?limit=`（默认 200、可配上限）供部门等小表一次取全；本轮不动代码。
