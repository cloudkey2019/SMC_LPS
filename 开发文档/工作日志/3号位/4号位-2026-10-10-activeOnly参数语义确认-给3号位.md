## 二、根因（已读 lps/ 源码确认，非前端误判）

### 2.1 调用链

```
GovernanceController.cs:675-685
  ↓ [FromQuery] bool? activeOnly
  ↓ 透传
RuleSetRepository.GetListWithVersionAsync(activeOnly, keyword, skip, take)
  ↓ L110-114
  sql += " AND r.[IsActive] = @IsActive"
  parameters.Add("IsActive", activeOnly.Value)
  ↓
  SQL Server: WHERE r.[IsActive] = 0
```

### 2.2 客观事实

- dev DB `APS_Production.dbo.RuleSet` 全表 648 条记录，`IsActive` 列**全部为 1**（与 R1 早期催办单「Seed 数据仅造 active=True」一致）
- `?activeOnly=false` → 拼 `IsActive=0` → 自然返 0 条
- 这与 4号位 10-10 策略配置页观察到的"1682 占位数据无版本"问题**同源**（dev DB 数据分布问题，不是后端 bug）

### 2.3 结论

**`activeOnly` 参数解析、Controller 透传、Repository SQL 拼接均正确**。返 0 = dev DB 真实状态（无归档/停用数据）。

## 三、建议（请 3号位 拍板，2 选 1 或都不采纳）

### 方案 A：API 文档化 + 响应提示（推荐，零代码改动）

在 `3号位契约-dev种子补丁说明.md` 或新增 1 个 `3号位契约-activeOnly参数语义.md` 中明确：

> **`activeOnly` 三态语义**：
> - `?activeOnly=true`  → 仅查 `IsActive=1`（dev 当前唯一数据源）
> - `?activeOnly=false` → 仅查 `IsActive=0`（dev 当前返 0 条 = 真实状态）
> - 无该参数          → 不加 IsActive 过滤（全量，等同 `IS NULL`）

并在 OpenAPI/Swagger 注释（`GovernanceController.cs:675`）补一句 `/// <remarks>dev DB 当前全为 IsActive=1，传 false 必返 0</remarks>`，避免其他号位踩坑。

### 方案 B：响应头加 `X-Total-Count` 或 body 加 `total`（需代码改动）

参考 `/api/business-fact-issues` 4号位 10-10 提的分页契约：

```json
{
  "code": 200,
  "data": {
    "items": [...],
    "total": 0,          // ← 新增
    "activeCount": 648,  // ← 可选：当前 active 数（让调用方一眼看出返 0 是无归档）
    "inactiveCount": 0   // ← 可选
  }
}
```

**改造成本**：Controller + Repository + DTO 三处 + DTO 新增 `ActiveCount`/`InactiveCount` 字段（多 1 个 COUNT 查询）；4号位 同步改 types/api/store。

### 方案 C：均不采纳，保持现状

理由：当前 4号位 默认 `?activeOnly=true&pageSize=500` 实际不踩坑；`activeOnly=false` 是 dev 联调偶发需求，不值得为它改契约。
