## 三、必加实体 + DDL 修订（§二十一 字段 / DDL 修订特别注意）

### 3.1 新增实体

```csharp
// lps/LPS.APS.Core/Entities/Aps/SetupRule.cs
public class SetupRule : AuditableEntity
{
    public long Id { get; set; }
    public long RuleSetVersionId { get; set; }              // FK → RuleSetVersion
    public RuleType RuleType { get; set; }                  // EXACT / DEFAULT
    public string DepartmentCode { get; set; }              // 生产部门
    public string StageCode { get; set; }                   // 大工艺
    public string OperationCode { get; set; }               // 当前小工序（**唯一工序维度**）
    public string ResourceCode { get; set; }                // 设备
    public string? FromMaterialCode { get; set; }           // 前产品（EXACT 必填 / DEFAULT 必空）
    public string? ToMaterialCode { get; set; }             // 后产品（EXACT 必填 / DEFAULT 必空）
    public int SetupMinutes { get; set; }                   // 换型时间（分钟）
    public SetupRuleStatus Status { get; set; }             // DRAFT / ACTIVE / DEPRECATED
    public string? Remark { get; set; }
    public DateTime CreatedAt { get; set; }
    public string CreatedBy { get; set; }
    public DateTime? UpdatedAt { get; set; }
    public string? UpdatedBy { get; set; }
}
```

### 3.2 唯一性约束（§10）

- **EXACT 唯一键**：`RuleSetVersionId + DepartmentCode + StageCode + OperationCode + ResourceCode + FromMaterialCode + ToMaterialCode`
- **DEFAULT 唯一键**：`RuleSetVersionId + DepartmentCode + StageCode + OperationCode + ResourceCode`
- **业务约束**：
  - `RuleType = EXACT` → `FromMaterialCode + ToMaterialCode` 必填非空
  - `RuleType = DEFAULT` → `FromMaterialCode + ToMaterialCode` 必为空
  - `FromMaterialCode != ToMaterialCode`（同产品连续 = 0 分钟，不存规则）
  - `SetupMinutes >= 0`

### 3.3 必删 / 退役字段（§二十一）

- ❌ **删除** `RoutingOperation.SetupTime` 字段（v1.2 收口版 §1.1 明确废止 MES 提供 SetupTime 模型）
- 历史物理列若暂不 DROP，加注释 `[Obsolete("Setup v1.2 收口版废止，新代码禁止使用")]`
- ❌ **不得新增** `FromOperationCode / ToOperationCode` 字段（§二十 明确废止前小工序 + 后小工序模型）

### 3.4 必加索引

```sql
CREATE INDEX IX_SetupRule_EXACT_Lookup
ON SetupRule (RuleSetVersionId, DepartmentCode, StageCode, OperationCode, ResourceCode, FromMaterialCode, ToMaterialCode)
WHERE RuleType = 'EXACT' AND Status = 'ACTIVE';

CREATE INDEX IX_SetupRule_DEFAULT_Lookup
ON SetupRule (RuleSetVersionId, DepartmentCode, StageCode, OperationCode, ResourceCode)
WHERE RuleType = 'DEFAULT' AND Status = 'ACTIVE';
```

## 四、建议实现路径（3 号位 可参考）

### 4.1 复用现有 RuleSetVersion 模式

参考 `lps/LPS.APS.Application/Services/RuleSetVersionService.cs` 的 CRUD 模式：
- Controller 增 `SetupRuleController`（`Route("api/governance/setup-rules")`）
- Service 增 `ISetupRuleService` + `SetupRuleService`
- Repository 增 `ISetupRuleRepository` + Dapper 实现

### 4.2 共同合法设备推荐（#9）

参考 `OperationResourceEligibility` 实体（lps 中已有）：
- 输入：`operationCode` + `materialId`
- 输出：`ResourceCode[]`（**当前 Operation 合法资源 ∩ 同部门同 Stage 任一 Operation 合法资源**）
- 由 3 号位 治理（§19.1 第 6 项"Setup 算法参数治理"延伸）

### 4.3 0 分钟兜底统计（#10）

参考 `RuleSetVersion` Run 绑定模式：
- 输入：`runId` + 筛选（`departmentCode?` / `stageCode?` / `resourceCode?`）
- 输出：聚合 `{ departmentCode, stageCode, operationCode, resourceCode, fromMaterialCode, toMaterialCode, count }[]`
- 聚合逻辑：扫描 Run 装载的 SetupRule，剔除有 EXACT/DEFAULT 命中的，剩余即为 0 分钟兜底

### 4.4 RuleSetVersion Diff 扩展（#12）

现有 `GET /rule-set-versions/{id}/diff` 响应体新增 `setupRuleChanges` 字段：
```json
{
  "ruleSetVersionId": 100,

  "strategyProfileChanges": [...],  // 已有
  "setupRuleChanges": {            // 新增
    "added": [{ "ruleType": "EXACT", "operationCode": "OP20", ... }],
    "modified": [{ "ruleType": "EXACT", "id": 123, "before": {...}, "after": {...} }],
    "removed": [{ "ruleType": "EXACT", "id": 456, ... }]
  }
}
```
