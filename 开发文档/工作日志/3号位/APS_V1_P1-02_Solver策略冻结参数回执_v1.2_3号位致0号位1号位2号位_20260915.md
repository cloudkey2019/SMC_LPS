## 一、结论一句话（v1.2 修订）

v1.1 的「四分法」（A 行为即变 / B live 硬编码 / C 死代码 / D 存留待裁）**被 0号位 驳回**。0号位 定调：

> **已纳入 V1 冻结的业务能力，不得因代码暂时未消费就「归档 / 不用 / 删除」；代码未消费 = 实现缺口（1号位 实现 + 2号位 投影），不是 3号位 删字段。**

因此换型（Setup）、客户按期（OnTimeTarget）、大工艺重叠（StageOverlap）、动态瓶颈四模式（BottleneckMode）**全部正式保留并必须实际消费**；早做惩罚/稳定性**不参数化但业务目标保留**；MaxIterations **退出 3号位 业务治理、归 1号位 内部工程参数**。3号位 侧由「裁字段」翻转为「**补字段 + 保留全量 + 退出两个非业务参数**」。

## 四、3号位 侧落地（净变化）

1. **不砍任何字段**（撤销 v1.1 §三 C/D 组的「砍 / 归档」）。
2. `SolverStrategyBlock` **补瓶颈阈值字段**（`0.85` 识别 / `0.90` 严重）。
3. `Split.MinBatchQty` 默认 **0 → 0.1**。
4. `MaxIterations`：**标记「内部技术字段 / 待废弃（归 1号位）」**，并从 `SolverStrategyValidator` 业务校验中**移除**（不再是 3号位 业务治理参数）。
5. **不新增** 早做惩罚 / 稳定性字段；在冻结点仅标注「业务目标由固定算法承载（倒排 / 贴交期 / 最终压缩；最小扰动 / 原资源优先 / 邻近时间优先），不设可配参数」——不写「从 V1 删除」。
6. `SolverStrategyValidator` 保留/新增校验：瓶颈阈值 `0~1`、`MinBatchQty > 0`。

> 改动仍仅限 2↔3 契约 + 校验；不碰 1号位 算法、2号位 编排。`PeggingOrchestrator` 投影归 2号位。
