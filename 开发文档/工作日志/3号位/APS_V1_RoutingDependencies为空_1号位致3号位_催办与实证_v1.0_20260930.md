## 一、我方侧实证（**新增**，2号位 未报）

### 1.1 我方建图的根工序判定方式

`PhaseOneConstraintBuilder` 内（符号锚：`BuildRoutingGraphs` → 识别根工序）：

```csharp
// 识别根工序（无前驱的工序）
var allToOps = graph.Dependencies.Keys.ToHashSet();
graph.RootOperations = graph.Operations.Keys
    .Where(nodeKey => !allToOps.Contains(nodeKey))
    .ToList();
```

**判定方式是「不在 `Dependencies` 的 To 端集合里 ⇒ 是根」** —— 这在依赖图完整时是对的。

### 1.2 依赖为空时的后果

| 步 | 结果 |
|---|---|
| `RoutingDependencies` 为空 | `graph.Dependencies` **为空字典** |
| ⇒ `allToOps` | **空集** |
| ⇒ `!allToOps.Contains(nodeKey)` | **对每一个工序都恒真** |
| ⇒ `RootOperations` | **= 全部工序** |

**⇒ 后果：DAG 退化成「一堆孤立点」——所有工序都成了源点，工序间依赖约束完全消失，Phase2 会把它们当并行源点各自排。**

**⇒ 且不报错。** 排出来的结果**结构完整、时间合理、看起来正常**，只是**没有工艺顺序**。

### 1.3 这比 2号位 报的症状更重

| 侧 | 症状 | 量级 |
|---|---|---|
| **5号位**（2号位 报） | 依赖为空 ⇒ `predecessors` 空 ⇒ `preds.All(…)` 对空集**恒真** ⇒ **恰 1 个候选被判成「唯一前沿」并自信输出** | 影响**起点判定**一条 |
| **1号位**（本件补） | 依赖为空 ⇒ `allToOps` 空 ⇒ **全部工序成根工序** | 影响**整张依赖图** |

⇒ **同一根因（源侧缺配对行），在我方侧后果更大：不是判错一个起点，是整张图失去顺序。**
