# APS V1 1号位答疑：Task粒度、Operation与MES执行边界说明

## 一、核心结论

1号位的Task不是简单等同于"小工序"，也不是"一道小工序一个设备就必然一个Task"。

APS V1中的Task定义为：

> 有限产能排程后的可执行排程单元（Scheduling Execution Unit）。

通常粒度接近：

> Routing Operation（工序） + Resource（资源） + 数量分配 + 时间窗口。

但会受到拆批、并行资源、非资源时间节点等因素影响。

------------------------------------------------------------------------

## 1. Task的核心来源

APS排程链路：

Routing Operation\
→ Resource Eligibility\
→ 有限产能Solver\
→ Task

因此Task不是订单级对象，也不是产品级对象，而是排程求解后的结果。

------------------------------------------------------------------------

## 2. 一道小工序是否一定一个Task？

通常：

一个Operation经过资源分配后，会形成一个Task。

但是不是绝对。

### 拆批

例如100件精加工：

-   Task001：精加工，MC01，50件
-   Task002：精加工，MC01，50件

同一个Operation产生多个Task。

### 多资源并行

例如喷涂：

-   Task001：喷涂线1，500件
-   Task002：喷涂线2，300件

同一个Operation产生多个Task。

------------------------------------------------------------------------

## 3. Task是否一定绑定设备？

对于有限资源工序（FINITE_RESOURCE）：

通常需要绑定Resource，因为有限产能必须知道：

-   谁加工；
-   什么时候加工；
-   加工数量。

Task通常包含：

-   OperationCode
-   ResourceId
-   StartTime
-   EndTime
-   Quantity

但是非资源工序不是这样。

例如：

-   自然冷却；
-   固化等待；
-   工艺等待。

Task可能：

-   有Operation；
-   有Start/End时间；
-   Resource为空。

它仍然影响后续工序开始时间。

------------------------------------------------------------------------

## 4. 非资源工序为什么也可能生成Task？

因为Task表达的是：

> APS排程时间节点。

不是：

> MES工单。

例如：

加工\
→ 自然冷却8小时\
→ 装配

如果没有冷却Task，APS可能认为加工完成后可以立即装配，这是错误的。

因此冷却可以形成WAIT_ONLY Task，用于：

-   时间约束；
-   Dependency计算；
-   甘特展示；
-   排程解释。

------------------------------------------------------------------------

## 5. Task与MES工单不是一一对应关系

一个MES工单可以对应多个APS Task。

例如：

一个生产指示：

产品A

Routing：

-   加工
-   清洗
-   检验
-   装配

MES可能只有一个工单，APS会产生多个Task。

反过来，一个Task也可能对应一个独立MES执行对象。

因此：

APS Task 与 MES WorkOrder 是映射关系，不是一对一关系。

------------------------------------------------------------------------

## 6. OperationPlanningMode的意义

OperationPlanningMode不是告诉1号位"是否生成Task"。

它告诉Solver：

这个Operation如何参与时间轴计算。

### FINITE_RESOURCE

-   占用有限资源；
-   参与资源能力计算。

### UNCONSTRAINED

-   有时间消耗；
-   不受有限资源约束。

### WAIT_ONLY

-   不占有限资源；
-   但占用工艺时间；
-   影响后续Operation最早开始时间。

------------------------------------------------------------------------

## 7. MES执行判断不能根据ResourceId判断

错误：

ResourceId为空 → 不能MES执行。

原因：

是否创建MES工单，与是否存在资源约束不是同一个维度。

例如自然冷却：

可能只是Routing中的等待；

也可能：

-   是独立生产指示；
-   需要人工确认；
-   需要MES状态闭环。

因此MES是否创建工单，应依据：

-   生产执行模型；
-   工艺执行属性；
-   MES接口契约。

不能依据是否有Resource。

------------------------------------------------------------------------

## 8. 最终职责边界

### 1号位负责

-   Operation级有限产能求解；
-   Resource选择；
-   Start/End计算；
-   Task生成。

### 2号位负责

-   Task结果落库；
-   Task生命周期；
-   MES接口和下发。

### 3号位负责

-   Routing工艺事实；
-   OperationPlanningMode；
-   Resource Eligibility等工艺/资源ODS数据。

------------------------------------------------------------------------

## 最终给1号位的简版结论

1.  Task通常细到Operation级，但不是简单等于小工序。

2.  一个小工序不一定只有一个Task：

    -   拆批会产生多个Task；
    -   多资源并行会产生多个Task。

3.  Task不是MES工单。

4.  非资源工序可以生成Task，因为Task表达APS时间节点。

5.  Resource为空不代表不能MES执行。

6.  MES执行资格由执行模型决定，不由OperationPlanningMode或ResourceId单独决定。

7.  OperationPlanningMode的作用是指导Solver如何计算该Operation的时间和约束方式。
